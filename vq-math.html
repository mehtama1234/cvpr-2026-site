Snap continuous perception to discrete integers via learned Voronoi partitions, so language models can eat images and video.

Plain-English big picture

What this is really about

Vector quantization turns a continuous signal into a small set of learned codes. It is like replacing every patch with the nearest word in a visual dictionary.

Where topology and shape enter

Topology matters because nearby inputs should usually choose nearby or related codes. If the codebook cuts the data surface badly, small visual changes become sudden symbol jumps.

Where the same idea appears elsewhere

It appears in image tokenizers, audio codecs, compression, generative models, and retrieval.

Why Vector Quantization / Visual Tokenizers is worth learning

It matters because discrete tokens let images and sounds be handled with the same tools used for language.

The problem, as a quantity

Neural networks work with continuous numbers: vectors, decimals, gradients that flow everywhere. But autoregressive language models eat tokens—discrete integers, one symbol at a time. To feed continuous output (images, video, robot movement) into a pretrained language model, you must turn streams of decimals into sequences of integers. But snapping to the nearest integer is not smooth; gradients break at the snap boundary. Worse, if your learned partition is unbalanced—dense in some regions, empty in others—most codes go unused while a few get overloaded (codebook collapse), wasting space and breaking predictability. The whole theme fights to keep the partition alive and balanced while gradients flow through the discrete snap.

The core ideas — and why they work

Voronoi partitions: geometry of snapping

z_q = e_{argmin_k ‖z − e_k‖}, partition: V_k = {z : k = argmin_j ‖z − e_j‖}
Every continuous feature z in your encoder's latent space gets labeled by its nearest codebook vector e_k. This is geometric nearest-neighbor assignment. Mathematically, this partitions the entire feature space into Voronoi cells: cell V_k holds all points closer to e_k than to any other code. Every point in cell k maps to the same integer k, no matter where inside the cell it lands. In principle this is lossless: given only the integer k, you know you landed somewhere in V_k. In practice, the cell center e_k is just an approximation of all the features inside the cell—you lose fine detail. But Voronoi geometry does all the work: the partition is the lowest-distortion way to cover space with K balls, and the quantizer learns to place those balls where data actually lives.

Straight-through estimator (STE): gradients past the snap

forward: q̃(z) = z + sg[e_q(z) − z] ⇒ backward: ∇z L = ∇q̃ L (treat argmin as identity)
The argmin operation that picks the nearest code is not smooth: which cell you land in changes abruptly as z moves even a tiny bit. But you need gradients to learn the codebook. The straight-through estimator is a practical workaround: on the forward pass, snap z to e_q(z) (the reconstructed code) and throw away the offset. On the backward pass, pretend the quantizer was the identity—copy the gradient straight through as if q(z) = z, ignoring that the forward pass was discrete. This 'pretend' gradient does not match the actual forward-pass reality; it is a deliberate fiction. But it works: upstream layers learn to produce features close to codebook centers (because those gradients reward nearness), and the codebook learns to cluster around data (because codebook gradients see where features land). STE is the practical choice when the true gradient is zero almost everywhere.

Codebook collapse and the balancing problem

L_recon = ‖sg[z] − e_q(z)‖², L_commit = β‖z − sg[e_q(z)]‖², L_total = L_recon + L_commit
If you only use reconstruction loss (the distance from the code to where features land), the codebook vectors drift toward high-density regions and ignore empty space. Most codes never get assigned any feature and become dead—they cost memory but contribute nothing. Predictability crashes. The fix is two simultaneous pushes: the reconstruction loss pushes the code toward the cluster of features that claimed it, and the commitment loss pushes features toward their assigned code. Together they are an agree-to-move-together signal: features cannot drift arbitrarily far from their codes, and codes must earn their seats by staying near used features. Additionally, exponential-moving-average (EMA) codebook updates help: instead of moving codes via gradient, compute the mean of all features assigned to each code at each step and blend it as e_k := γ·e_k + (1−γ)·mean(assigned z_i). Dead codes that were never assigned are reset to random samples of live features. The result: every code is encouraged to see roughly equal traffic.

Learning the partition from data

e_k ← EMA update: mean of all z assigned to k, codebook adapts to feature distribution p(z)
A fixed uniform quantizer (integers on a grid) wastes codes on empty space and runs out of precision where data clusters. Instead, learn the codebook from data: over time, codes spread out and settle in regions where features actually land. This is like k-means, but end-to-end: at each step, features vote for their nearest codes (forward pass, via nearest-neighbor), and codes move toward their assigned feature clusters (codebook update). But here the feature distribution itself can shift as upstream layers learn, so the codebook must adapt continuously or it will collapse onto stale centers. The learning is passive: codes follow features, not the other way around. Because quantization is part of a larger model (autoencoder, video tokenizer, visual encoder for a language model), learning the codebook jointly with the encoder means the partition and the data co-evolve. Encoder learns features shaped to fit the codebook; codebook learns to cover the encoder's output. If either freezes, the other learns a suboptimal shape.

The approaches, as variations on the math

The craft of VQ is fighting collapse and keeping codes alive. Knob 1—balance the partition so every code gets used: EMA updates (codes learn where data actually lives), dead-code resets (revive codes starved of assignments), commitment loss (keep features from drifting), tracking code usage (monitor how many tokens use each code). Knob 2—refine the quantization so you lose less detail: break the codebook into independent pieces (product quantization), learn a hierarchy of codes where each refines the last (residual VQ), replace hard nearest-neighbor with a soft assignment where nearby codes also get a share (Gumbel-softmax). Knob 3—shape the features for tokenization: encourage codes to be equally likely, add side losses that make tokens capture meaning not just nearness, and in video, make adjacent frames get similar tokens so the sequence is smooth. Every method is a different turn of these three knobs.

A worked numeric example

An encoder vector z=[0.9,0.1] chooses the nearest code from [(1,0),(0,1),(-1,0)], so it becomes code 1. A continuous point is replaced by a discrete symbol. The price is quantization error; the payoff is that images can be handled like token sequences.

1Fighting collapse: better quantizers

Standard VQ suffers from codebook collapse because the discrete snap and gradient-flow bottleneck leave codes unused. Geometrically smart initialization: arrange the codebook using patterns (like the Leech lattice) that spread codes evenly apart, so all codes start equidistant and well-separated. Soft quantization (instead of hard nearest-neighbor): assign probability mass to multiple codes based on distance, spreading gradient pressure and keeping all codes alive. Add a loss that penalizes dead codes—codes that were never assigned to any feature.

The through-line. Continuous perception—images, video, robot state—must become discrete token sequences to feed into language models. Vector quantization does this by partitioning feature space into Voronoi cells and assigning each cell an integer code. The partition is learned by k-means-like iteration: features vote for nearest codes, codes move toward assigned features. Straight-through estimators let gradients flow through the discrete snap. Balancing losses and EMA updates keep the partition alive and prevent collapse, where most codes would go unused. The result is a learned, interpretable compression where each token is a codeword from a balanced vocabulary shaped to the data it represents.
