Gaussian splatting — why it works, mathematically

Render a scene as a sum of smooth 3D blobs, project them once, and blend—differentiable rasterization for instant photorealistic view synthesis.

The problem, as a quantity

Traditional 3D rendering paints the scene pixel-by-pixel with a neural network (like NeRF). That's slow—you trace rays and run the network millions of times. We need instant rendering of photorealistic, view-dependent scenes without waiting for per-pixel computation.

The core ideas — and why they work

Explicit Gaussian primitives

Core representation
Instead of a black-box per-pixel network, build the scene from an EXPLICIT set of primitives. A 3D Gaussian G_i(x) = exp(−½·(x−μ_i)ᵀ·Σ_i⁻¹·(x−μ_i)) is a soft blob centered at μ_i with spread defined by covariance Σ_i. Anisotropic Σ (full 3×3 matrix, factored as rotation·scale) lets the blob stretch and rotate to match real structure—a sphere becomes a thin pancake or needle as needed. Each Gaussian carries a colour c_i and opacity α_i. A sum of Gaussians is incredibly flexible: smooth to model details, sparse to stay efficient. And crucially: Gaussians are DIFFERENTIABLE through-and-through, so gradients flow to position, covariance, colour, opacity—you can optimize a scene by backprop.

Differentiable rasterization

Rendering pipeline
Project each 3D Gaussian onto the 2D image plane (perspective geometry). For each pixel, accumulate the projected Gaussians using alpha-compositing, the exact same blend formula as volume rendering: C = Σ_i c_i·α_i·∏_{j

Sparse, moving blobs

Scalability
A sum of ~100k Gaussians can model an entire scene. Because you only store position/covariance/colour/opacity (tens of floats per blob), you use less memory than a dense feature grid. Since each Gaussian projects independently, you can parallelize across blobs. And because Gaussians are differentiable and have clear geometric meaning—a position, a scale, a rotation—you can optimize them from multiple views simultaneously. Want the scene to move? Animate μ_i(t), Σ_i(t), c_i(t)—add a time dimension and you get 4D Gaussian splatting for dynamic scenes.

From photogrammetry to motion

Inverse rendering and animation
Start with multi-view images and camera poses. Initialize Gaussians by projecting depth points, then optimize: nudge μ, Σ, c, α to match all views simultaneously. Gradients backprop through the rasterizer to update all parameters. In minutes, you fit a high-quality sparse set of blobs. To animate: add velocity to μ, quaternions to rotation, scale over time—the same differentiable rasterizer works. Or run a generative model on top to predict new Gaussians from text, inpainting, or deformation. Because the whole pipeline is differentiable, you can optimize for sharpness (L1 loss on RGB), view consistency, semantic labels, whatever you want.

The approaches, as variations on the math

Make the blobs cheaper by culling or hierarchies (only shade near-front Gaussians). Make them sharper by adaptive splitting and merging—coalesce overlapping blobs, subdivide high-frequency regions. Predict Gaussians in one shot: train a feed-forward encoder that takes a sparse 3D signal and outputs the full set of blobs (speed at test-time). Extend to 4D: add time and velocity so scenes morph and move. Conjure and animate: train a diffusion model or transformer to generate plausible Gaussians from a prompt or rough sketch. Teach semantics: each Gaussian stores a feature embedding, so the scene is also a semantic feature field. Robotics: learn the robot's scene as a live 3D Gaussian map so the robot updates, plans, and re-renders on the fly.

1Make the blobs cheaper and sharper
ℓ = Σ_i [diff(C_pred, C_gt)] · mask(i) where C_pred = Σ_j α_j(t) · c_j ∏(1−α_k<j), pruning blobs where |α_j| < ε and reshaping Σ covariance to remove far-field tail
Eliminating densification and approximation artifacts by replacing gradual splitting with dense initialization and exact alpha compositing. EDGS skips the slow grow-then-prune cycle; FastGS vectorizes the loss over batches; Exact-GS replaces approximations like spherical covariance or discrete grid steps with true 3D anisotropic Gaussians and continuous alpha accumulation.
2Predict the blobs in one shot
G = f_θ(img) where G = {μ_i, Σ_i, α_i, c_i} ∈ ℝ^(N×D), D=16+3+1+3, output from a single forward pass encoder→decoder; optionally pose T learnable from same img set
Feed-forward decoders learn to regress 3D Gaussian primitives directly without optimization loops. TokenGS decouples predictions from pixel space by operating on tokens; EcoSplat conditions the count N via a budget parameter; TokenSplat jointly solves for pose and scene, treating cameras as unknowns with the same encoder backbone.
3Make the scene move
μ_i(t) = μ_i(0) + v_i·t + Σ_k a_{i,k}·B_k(t); Σ_i(t) = Q_i(t)·Λ_i·Q_i(t)ᵀ where Q_i(t) rotates via quat (4D Rotor) or deform grid; α_i(t) = α_i·fade(t, t_birth, t_death)
Time-aware Gaussians embed motion into the primitive itself rather than rendering static frames. Rotor-based 4D blobs compress space–time into a single rotation quaternion; motion-aware losses tie optical flow to blob trajectories; lifespan masking lets blobs fade in and out, reducing ghosting and enabling temporal coherence.
4Conjure and animate
G_{t+1} ∼ p_diffusion(G_t | img_0, prompt) · p_physics(G_t) where physics term enforces conservation: ∂G/∂t ∝ grad_smooth + grad_rigid + grad_material(ρ, η, k)
Generative models (diffusion, large-scale priors) seed plausible Gaussian scenes; physical constraints regularize motion and appearance. DIFF4SPLAT repurposes video diffusion priors that know how scenes evolve; PhysGM jointly predicts materials (albedo, roughness, metallicity), grounding appearance in physics; HyperGaussians add learnable per-blob degrees of freedom (higher-dim embeddings) to capture fine details.
5Teach the blobs what they are
s_i = f_semantic(μ_i, Σ_i, c_i, img) where s_i ∈ ℝ^C (C classes); mask_i = argmax(s_i); scene-text query = (MLLM, G, mask) → reasoning loop
Attaching semantic labels to each Gaussian via lightweight feature fields or MLLM grounding. LightSplat adds a tiny MLP per blob to predict class tokens; Uni3R folds semantics into the direct decoder; REALM chains Gaussians through language-model agents that interpret geometry spatially.
6A map the robot lives in
map = {μ_i, Σ_i, α_i, c_i, flow_i, label_i} where flow_i ∼ optical_flow(img_t, img_{t+1}); dynamics = {static, dynamic, occluded} via P(label | flow, depth_consistency); collision = min_distance(blob_i, blob_j | Σ)
Real-time SLAM fuses sensor streams (camera, LiDAR, IMU) into a Gaussian map that updates live. Flow-aware masks separate moving objects; Gaussian uncertainties Σ encode map confidence for planning; collision and trajectory optimization directly use blob covariances as risk metrics for robot navigation.
The through-line. The insight: EXPLICIT smooth primitives (Gaussians) are differentiable and rasterize instantly, so you can optimize a scene from images in minutes and render photorealistically in real-time—no neural networks during render, no per-pixel computation, just project and blend.
