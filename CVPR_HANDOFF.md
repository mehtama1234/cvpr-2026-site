## Important implementation notes

- The repo is generated by Python builders under `scripts/`.
- Every major generated demo has a verifier under `scripts/verify_*.py`.
- Package-level JavaScript tests live under `source-code/learning/*/tests/core.test.js`.
- `scripts/validate_cvpr_full_stack.py` is the canonical end-to-end gate.
- Human-readable subtheme lane slugs can collide, so `cvpr-subtheme-scenario-lab` uses stable `laneKey` identifiers while preserving original lane labels.
- The upstream paper repo forge uses `perceive` as the perception taxonomy label; downstream pages preserve that source taxonomy.

## Resume point

The clean wrap point is the subtheme release scoreboard:

- Page: `cvpr-subtheme-release-scoreboard.html`
- Registry: `analysis/cvpr_subtheme_release_scoreboard/registry.json`
- Verifier: `scripts/verify_cvpr_subtheme_release_scoreboard.py`
- Package: `source-code/learning/cvpr-subtheme-release-scoreboard/`

The next optional layer would be a subtheme handoff bundle that packages the matrix, drilldown, scenario lab, and release scoreboard as one audited operator bundle. It was planned but not implemented.
