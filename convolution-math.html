Convolution & weight sharing — why it works, mathematically

A detector slid over an image to find the same edge or texture everywhere, using one small pattern instead of a billion separate patterns. This is how a network reuses knowledge across space.

The problem, as a quantity

Imagine you train a network to spot stop signs. It learns a detector for a red octagon shape. But that shape can appear anywhere in a picture — top left, bottom right, upside down. If you have a billion pixels, and a network learns one detector pattern per pixel location, you'd need a billion separate detectors even though they're all doing the same job. The core insight is: use one detector, then slide it to every position in the image. Same small learned pattern everywhere. That is weight sharing — the same numbers do the work at every location. But how do you slide it efficiently? And what happens when you stack many detectors on top of each other?

The core ideas — and why they work

One detector, slid over every position

y[i] = Σ_k w[k]·x[i+k], the same w at every position i
The equation describes: for each output position labeled i, add up products of the detector's weights (called w, indexed by k) times the nearby input values (called x, also indexed from some offset of i). The weights w are the same at every position i—that is the magic. You compute the multiply-and-add of the detector w with a patch of the input, and call that one output number y[i]. Then slide the detector one pixel over and do it again at position i+1, using the exact same w. This reuses the detector everywhere. It is cheap because you have one set of weights w, not a billion sets. It is powerful because the same detector fires wherever it finds the pattern it learned.

Each output looks only at a small nearby patch

y[i] depends only on x[i−r … i+r] (a local window)
The output y[i] only depends on input values x in a small neighborhood—specifically from x[i−r] to x[i+r], where r is the detector's reach. The detector has a fixed size (call it the detector's reach). A 3×3 detector on a 2D image looks only at the 9 pixels in its 3×3 square. A detector 5 numbers wide looks at 5 input positions. This locality is crucial: it means the detector learns one small, meaningful pattern. An edge detector spots local contrast. A texture detector finds a small repeating grain. You cannot learn what is everywhere from what is only here—the detector is forced to be specific. That specificity is what makes weight sharing powerful: the same small pattern really does appear everywhere you slide it.

Shift the input and the output just shifts too

conv(shift(x)) = shift(conv(x))
If you shift the input image slightly (e.g., move everything one pixel to the right), the output shifts in the same way. Mathematically: if you apply the detector to a shifted version of x, you get a shifted version of y. This is the shift-along-together property. It happens because the detector is a local operation: it does not care about absolute positions, only about what is nearby. A red edge is an edge whether it is at pixel 50 or pixel 51. This property is why weight sharing works at all—sliding the detector makes sense only because the world is the same everywhere. If objects changed meaning based on their pixel coordinates (which they do not), weight sharing would fail.

Stacking builds bigger parts out of smaller ones

reach after L layers ≈ L·(k−1)+1 — edges → shapes → objects
Stack many detectors on top of each other, in layers. After one layer, each output sees only a small patch (say, 3×3). After two layers, each output sees the union of what its input's neighborhood saw, which is a larger patch (maybe 5×5). After L layers, the reach grows to roughly L times the original detector size, plus one. Layer 1 spots tiny edges. Layer 2 combines edges into short corners and lines. Layer 3 combines those into shapes. Layer 4 combines shapes into objects. The reach increases because each layer's detector integrates over the previous layer's outputs, which themselves integrate over space. This hierarchy is why deep networks work: many shallow layers compose local detectors into detectors for bigger, more meaningful patterns. The weight sharing at each layer is what makes this feasible—you do not learn a separate billion-parameter object detector for every position.

The approaches, as variations on the math

The core mechanism is the sliding detector, but several dials change what you find. Detector size: a 3×3 detector is small and fast, a 5×5 is slower but sees more context. How far you slide: slide by 1 pixel (overlap a lot, dense outputs) or by 2 or 4 pixels (sparse outputs, faster). What you do at the edge: when the detector would fall off the image, you can pad with zeros, or crop the output, or pad with the edge pixel values repeated. How many detectors: use one detector to learn one small pattern, or stack a hundred parallel detectors to learn a hundred different patterns at the same layer. The thread never changes: reuse the same small learned patterns by sliding them everywhere, building bigger patterns by stacking layers.

Every approach, and the lever it pulls

One notch deeper: each of the theme's 4 approach-families and the specific mathematical mechanism that makes its papers work — the exact knob turned on the core relations above. Under each, the specific mathematical note for every paper in that family.

1Detector size (receptive field)
k × k kernel: wider detectors see more context, cost ∝ k²
The detector—the set of learned weights you slide over the image—can be a small square (3×3 means 9 weights) or a larger square (5×5 means 25 weights). A bigger detector sees a wider view of the input, catching larger patterns in one step. But it is also more expensive: a 5×5 detector has 5 times more weights than a 3×3 one. The trade-off is between having enough context to learn useful patterns and keeping computation fast. Small detectors force the network to build large patterns slowly by stacking layers; large detectors let each layer see farther but cost more upfront.
2Stride (how far you slide)
stride s: output position = i·s, density = 1/s²
After you compute one output by sliding the detector over positions 0 through k, you can move the detector forward by 1 position (stride=1, dense outputs) or by 2, 4, or more positions (stride=2, 4, sparser outputs). A stride of 1 gives you many outputs—one for every input position. A stride of 2 gives you half as many outputs in each dimension, four times fewer overall, and is faster to compute. The trade-off is between keeping detailed spatial information (stride=1) and reducing computation and memory (larger stride). Many networks use stride=2 to shrink the spatial grid at each layer, automatically focusing on broader patterns.
3Boundary handling (padding)
pad width p: effective input size grows from n to n+2p
When you slide the detector near the edge of the image, it would fall off—part of the detector would be outside the input. You can handle this by padding: add a border of dummy values (usually zeros) around the input before sliding. A padding width p of 1 adds one layer of zeros all around, making the effective image size go from n×n to (n+2)×(n+2). No padding means the output is smaller than the input (information loss at edges); full padding keeps the size the same (good for stacking many layers without shrinking). The padding trick lets you control whether edge pixels get as much representation as interior pixels.
4Number of detectors (channels)
C output channels: learn C independent patterns, cost ∝ C
You can use one detector to spot one kind of edge (say, vertical edges). But you probably want to spot many patterns—horizontal edges, textures, colors, corners. Instead of stacking many layers, you can run C different detectors in parallel at the same layer, each with its own learned weights. You slide detector 1 over the input and get one output grid; slide detector 2 and get another grid. Now you have C output grids stacked on top of each other (called C output channels). This multiplies the cost by C but lets each layer learn richer patterns. A layer with many channels is like having many detectors voting on what they see at each position.
The through-line. The core problem is learning the same pattern everywhere without repeating your learning a billion times. A naive network would use different weights for each pixel location—hopeless. The solution is to use one detector and slide it to every position. But that works only if the pattern you are looking for is actually the same everywhere, which is only true because the input is a spatial grid where locality matters. When you stack layers of slid detectors, the reach grows, and you build bigger and bigger patterns: individual edges become shapes, shapes become objects. Two plain ideas carry it: the same small detector is slid to all positions in a spatial grid (weight sharing), and stacking these layers automatically builds hierarchical patterns by composing smaller pieces into larger ones (compositional structure).
