Mixture of LoRA — why it works, mathematically

Route through many small skill matrices instead of one. Why it works: low-rank is how models learn, and routing composes specialists without forgetting.

The problem, as a quantity

Fine-tuning a giant model is expensive: training millions of parameters for each task. Freezing weights and learning small updates (LoRA) cuts this — but one adapter per task means choosing which skill to use, picking a single specialist for each input. How do you compose multiple skills in one forward pass?

The core ideas — and why they work

Low-Rank Constraint

foundation
When you adapt a pre-trained model to a new skill, the weight changes stay within a low-dimensional subspace — the model does not need to rewrite every parameter. LoRA captures this by learning ΔW = B·A where A ∈ ℝ^(r × d_in) and B ∈ ℝ^(d_out × r) with rank r ≪ d. This means trainable parameters drop from d² to only 2dr: you get the same expressive power using just the narrow directions where learning actually happens.

Merging at Inference

foundation
LoRA is a mathematical identity: W·h + B·A·h = (W + B·A)·h. So after training, you can bake B·A into the base weights with zero cost and zero loss. The new skill is packaged as a tiny low-rank update (2dr parameters) that travels with your model. At test time, you pay no overhead — merging is free arithmetic, just a reassignment of the matrix.

Routing via Learned Gate

extension
Mixture-of-LoRA keeps multiple adapters {ΔW_1, ΔW_2, ..., ΔW_k} and learns a gating function g_i(x) for each input x. The forward pass becomes h → Σ_i g_i(x)·(B_i A_i·h), a soft mixture where the gate assigns each input to the specialists that matter. This is mixture-of-experts at adapter scale: you route among skill updates, not full networks, composing a committee inside one frozen base.

Composing Without Overwriting

payoff
Adding adapters in parallel (via routing) avoids the catastrophic forgetting you get from sequential fine-tuning. Each adapter stays a low-rank deformation of the original weights; the gate learns to blend them without training updates to the base. You gain new skills for task B without erasing task A — the base remains universal, and routing negotiates which skill to apply.

The approaches, as variations on the math

Start with a frozen pretrained base. For each new skill, train a LoRA adapter (two small matrices A_i, B_i) on that task alone — fast, few parameters. Then stack the adapters and train a router: a small neural net or attention head that learns g_i(x), the soft attention over adapters. The router sees the input and decides which adapter to activate. At inference, compute each adapter's output in parallel and sum them weighted by g. This pattern generalizes: you can add adapters after deployment, train them offline, and plug them in — no retraining the base or any prior adapters.

5Combine specialists after training
Merge disjoint LoRAs via null-space geometry; if ker(A_i) ⊥ ker(A_j), then ΔW = B_i·A_i + B_j·A_j remains optimal
Each trained expert occupies a low-dimensional subspace in the weight space. If two experts' subspaces are orthogonal (null-spaces don't overlap), their contributions combine without conflict. Merging projects all experts into a single LoRA; subspace structure guarantees recovery of all learned behaviors.

7Mixture-of-LoRA proper — the keystones
Σ g_i(x)·(B_i·A_i) where each expert i is fully low-rank and gate g(x) is learned; dynamic routing respects rank constraint across all experts
True Mixture-of-LoRA merges three layers: a shared frozen base, a dynamic gate that learns routing patterns from data, and a set of learned low-rank experts. Each expert B_i·A_i is intrinsically small (rank r ≪ d), so adding experts is cheap. The gate learns which expert matters for which input, making the whole system both parameter-efficient and task-adaptive.
The through-line. Low-rank updates are how pre-trained models learn new skills cheaply — the subspace is narrow. Routing among these thin updates is like a committee: each specialist is tiny, and a learned gate blends their expertise without forgetting the base model.
