Mixture of LoRA — why it works, mathematically

A skill is a small bend in a big fixed function. Low-rank is the honest size of that bend; a soft gate turns “which skill” from a choice you must hard-code into a quantity you can learn.

The problem, as a quantity

A pretrained model is one enormous fixed function, a matrix W with hundreds of millions of numbers. A new skill is not a new function — it is a small bend of the one you already have. So retraining all of W for each skill is a category error: you are re-deriving the whole function to change a little of it, and worse, each fully-tuned copy overwrites the last, so learning skill B quietly destroys skill A. The real problem has three edges at once: make each skill cheap to store, make skills coexist without erasing one another, and make the choice of which skill to apply something the model can learn rather than something you hard-wire. The whole theme is the shape that satisfies all three.

The core ideas — and why they work

A skill lives in a few directions (low rank)

ΔW = B·A, A ∈ ℝ^{r×d}, B ∈ ℝ^{d×r}, r ≪ d ⇒ 2dr trainable numbers instead of d²
Adapting to a task is not learning from scratch — the pretrained model already holds the features; the task only has to re-weight and recombine directions it already knows. So the change it needs, ΔW, does not fill the whole d×d matrix — it lives in a tiny subspace. Measured directly, the fine-tuning gradient has almost all of its energy in a handful of singular directions: the intrinsic dimension of a task is often just a few hundred numbers. Writing ΔW = B·A with r ≪ d is therefore not an approximation you settle for — it is the honest shape of the update. You drop from d² to 2dr parameters not by giving anything up, but by refusing to store the zeros. Same primitive elsewhere: this is the low-rank / compression idea that also carries knowledge distillation and codebooks — the useful signal always lives in few dimensions.

The skill adds in, for free (linearity)

(W + B·A)·h = W·h + B·A·h — an exact identity; at test time fold B·A into W, extra cost → 0
A LoRA is not a new layer bolted onto the model — it is added into the weight matrix. Because a linear layer is linear in its weights, “run the base” and “apply the skill” commute and simply sum: (W + BA)h = Wh + BAh, with no approximation anywhere. Linearity is doing all the work. During training you keep B and A separate so gradients only ever touch 2dr numbers; at inference you collapse them back into W and the skill costs literally nothing — it is a reassignment of the matrix, not an extra computation. The skill becomes a portable object: a few-kilobyte diff that travels with the model. And because the update enters by addition, several skills can coexist — sums do not fight.

Which skill? Make the choice soft (a gate)

h ↦ Σᵢ gᵢ(x)·BᵢAᵢ·h, g(x) = softmax(router(x)), gᵢ ≥ 0, Σᵢ gᵢ = 1
Keep one adapter per skill and you are forced to pick one for each input — and a hard pick has no gradient, so you cannot learn it. The fix is the single most reused move in the whole field: replace the hard argmax with a soft, differentiable weighting. A small gate reads the input and emits positive weights that sum to one; the layer computes a blend, Σᵢ gᵢ(x)·BᵢAᵢ·h, not a choice. Now “which skill” is a continuous quantity you can train by gradient descent, and a single input can draw on two skills at once in whatever proportion helps. Same primitive elsewhere: this is exactly the softmax selection at the heart of attention and mixture-of-experts — the identical trick, pointed at skill-updates instead of tokens or whole sub-networks.

Add skills without overwriting (parallel, not sequential)

W_frozen + Σᵢ gᵢ(x)·BᵢAᵢ — a new skill is a new summand; the base is never rewritten
Teaching skills one after another overwrites: because sequential fine-tuning keeps writing to the same shared W, learning skill B moves the weights and silently erases skill A — the model has one set of parameters and the tasks collide in it. Routing sidesteps the collision by keeping each skill as its own frozen low-rank term and never touching the base. The skills are added in parallel (all at once, side by side), not layered in time. Because the terms are summed (idea 2) and selected softly (idea 3), bolting on a new adapter is a new summand — not a rewrite of the old ones. The base stays universal, memory is additive, and the gate negotiates who speaks. The enemy it defeats is the same “one objective, one shared parameter set, they fight” tension that collapse-fighting solves throughout the field.

The approaches, as variations on the math

Every method in this family is two knobs on one recipe. Knob 1 — make the expensive thing thin so you can afford many of them: freeze the base, and learn each skill as a rank-r pair (Aᵢ, Bᵢ) — a few thousand numbers, trained on that task alone. Knob 2 — make the choice soft so you can learn it: train a gate g(x) that reads the input and blends the adapters. Everything that looks like a different method is just a setting of those two knobs: how thin (the rank r), how many adapters, how the gate reads the input (per-token vs. per-sequence, a tiny network vs. a fixed rule), and what stops the gate from collapsing onto a single favourite adapter. Crucially, because the base and the old adapters are frozen, you can add a new skill after deployment — train it offline, plug it in, retrain nothing.

A worked numeric example

A dense 4096×4096 update has 16,777,216 numbers. A LoRA with rank 8 stores 2·4096·8=65,536 numbers, about 256× smaller. If a gate blends three such adapters with weights [0.7,0.2,0.1], the skill update is a weighted sum of tiny bends rather than a new full model.

1Meet the world the giant never saw

A pretrained foundation model encodes broad patterns. Frozen backbone forces adaptation into low-rank space, so each domain (surgical, geospatial, weather) is compressed into its essential dimensions. Patches are additive residuals—they layer new knowledge on frozen structure, preventing catastrophic forgetting.

2Two ideas in one picture
Separate rank-r LoRA modules per concept (content B_c·A_c, style B_s·A_s); compose as ΔW = B_c·A_c + B_s·A_s
Content and style are orthogonal factors in generative models. By training independent low-rank modules for each, you isolate their roles—each expert learns one semantic axis. Rank-constrained composition keeps modules specialized and prevents entanglement, so they recombine cleanly across tasks.
CRAFT-LoRA: Content-Style Personalization via Rank-Constrained Adaptat — Separate content and style LoRA matrices with enforced rank splitting forces each adapter to capture orthogonal semantic subspaces.
OrthoFuse: Training-free Riemannian Fusion of Orthogonal Style-Concept — Geodesic weighted average on the Riemannian manifold of orthogonal LoRA updates preserves orthogonality under fusion.
SplitFlux: Learning to Decouple Content and Style from a Single Image — Low-rank factorization applied selectively—early blocks only for content, late blocks only for style—creates implicit routing by layer depth.
PositionIC: Unified Position and Identity Consistency for Image Custom — LoRA applied with dual reconstruction losses (position + identity) forces learned matrices to encode both spatial and semantic dimensions simultaneously.
3A committee inside one model
Router gate g(x) selects expert subset; ΔW(x) = Σ g_i(x)·(B_i·A_i), sparse activation only when needed
Not all samples need all experts. A learned gate g(x) routes input to specialists—one sample activates few experts, another activates different ones. Sparsity reduces compute; routing lets each expert focus on its own subproblem (geometry, language, action) without interference from others.
MoRE: 3D Visual Geometry Reconstruction Meets Mixture-of-Experts — Shared backbone plus sparse expert swaps replace plain blocks with multiple LoRA experts that activate in parallel based on input geometry signature.

MoE-Loco: Mixture of Experts for Multitask Locomotion — Policy network replaced by expert pool with trainable router that maps (task, state) to expert index via differentiable gating, each expert is a LoRA-adapted policy head.
4Learn more without forgetting or fighting
Frozen base + per-task LoRA modules (B_i·A_i per task i); no base rewrite, no gradient conflict via domain routing g_d(x)
As tasks arrive sequentially, adding new low-rank modules keeps the frozen backbone clean. A domain router g_d assigns each sample to its task's module without contaminating shared structure. Gradient updates stay confined to per-task experts, so learning task N does not clobber task 1.
DGS: Dual Gradient and Semantic-Shift Guided Low-Rank Adaptation for C — Two gradients (task + semantic-shift penalty) jointly steer each new LoRA module to occupy orthogonal subspace without corrupting old class parameters.

Keep It Frozen: Domain-Routed Conditional Residual Modulation for Mult — Domain indicator conditions a learned multiplier on the LoRA residual output A·B·x, scaling each expert's contribution without touching backbone or other experts.
5Combine specialists after training
Merge disjoint LoRAs via null-space geometry; if ker(A_i) ⊥ ker(A_j), then ΔW = B_i·A_i + B_j·A_j remains optimal
Each trained expert occupies a low-dimensional subspace in the weight space. If two experts' subspaces are orthogonal (null-spaces don't overlap), their contributions combine without conflict. Merging projects all experts into a single LoRA; subspace structure guarantees recovery of all learned behaviors.
MergeVLA: Cross-Skill Model Merging Toward a Generalist Vision-Languag — LoRA adapters fused by aligned projection: each adapter decomposed into complementary subspace + preferred direction, then combined via weighted sum preserving both.
Preference-Aligned LoRA Merging: Preserving Subspace Coverage and Addr — Each adapter's null space (complement of its range) extracted via SVD; merged adapter constructed to preserve coverage of all original subspaces plus preference weighting.
MapReduce LoRA: Advancing the Pareto Front in Multi-Preference Optimiz — Parallel training of independent LoRA experts per reward signal (map step) then Pareto-optimal combination (reduce step) via convex hull in weight space.
Label-Free Cross-Task LoRA Merging with Null-Space Compression — Task information compressed into low-rank subspace; null-space orthogonal to all tasks used as free capacity to add additional constraints without task conflict.
6Make the router trustworthy
Reparameterize gate via eigenvectors of task covariance; g(x) = softmax(Q·E·c(x)), Q eigenbasis avoids mode collapse
Learned gating alone is brittle—gradients concentrate weight on a few modes, making the router ignore specialists. Tying gates to data geometry (eigenvectors of task statistics) anchors routing to real structure. Eigenspace parameterization stabilizes sparse activation and forces honest specialization.
ERMoE: Eigen-Reparameterized Mixture-of-Experts for Stable Routing and — Router gate reparameterized as eigendecomposition of a learned symmetric matrix; yields stable routing with guaranteed spectral properties independent of learned magnitudes.
Teacher-Guided Routing for Sparse Vision Mixture-of-Experts — Router trained to mimic teacher predictions first, then fine-tuned on task loss; two-stage training decouples routing stability from task specialization pressure.
Enhancing Mixture-of-Experts Specialization via Cluster-Aware Upcyclin — Expert initialization via k-means clustering of gradients breaks symmetry before training; each expert seeded toward distinct data regions, biasing router toward meaningful specialization.
7Mixture-of-LoRA proper — the keystones
Σ g_i(x)·(B_i·A_i) where each expert i is fully low-rank and gate g(x) is learned; dynamic routing respects rank constraint across all experts
True Mixture-of-LoRA merges three layers: a shared frozen base, a dynamic gate that learns routing patterns from data, and a set of learned low-rank experts. Each expert B_i·A_i is intrinsically small (rank r ≪ d), so adding experts is cheap. The gate learns which expert matters for which input, making the whole system both parameter-efficient and task-adaptive.
The through-line. A skill is a small bend in a big fixed function, so the honest update is low-rank — you store the few directions where learning actually happens, not a full new matrix. Because linear layers add, those bends fold in for free and stack side by side without fighting. And because a hard “pick one skill” has no gradient, a soft gate turns the choice into a smooth, learnable weighting. The two moves that run underneath — compress the update, soften the selection — are the same two moves the whole field keeps reaching for.
