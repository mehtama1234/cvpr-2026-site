Kernels & Gaussian processes — why it works, mathematically

Instead of guessing the shape of a rule from scratch, measure how similar each new point is to past examples, and a straight line can bend into a curve. Kernels lift this idea to rich feature spaces without building them. Gaussian processes add uncertainty—a mean answer and a confidence band.

The problem, as a quantity

Learning a rule from examples usually starts with guessing its shape: is it a line, or curvy? Too simple a shape and the rule misses the true pattern. Too complex and it latches onto noise instead of the real signal.

There is another path. Instead of deciding upfront what form the rule takes, ask: how similar is this new point to the examples you have already seen? A point near a well-performed example will probably perform well too. This is not a guess at the global shape; it is local, and it flows directly from the training data. The trick is making this work in high-dimensional spaces—where 'similar' can mean almost anything—without having to build all those hidden dimensions explicitly.

The core ideas — and why they work

Judge by similarity, and a straight rule becomes a curved one

f(x) = Σ_i α_i · k(x, x_i) — blend of similarities to seen points
Start with a concrete example: you see how well a network performs on some test cases, and now you want to predict its performance on a new case. Instead of fitting a separate line or curve for the whole space, imagine painting the value at each old test case onto a canvas, then spreading that paint outward so that the value at any new point is a blend of the nearby painted values. The blend is weighted by 'similarity'—a new point's answer is a weighted sum of all the old answers, where the weight for each old point is how similar the new point is to it. This is exactly what the equation says: the predicted value at x is a sum of α_i (a learned blend weight for each past point) times k(x, x_i) (the similarity between the new point and past point x_i). The k here is the kernel—a similarity measure. If a past point was right next to the new one, its weight is high and it pulls the answer toward its value. A point far away has low weight and barely influences the answer.

Why does this create a curve instead of a line? Because the blend of many local values, each peaked near its own past point, naturally traces a wavy, curved path through the space. You are not choosing the curve's equation upfront; it emerges from how the data points influence each other through similarity.

Get a rich feature space without ever building it

k(x, x') = ⟨φ(x), φ(x')⟩ — compute k directly, never form φ
In practice, computing similarity in a rich feature space is brutal. If you wanted to represent each point as a thousand-dimensional number-list and measure similarity as the multiply-and-add, you would need to build and store that thousand-dimensional version. Thousands of examples, each a thousand-dimensional list—and that is still not very high-dimensional by modern standards.

The kernel trick sidesteps this entirely. Instead of building the high-dimensional feature space, you compute similarity directly in the original space, and the answer you get is the same as if you had built the high-dimensional space and computed the multiply-and-add there. The equation k(x, x') = ⟨φ(x), φ(x')⟩ says: a kernel k is defined as the multiply-and-add of two points φ(x) and φ(x') in some hidden, richer feature space—but you never actually compute φ. You compute k directly in the original space, and get the same answer far faster. This is the 'kernel trick': a choice of kernel function encodes an implicit feature space without ever constructing it.

The shape of the similarity is your assumption about smoothness

choice of k fixes which functions count as 'simple'
Different kernels embed different assumptions about the data's shape. A linear kernel assumes the best boundary between classes is a straight line in the original space; a polynomial kernel assumes it is a curve; a Gaussian (or radial basis) kernel assumes points close in the original space are similar, and that similarity decays smoothly as they drift apart. Each kernel choice locks in a set of function shapes that the model is allowed to learn—some will be preferred (called 'simple' by that kernel) and others penalized ('complex'). A Gaussian kernel, for instance, strongly prefers smooth, wavy functions over wiggly ones: neighboring points are forced to be similar, so the learned rule cannot jitter wildly. This smoothness assumption is built into the kernel itself, not imposed later. The shape of the kernel determines what counts as a plausible rule for your data.

The same idea, but it also tells you how unsure it is

predict a mean and a spread (Gaussian process): mean ± uncertainty
A Gaussian process extends the idea by acknowledging that you are uncertain. Instead of a single predicted value at each new point, it gives a mean (the best guess) and a spread (the confidence band around that guess). Where training data is dense, the spread is tight—you know the answer well. Where training data is sparse, the spread is wide—you are admitting ignorance. The math is the same—still a weighted blend of past values—but now it also estimates how much the answer could reasonably waver. This uncertainty is not arbitrary; it comes from the kernel and the scatter of the data. Points near training data have narrow confidence bands; points far from any example have wide ones. A Gaussian process naturally outputs two numbers: mean ± uncertainty.

The approaches, as variations on the math

Kernels and Gaussian processes dial a few key levers on the same core idea.

The kernel itself is the main dial: linear, polynomial, Gaussian, or hand-crafted to match domain knowledge about what 'similar' means in your problem. How to combine multiple kernels: add them (a point is similar if it matches any of several criteria), multiply them (a point must match all criteria), or learn a weighted mix. Uncertainty in a Gaussian process comes from the noise level you assume in the data and how spread out your training examples are. More noise means wider confidence bands; clustered training data means you are confident near the cluster and unsure far away. Speed versus power: exact kernels are slow on many examples (the computation grows with the square of data size), so fast approximations use subsets, random projections, or sparse grids. The thread never changes: measure similarity between points via a kernel, blend past answers weighted by that similarity, and let the data reveal the rule's shape through local neighborhood structure.

Every approach, and the lever it pulls

1Kernel trick: implicit feature expansion
k(x, x') = φ(x) · φ(x') without computing φ
Instead of manually writing down all the features φ(x), you pick a similarity function k(x, x') that secretly does the inner product in a high-dimensional space. This lets you work in thousands of dimensions without the slowness or storage cost—the kernel function does all the work behind the scenes. You get a rich, curved decision boundary without ever building the feature space.
2Kernel choice: encoding smoothness
k(x, x') shape determines how output changes with input—narrow vs. wide, periodic vs. smooth
The kernel function is not magic—it's your way of saying how much two points should influence each other. A narrow Gaussian kernel says nearby points are similar, and the output is smooth; a polynomial kernel says relationships grow with powers of x. You are directly encoding your assumption about how wiggly or flat the true function should be. Pick wrong, and you'll either underfit or overfit.
3Gaussian processes: predictions with honest uncertainty
μ(x*) = K(x*, X) K(X, X)^{-1} y; σ²(x*) = k(x*, x*) - K(x*, X) K(X, X)^{-1} K(X, x*)
Gaussian processes use the same kernel idea, but instead of picking one answer, they give you a mean prediction μ(x*) and a confidence band σ²(x*). The mean comes from fitting to the data; the confidence grows where you have no training examples nearby. K(X, X) is the similarity table between all training examples, K(x*, X) is similarity from the new point to training, and k(x*, x*) is self-similarity of the new point. This honest uncertainty is why GPs matter for decisions where you need to know how wrong you might be.
4Kernel table: all similarities at once
K_{ij} = k(x_i, x_j) for all training pairs; predictions rely on inverting K
Every kernel method needs to compute how similar each training example is to every other. The kernel table K holds all these similarities in one big table. Solving the problem means inverting this table (or using close relatives like Cholesky), which is expensive when you have thousands of examples. But the payoff is that this single table of numbers is all you need to make predictions anywhere in the input space.
The through-line. The core problem is learning a rule without guessing its global shape ahead of time. One route is to ask, for each new point: how similar is it to the examples I have already seen? And then borrow those examples' answers, weighted by similarity. Kernels answer the similarity question without building a high-dimensional feature space; different kernel choices embed different smoothness assumptions. Gaussian processes push the idea further by admitting uncertainty: not just a best guess, but a confidence interval built from the data's sparsity and the kernel's decay. Two plain ideas carry it: let the data's local neighborhood structure reveal the rule's shape through similarity weighting, and make similarity computation cheap by computing it directly in the original space rather than expanding into a richer hidden one.
