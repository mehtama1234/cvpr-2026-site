Reinforcement learning — why it works, mathematically

Train agents by climbing the gradient of expected reward — but you're climbing exactly what you wrote, so guard against reward hacking.

The problem, as a quantity

The goal is simple: maximize expected cumulative reward J(θ) = E_π[ Σ_t γ^t·r_t ] as an agent learns a policy π_θ. But the reward is a sampled black box you can only observe, never differentiate. Standard optimization assumes you can compute gradients directly; here, the reward function itself blocks that path. The policy's parameters θ control which actions appear likely — the only lever you have — yet the only signal you get back is a scalar reward on each trajectory. How do you extract a useful gradient from samples of something you can't differentiate?

The core ideas — and why they work

Policy gradients via score-function

The core trick that makes RL optimization possible
Instead of differentiating the reward (impossible), differentiate the log-probability of actions. The identity ∇_θ J = E[ Σ_t ∇_θ log π_θ(a_t|s_t)·(R_t − b) ] converts the problem: rather than ∇r, you compute ∇ log π and weight it by how much the return beat a baseline b. The return R_t is just a number you observe; multiplying it by the gradient of log-probability is the CREDIT ASSIGNMENT step. Actions that led to above-average reward get pushed higher; below-average actions get suppressed. No derivative of the black-box reward needed — only its samples.

Reward hacking and the alignment problem

Why RL systems exploit their incentive
Once you define a reward r(s, a), the policy will optimize it exactly — finding every loophole and proxy shortcut. The mathematics is clean: the gradient ∇_θ log π·r climbs the value of r with no regard for intent. If r is 'maximize pixels on screen', the agent might cover the screen with darkness. If r is 'point at target', it might point at the shadow. RL does not understand goals; it compresses your loss function into actions. This is not a bug—it is the definition of optimizing a function. The aligned reward is your responsibility.

KL regularization as a safety leash

Bounding the policy's distance from a trusted reference
To prevent unbounded reward hacking, add J(θ) − β·KL(π_θ ‖ π_ref), where π_ref is a known-good policy and β sets the tightness. The KL divergence measures distributional distance; subtracting it punishes the policy for straying far. This forces a trade-off: pursue high reward, but not at the cost of diverging drastically from the reference. In RLHF, π_ref is often a supervised model; in language-model alignment, it anchors what 'on-distribution' means. Without the leash, optimization runs off the rails; with it, you buy back safety at the cost of final reward—a deliberate constraint.

Inverse problem: designing the reward

The mathematical optimization is clean; the specification is not
The score-function gradient tells you how to climb any reward hill. The hard part is writing r such that climbing it serves your goal. Reward engineering requires intuition, iteration, and often domain expertise. A robot learning to locomote needs r to account for speed, stability, energy, and smoothness—and different weightings yield different gaits. A language model needs r to encode fluency, factuality, and safety. The math says 'maximize r'; your job is ensuring r encodes 'do the right thing.' This inverse problem—specifying an objective such that maximizing it aligns with intent—is RL's deepest challenge.

The approaches, as variations on the math

Policy gradient methods like REINFORCE and PPO climb ∇_θ J directly via sampled trajectories. Value-based methods (Q-learning, actor-critic) learn to predict future reward, improving sample efficiency. RLHF in language models combines a frozen reference policy with a learned reward model to align generation with human preference. GRPO uses reasoning traces as reward signals, pushing policies to find better solution paths. Reward at scale—multi-robot or large swarms—distributes the learning signal across many parallel agents, each sampling and climbing locally. Inverse RL flips the problem: given expert demonstrations, infer the hidden reward. In each case, the core idea remains: differentiate the log-probability, weight by observed reward, and update the policy to climb.

1Aligning generation with reward: preference optimization for images and video
R_pair = logit(π(y_better) - π(y_worse)) + λ·KL(π‖π_ref); train consistency/style/detail rewards as separate models, then combine via weighted sum to steer image/video generation
Preference optimization (PaCo-RL, Style-GRPO) works by scoring paired outputs (good vs. bad) and using the log-odds difference as a reward signal. Multiple task-specific rewards (consistency, style preservation, detail quality) are learned separately then weighted together, avoiding the single-objective reward hacking problem by explicitly balancing competing goals.
PaCo-RL: Advancing Reinforcement Learning for Consistent Image Generat — Trains a consistency reward model by comparing paired images, using contrastive loss on embeddings to measure style and identity preservation via cosine similarity.
Style-GRPO: Semantic-Aware Preference Optimization for Image Style — Decomposes reward into orthogonal objectives (style transfer vs. content preservation) and optimizes via multi-head DPO loss, each head → gradient independent.
GDPO-SR: Group Direct Preference Optimization for One-Step Generative — Uses attribute-aware reward scoring that samples smooth regions vs. edge regions separately, then combines via weighted sum → explicit spatial decomposition.
Mind the Generative Details: Direct Localized Detail Preference Optimi — Creates preference pairs by spatio-temporal corruption (random frame/region drops), computing loss only on affected regions via mask-weighted cross-entropy.
2Reasoning by reward: GRPO for multimodal LLMs
J(θ) = E[∇log π_θ(a|s)·(R_task(a) - b(s))] with R_task normalized per dataset: R_norm = (R_raw - median[R_task_i]) / std[R_task_i]
Multimodal reasoning (MedGRPO, PEARL) uses policy gradients on task-specific rewards anchored to verifiable evidence (images, text). Normalizing rewards across datasets ensures that one dataset's reward scale does not dominate training, enabling balanced multi-task RL where diverse perception tasks learn simultaneously.
MedGRPO: Multi-Task Reinforcement Learning for Heterogeneous Medical V — Normalizes cross-dataset rewards by mapping each dataset median to common anchor, then optimizes via scaled KL-regularized policy gradient: Σ w_i * (reward_i - β * KL).
Dr. Seg: Revisiting GRPO Training for Visual Large Language Models thr — Applies group-relative policy optimization where within-group ranking replaces absolute rewards, sorting trajectories by metric then computing relative gains.
Perceptual-Evidence Anchored Reinforced Learning for Multimodal Reason — Rewards are constructed as products of perceptual evidence probabilities (image features × text features), converting multi-modal alignment into joint log-likelihood.
Incentivizing Versatile Video Reasoning in MLLMs via Data-Efficient Re — Uses multi-task RL with task-specific reward heads summed via learned gates, optimizing both policy and gate weights via alternating gradient descent.
3Designing the reward: reward models, curricula, and the hacking problem
Curriculum: difficulty β(t) = initial + ramp·t; variance filter σ²(traj) to select high-information samples; token-reward decompose coarse r via ∇r · δtoken (first-order attribution)
Hacking prevention uses three levers: (1) co-evolutionary curriculum that gradually raises task difficulty so the policy cannot overfit to easy modes, (2) trajectory variance filtering to select samples where the reward signal is most informative (low-confidence predictions matter most), and (3) fine-grained token-level reward attribution so the policy learns what specific actions earned the reward, not just exploits aggregate numbers.
FinPercep-RM: A Fine-grained Reward Model and Co-evolutionary Curricul — Decomposes action rewards into sub-component scores (position, velocity, efficiency), then increases difficulty curriculum level when mean reward crosses threshold.
Expand and Prune: Maximizing Trajectory Diversity for Effective GRPO i — Selects high-variance reward subsets via covariance filtering, then applies in-process trajectory pruning: drop low-reward rollouts before computing policy gradient Σ.
Unlocking Token Rewards via Training-Free Reward Attribution — Uses first-order Taylor approximation to decompose coarse reward into token-level components: r_token ≈ (∂r/∂h_t) · Δh_t for each token logit.
Are We Ready for RL in Text-to-3D Generation? A Progressive Investigat — Systematically ablates reward model architectures, GRPO variants (entropy/KL scaling), and scaling laws by varying batch size and training steps in controlled sweeps.
4Reward for perception: RL where the goal is not differentiable
Two-stage: supervised pretraining learns critic π_clip from CLIP labels; hierarchical RL optimizes π with chunk-level temporal rewards R_t = consistency(frame_t, frame_t-1) + relevance(frame_t)
Perception tasks (keypoint tracking, frame selection) lack differentiable goals, so RL uses a two-stage approach: first pretrain a value critic on a proxy task (CLIP relevance), then fine-tune with RL using explicit temporal consistency rewards. Hierarchical decomposition (temporal chunks → spatial details) reduces variance by structuring the credit assignment problem.
From Pairs to Sequences: Track-Aware Policy Gradients for Keypoint Det — Defines track-aware reward as temporal consistency metric (IoU between consecutive detections), then backprops through selection policy via reinforce estimator.
Efficient Frame Selection for Long Video Understanding via Reinforceme — Two-stage learning: supervised pretraining → CLIP relevance prior p(relevant|frame), then RL fine-tuning maximizes cumulative relevance via hierarchical policy gradient.
EVA: Efficient Reinforcement Learning for End-to-End Video Agent — Hierarchical RL with temporal abstraction: high-level policy picks chunks, low-level spatial policy operates on compressed representations, rewards → per-chunk task success.
Saliency-Guided Representation with Consistency Policy Learning for Vi — Decouples representation learning from reward via auxiliary saliency loss, then applies consistency policy that minimizes reconstruction error: ||f(x_1) - f(x_2)||^2.
5Learning to move: RL for legged locomotion and agile control
Trajectory reward R_traj = Σ[v_desired·v_actual + τ·(load_state - load_pred)] where load_state tracked by built-in model; contrastive goal reward R_goal = log(sim(video_demo, video_rollout) / sim(video_demo, random_video))
Locomotion RL solves for unobserved dynamics (load forces, thrust coupling) by bundling a forward model into the reward (load tracking). Goal-contrastive rewards learn from video demonstrations alone (no action labels) by treating the demo video as positive and random videos as negatives, grounding the reward in perceptual similarity without manual annotation.
On-Robot Reinforcement Learning with Goal-Contrastive Rewards — Extracts reward signal from video-only demonstrations via contrastive learning: maximize similarity to positive frames, minimize to negative, then apply as scalar reward.
Learning to Swim: Reinforcement Learning for 6-DOF Control of Thruster — Trains in parallel physics simulator with domain randomization (thrust noise, drag variation), then applies learned policy directly → sim-to-real via randomized Gaussian parameters.
Beyond Robustness: Learning Unknown Dynamic Load Adaptation for Quadru — Builds load-motion model as auxiliary predictor (e_load = model(internal_state, predicted_load)), feeds into policy via concatenation: state ← [q, dq, e_load].
Watch Less, Feel More: Sim-to-Real RL for Generalizable Articulated Ob — Replaces raw image observations with compact perception module outputs (e.g., estimated joint angles), reducing observation dimension and improving generalization via state abstraction.
6Reward at scale: RL for multi-robot coordination, exploration, and assembly
Multi-robot: π_i chooses next frontier via attention over comm-compressed map; residual RL: π_residual = π_imitation + ε·∇log π_RL·(R_refine - R_imitation); curriculum β_start ← demo_state + progress·(state_range - demo_range)
Scaling RL to teams uses three mechanisms: (1) centralized path planning (A*) + decentralized learned policies for frontier selection, reducing communication overhead; (2) residual policies that keep imitation learning frozen and train a lightweight correction policy, preserving stable behavior while adding refinement; (3) demonstration-seeded curriculum that begins in easy demo configurations and gradually expands state coverage, ensuring the policy learns before exploration becomes chaotic.
Reinforcement Learning Driven Multi-Robot Exploration via Explicit Com — Each robot's RL policy outputs next boundary via softmax over frontier set, guided by A* path cost and compressed map representation (occupancy grid → embedding).
From Imitation to Refinement - Residual Rl for Precise Assembly — Residual RL architecture: frozen base policy + learnable correction policy added as residual, optimized via policy gradient on assembly error difference: ΔE = E_base - E_residual.
DemoStart: Demonstration-Led Auto-Curriculum Applied to Sim-to-Real wi — Initializes trajectories from demonstration states, then gradually expands initial state distribution via curriculum: P(s_0, t) = demo_states if t < T_1 else uniform.
Learning Adversarial Policies for Swarm Leader Identification Using a — Prober robot trains via PPO to maximize leader-exposure policy: reward = detection_change_rate, then swarm trains to counter via learned formation policy on latent identity.
The through-line. RL solved the black-box optimization problem via the log-derivative trick. But optimizing a reward function is only as good as the reward itself. The mathematical machinery is now clear and scalable; the challenge has shifted to specification—writing rewards that capture intent—and safety—bounding how far policies will go to exploit their objectives.
