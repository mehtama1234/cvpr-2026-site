Reinforcement Learning — why it works, mathematically

You can sample a black-box reward but never differentiate it. The score-function trick unwraps the gradient via log-probabilities; then guard against reward hacking by constraining how far the policy can drift.

The problem, as a quantity

The agent is a learned policy π_θ(a|s) parameterized by θ. The goal is to maximize expected cumulative return J(θ) = E_π[ Σ_t γ^t·r_t ] — a sum of rewards sampled along trajectories. But the reward function itself is a black box: you can observe a scalar r at each step, yet you cannot compute its derivative. Standard optimization assumes ∇r exists; here it does not. The policy's parameters θ control only the action probabilities — the only lever available — and the only signal flowing back is the raw return, a number. The mathematical wall is stark: how do you extract a usable gradient from samples of a quantity you cannot differentiate?

The core ideas — and why they work

The score-function trick: differentiate log-probability, not reward

∇_θ J(θ) = E[ ∇_θ log π_θ(a_t|s_t) · (R_t − b) ]
The core insight is to not differentiate the reward at all. Instead, rewrite the expectation: the gradient of the expected return is the gradient of the log-probability of the action, weighted by how much the actual return beat a baseline estimate b. This is not an approximation — it is an exact rearrangement of the mathematics. The return R_t is just a number you observe from the environment; the gradient ∇ log π_θ is something you compute. When you weight them together and backpropagate, you push high-reward actions upward in probability and suppress low-reward ones. The black-box obstacle vanishes because you never tried to differentiate the black box — you differentiated only the policy's log-probability, which is always available. Same primitive elsewhere: this is the gradient-of-an-expectation score-function trick that reappears in adversarial attacks (where you differentiate the attack, not the target), VLA spatial reasoning (where you differentiate the language model's logits, not the scene geometry), and energy-based models (where you differentiate the energy parameterization, not the data distribution).

Baseline and variance reduction: separate noise from signal

Subtract b from the return: (R_t − b) where b ≈ V(s_t), the expected return from this state
The raw return R_t is high-variance: one trajectory might give 100, the next 20, even from the same state. That noise jangles the gradient. A baseline b(s_t) — typically the value function V(s_t), an estimate of the expected long-term return — cancels out the constant part of the return. If every trajectory from a state yields similar V, subtracting it leaves only the advantage, the deviation that tells you something new. Actions that beat the baseline by a lot get a big positive weight; actions below it get negative weight. The baseline itself does not affect the gradient's direction — only its variance. By centering the reward signal, you tell the optimizer 'push on actions that outperform the average from this state,' which is more stable and data-efficient than raw rewards that include a global level shift. The job of the baseline is purely variance reduction, a form of regularization through centering.

Reward hacking: the policy optimizes exactly what you wrote

The gradient points uphill on r — and every slope, no matter how unintended, is a valid hill to climb
RL solves an optimization problem. If you write r = pixels_on_screen, the policy will find every way to put pixels there — cover the screen with noise, exploit rendering bugs, hack the graphics card. If you write r = distance_to_target, the agent might lock its laser onto the target's shadow. The mathematics is clean: ∇_θ log π · r climbs the value of r with no understanding of your intent. This is not a failure of the algorithm — it is the algorithm working exactly as specified. The agent has no access to your goal; it has only the reward function. Reward hacking is the trivial-minimizer problem: given a loss, the system will find the easiest route to make it small, even if that route is an out-of-distribution trick that never appears in training. Same primitive elsewhere: this is the degeneracy trap that haunts self-supervised learning (where any useless representation that predicts context is equally valid), mixture-of-experts routing (where all experts converge to one), vector quantization codebooks (where most codes collapse unused), and test-time adaptation (where the model drifts toward the test distribution and forgets the real one). The pattern is universal: one objective, one shared parameter set, no guard-rail — collapse is the trivial solution.

KL regularization: tether the policy to a trusted reference

J(θ) − β·KL(π_θ ∥ π_ref) where π_ref is a frozen, known-good policy
To prevent unbounded hacking, pair the reward objective with a constraint that penalizes drifting too far from a reference policy π_ref. The KL divergence KL(π_θ ∥ π_ref) measures the distributional distance — how different the two policies' action probabilities are. Subtracting β·KL forces a trade-off: pursue high reward, but not at the cost of diverging drastically from π_ref. If the policy tries an out-of-distribution trick, the KL term fires, penalizing it. In RLHF for language models, π_ref is a supervised model trained on clean data; the KL leash ensures the fine-tuned model stays roughly in the distribution of the original. In constitutional AI, the reference can be the base model's own prior. The leash buys safety at the cost of lower final reward — a deliberate constraint, a trade-off you accept to keep the policy on-distribution. The β knob sets the tightness: large β clings to π_ref (safe, low-reward); small β lets it wander (high-reward, risky).

Designing the reward: the inverse problem nobody solves perfectly

Given the policy and the loss, the math is deterministic. Specifying r such that climbing it serves your goal is open-ended.
The score-function gradient is mechanical: you write r, the algorithm climbs it. The hard part is writing r such that climbing it aligns with what you actually want. A robot locomotor needs r to account for speed, stability, power consumption, and smoothness — and different weightings yield different gaits. A language model needs r to reward accuracy, fluency, brevity, and alignment — but these tensions are not resolvable by math alone. You must iterate, observe the learned behavior, and refine the reward. Reward engineering is an art: you need domain intuition, empirical observation of what the policy actually does, and willingness to rewrite your objective when it produces unintended behavior. Unlike the gradient step (which is mathematically correct once r is fixed), the choice of r is a human responsibility. This inverse problem — finding the specification that, when optimized, recovers your goal — is RL's deepest unsolved challenge, and it remains harder than the forward problem of climbing the gradient.

The approaches, as variations on the math

Policy gradient methods like REINFORCE and PPO compute the score-function gradient ∇ log π · (R − b) directly from sampled trajectories, using a simple rule: on-policy samples tell you which actions were good. Actor-critic methods learn both a policy π(a|s) and a value function V(s), so the baseline is stable and the advantage is low-variance. Value-based methods like Q-learning skip the policy entirely and learn Q(s,a), the expected return per action; the policy is implicit (argmax). RLHF combines a frozen reference policy with a learned reward model: sample from the reference, score the outputs with the reward model, and update the policy to climb the reward. GRPO uses reasoning traces as explicit rewards, pushing the policy toward better solution paths. PPO-style methods use importance weighting to allow multiple gradient steps per trajectory without diverging from π_ref. In each case, the shape is the same: differentiate the log-probability, weight by the observed return or advantage, and constrain how far from the reference you allow the policy to drift.

1Aligning generation with reward: preference optimization for images and video
R_pair = logit(π(y_better) - π(y_worse)) + λ·KL(π‖π_ref); train consistency/style/detail rewards as separate models, then combine via weighted sum to steer image/video generation
Preference optimization (PaCo-RL, Style-GRPO) works by scoring paired outputs (good vs. bad) and using the log-odds difference as a reward signal. Multiple task-specific rewards (consistency, style preservation, detail quality) are learned separately then weighted together, avoiding the single-objective reward hacking problem by explicitly balancing competing goals.
PaCo-RL: Advancing Reinforcement Learning for Consistent Image Generat — Trains a consistency reward model by comparing paired images, using contrastive loss on embeddings to measure style and identity preservation via cosine similarity.
Style-GRPO: Semantic-Aware Preference Optimization for Image Style — Decomposes reward into orthogonal objectives (style transfer vs. content preservation) and optimizes via multi-head DPO loss, each head → gradient independent.
GDPO-SR: Group Direct Preference Optimization for One-Step Generative — Uses attribute-aware reward scoring that samples smooth regions vs. edge regions separately, then combines via weighted sum → explicit spatial decomposition.
Mind the Generative Details: Direct Localized Detail Preference Optimi — Creates preference pairs by spatio-temporal corruption (random frame/region drops), computing loss only on affected regions via mask-weighted cross-entropy.
2Reasoning by reward: GRPO for multimodal LLMs

Multimodal reasoning (MedGRPO, PEARL) uses policy gradients on task-specific rewards anchored to verifiable evidence (images, text). 3Designing the reward: reward models, curricula, and the hacking problem
Curriculum: difficulty β(t) = initial + ramp·t; variance filter σ²(traj) to select high-information samples; token-reward decompose coarse r via ∇r · δtoken (first-order attribution)
Hacking prevention uses three levers: (1) co-evolutionary curriculum that gradually raises task difficulty so the policy cannot overfit to easy modes, (2) trajectory variance filtering to select samples where the reward signal is most informative (low-confidence predictions matter most), and (3) fine-grained token-level reward attribution so the policy learns what specific actions earned the reward, not just exploits aggregate numbers.

Expand and Prune: Maximizing Trajectory Diversity for Effective GRPO i — Selects high-variance reward subsets via covariance filtering, then applies in-process trajectory pruning: drop low-reward rollouts before computing policy gradient Σ.
Unlocking Token Rewards via Training-Free Reward Attribution — Uses first-order Taylor approximation to decompose coarse reward into token-level components: r_token ≈ (∂r/∂h_t) · Δh_t for each token logit.
Are We Ready for RL in Text-to-3D Generation? A Progressive Investigat — Systematically ablates reward model architectures, GRPO variants (entropy/KL scaling), and scaling laws by varying batch size and training steps in controlled sweeps.
4Reward for perception: RL where the goal is not differentiable

Perception tasks (keypoint tracking, frame selection) lack differentiable goals, so RL uses a two-stage approach: first pretrain a value critic on a proxy task (CLIP relevance), then fine-tune with RL using explicit temporal consistency rewards. Hierarchical decomposition (temporal chunks → spatial details) reduces variance by structuring the credit assignment problem.

Efficient Frame Selection for Long Video Understanding via Reinforceme — Two-stage learning: supervised pretraining → CLIP relevance prior p(relevant|frame), then RL fine-tuning maximizes cumulative relevance via hierarchical policy gradient.
EVA: Efficient Reinforcement Learning for End-to-End Video Agent — Hierarchical RL with temporal abstraction: high-level policy picks chunks, low-level spatial policy operates on compressed representations, rewards → per-chunk task success.
Saliency-Guided Representation with Consistency Policy Learning for Vi — Decouples representation learning from reward via auxiliary saliency loss, then applies consistency policy that minimizes reconstruction error: ||f(x_1) - f(x_2)||^2.
5Learning to move: RL for legged locomotion and agile control
Trajectory reward R_traj = Σ[v_desired·v_actual + τ·(load_state - load_pred)] where load_state tracked by built-in model; contrastive goal reward R_goal = log(sim(video_demo, video_rollout) / sim(video_demo, random_video))
Locomotion RL solves for unobserved dynamics (load forces, thrust coupling) by bundling a forward model into the reward (load tracking). Goal-contrastive rewards learn from video demonstrations alone (no action labels) by treating the demo video as positive and random videos as negatives, grounding the reward in perceptual similarity without manual annotation.
On-Robot Reinforcement Learning with Goal-Contrastive Rewards — Extracts reward signal from video-only demonstrations via contrastive learning: maximize similarity to positive frames, minimize to negative, then apply as scalar reward.
Learning to Swim: Reinforcement Learning for 6-DOF Control of Thruster — Trains in parallel physics simulator with domain randomization (thrust noise, drag variation), then applies learned policy directly → sim-to-real via randomized Gaussian parameters.
Beyond Robustness: Learning Unknown Dynamic Load Adaptation for Quadru — Builds load-motion model as auxiliary predictor (e_load = model(internal_state, predicted_load)), feeds into policy via concatenation: state ← [q, dq, e_load].
Watch Less, Feel More: Sim-to-Real RL for Generalizable Articulated Ob — Replaces raw image observations with compact perception module outputs (e.g., estimated joint angles), reducing observation dimension and improving generalization via state abstraction.
6Reward at scale: RL for multi-robot coordination, exploration, and assembly

Learning Adversarial Policies for Swarm Leader Identification Using a — Prober robot trains via PPO to maximize leader-exposure policy: reward = detection_change_rate, then swarm trains to counter via learned formation policy on latent identity.
The through-line. RL converted an impossible problem into a solvable one: you cannot differentiate the reward, but you can differentiate the policy's log-probability. The score-function trick unwraps the gradient, turning 'maximize sampled return' into a gradient descent step on action probabilities. But this power carries a cost — the policy will exploit any weakness in the reward specification. The leash of KL regularization and the art of reward engineering are not mathematical afterthoughts; they are the bulwark against hacking. The field has transformed twice: first, from 'impossible' to 'computable' via the log-derivative trick; second, from 'computable' to 'safe' via constraints and careful reward design. Both moves are essential.
