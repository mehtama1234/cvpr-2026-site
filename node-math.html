Neural ODEs — why it works, mathematically

A residual block is one Euler step of an ODE. Collapse the layer index to continuous time, solve with any ODE solver, and get depth for free — together with a topological price that is real and fixable.

The problem, as a quantity

Discrete residual networks write h_{k+1} = h_k + f(h_k, θ_k) and must store every intermediate activation to backpropagate — memory grows linearly with depth. More fundamentally, depth is a design decision you bake in before training. The real obstacle is that depth and memory are coupled: you cannot have more depth without paying more memory, and you cannot learn the right depth from data, because it is a fixed integer. The question is not 'how do we handle deeper networks?' — it is 'what is the mathematical object that a stack of residual blocks is an approximation of, and can we work directly with that object?'

The core ideas — and why they work

A residual block is one Euler step of an ODE

h_{k+1} = h_k + f(h_k, θ) ←— Euler step of dh/dt = f(h, t) with Δt = 1
The Euler method for integrating an ODE dh/dt = f(h,t) with step size Δt writes h(t+Δt) = h(t) + Δt·f(h(t), t). Set Δt = 1, index t by layer number, and you have exactly the residual block h_{k+1} = h_k + f(h_k, θ_k). The residual identity connection — the thing that makes ResNets trainable — is not an engineering trick: it is the signature of numerical integration. Once you see this, the whole architecture is a choice of ODE solver and step size. Taking the limit to infinitely many infinitely thin layers recovers the continuous ODE dh/dt = f(h, t), and now depth is time: how long you integrate, not how many blocks you stack. A forward pass becomes one call to an off-the-shelf ODE solver (e.g. Dormand-Prince / Dopri5), which uses adaptive step sizes and error control, so it is automatically deeper where the dynamics are hard and shallower where they are smooth. Same primitive elsewhere: this is the same 'discrete iteration → continuous flow' move that turns score-function MCMC steps into Langevin dynamics and turns discrete diffusion timesteps into the stochastic differential equation at the heart of diffusion models — the recurring primitive of Reshape a Gaussian into your data via continuous transport.

Adjoint method: O(1) memory gradients

dλ/dt = −λᵀ · ∂f/∂h, dθ-grad/dt = −λᵀ · ∂f/∂θ, integrated backwards alongside a re-run of h(t)
Standard backpropagation through an ODE solver is catastrophic: you need every intermediate h(t) to compute gradients, so memory is proportional to the number of solver steps — defeating the whole point. The adjoint method routes around this by never storing h(t) at all. Define the adjoint λ(t) = ∂L/∂h(t), the sensitivity of the loss to the hidden state at each instant. By differentiating the ODE itself, λ satisfies its own ODE running backward in time: dλ/dt = −λᵀ · ∂f/∂h. To evaluate the right-hand side you need h(t) — but you can recompute it on the fly by running the forward ODE backward (ODE dynamics are reversible). You trade storing activations for recomputing them: memory is O(1) in depth, at the cost of roughly 2× compute. This is not an approximation — it is an exact gradient, derived from Pontryagin's minimum principle in optimal control theory. The adjoint is a costate variable: it is the same object as the Lagrange multiplier in constrained optimization, lifted to continuous time. The enemy it defeats: the 'store everything for backprop' constraint that caps how deep ordinary networks can be on bounded memory.

The flow is a homeomorphism — and that is an honest limit

φ_t: ℝⁿ → ℝⁿ is a diffeomorphism for all t ⇒ trajectories cannot cross ⇒ topology of input is preserved
The solution map φ_t(h₀) = h(t) of a well-posed ODE is a diffeomorphism: a smooth, invertible map with a smooth inverse. This follows directly from the uniqueness theorem for ODEs — two trajectories starting at different points can never meet, because if they met at some time t* they would be the same solution from that point backward, contradicting distinct starting conditions. The beautiful consequence: an ODE flow is continuously deforming space like a fluid, and it can never change the topology of what it acts on. A ring of points stays a ring; a knot stays knotted. If your data lives on two nested rings in 2D — say, class 0 inside class 1 — no amount of continuous planar deformation can pull them apart without crossing. This is not a failure of the model; it is a theorem. The fix is augmentation: extend the state h → [h; 0] ∈ ℝⁿ⁺ᵐ with extra zero-initialized dimensions. In the higher-dimensional space, the rings are no longer nested — one can pass over the other — and the flow can separate them. Augmented Neural ODEs recover full universal approximation. The topological constraint is real, but the exit is cheap.

Continuous normalizing flow: the free log-determinant

d log p(h(t))/dt = −tr(∂f/∂h(h(t), t)) ⟹ log p(h(1)) = log p(h(0)) − ∫₀¹ tr(∂f/∂h) dt
Any invertible map φ changes probability density by the log-absolute-Jacobian-determinant: the normalizing flow formula log p(y) = log p(x) − log|det J_φ|. In the discrete setting (RealNVP, Glow), you engineer layers so that det J is cheap to compute. In the ODE setting you never need to compute det J at all: differentiate the change-of-variables formula with respect to time and you get the instantaneous version, d log p/dt = −tr(∂f/∂h). The trace of the Jacobian costs O(n) with a random estimator (Hutchinson), whereas det J costs O(n³). You get exact likelihoods with free Jacobian computation, at the cost of solving an ODE. This continuous normalizing flow (CNF) is the direct mathematical ancestor of flow matching: both parameterize a vector field f(h, t) that transports a simple base distribution (typically Gaussian) to the data distribution. Flow matching just trades the ODE-solver training loop for a simpler regression target — it fits f directly from known conditional paths — but the underlying object, a time-indexed vector field defining a transport, is identical. Same primitive elsewhere: this is the Reshape a Gaussian into your data primitive shared with diffusion models, normalizing flows, and flow matching — Neural ODE is the ancestor, and all of them are solving the same transport problem via different parameterizations of the velocity field.

The approaches, as variations on the math

Every Neural ODE variant is a choice along two axes: what ODE you solve (deterministic / stochastic, first-order / higher-order, in input space / latent space) and how you compute gradients (adjoint / checkpointed backprop / discretize-then-differentiate). Standard Neural ODE: solve dh/dt = f(h,t) in a learned latent space, use adjoint. Latent ODE: encode observations with an RNN, then evolve a latent state forward with an ODE — good for irregularly-sampled time series where you literally cannot use fixed-step recurrent networks. Continuous normalizing flow: solve the ODE and integrate tr(∂f/∂h) alongside it for an exact log-likelihood. Flow matching modernizes this by bypassing ODE-based training entirely — you regress the vector field from known conditional flows rather than backpropagating through the ODE solver. The throughline is always the same: turn the architecture into a learnable vector field, let numerical analysis do the integration, derive gradients from the ODE rather than from the graph.

A worked numeric example

For dh/dt=-0.5h with h(0)=2, the solution is h(t)=2e^{-0.5t}. At t=1, h≈1.21. A neural ODE replaces the fixed -0.5h with a learned vector field, but the idea is the same: depth becomes continuous motion.

The through-line. The move that makes Neural ODEs work is recognizing that a discrete residual network is already doing numerical integration — badly, with a fixed step size of 1, with no error control, and with memory that grows with depth. Taking the limit to the continuous ODE gives you the real object: a learnable vector field on the hidden state, integrated by a proper solver that adapts its step size, and differentiated by the adjoint method with O(1) memory. The cost is real computation (two ODE solves per gradient step) and a genuine topological constraint (the flow is a diffeomorphism, so you need augmentation for complex topology). The payoff is that the same object — a continuous vector field transporting a distribution through time — is exactly what normalizing flows, flow matching, and diffusion models are all computing. Neural ODE discovered the geometry; the later methods found cheaper ways to train it. The recurring primitive is Reshape a Gaussian into your data, and Neural ODE is where the continuous, ODE-based version of that idea was first written down.
