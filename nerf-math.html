NeRF / neural fields — why it works, mathematically

A scene is one giant function that takes a position and direction, and answers 'what color and how solid?'. Photos are pictures made by running that function. Put the picture-making math inside the training loss, and the optimizer rebuilds the whole world.

Plain-English big picture

What this is really about

NeRF represents a scene as a function. Give it a 3D point and a viewing direction, and it predicts color and density. Rendering follows camera rays through that field.

Where topology and shape enter

Topology matters because density should form coherent surfaces and empty spaces. A good scene model should preserve rooms, openings, object boundaries, and connected parts, not just match the training views.

Where the same idea appears elsewhere

It appears in 3D capture, graphics, robotics, archaeology, medical imaging, and simulation.

Why NeRF / neural fields is worth learning

It matters because it showed that photos can supervise a hidden 3D world when the rendering process is differentiable.

The problem, as a quantity

A photograph is a flat picture, not the real 3D scene. That flattening throws away depth, what is hidden behind what, and all the viewpoints that were never captured. The old way is: fit a shape like a mesh (a 3D shape made of triangular faces) or a 3D grid to match the photos, then draw a picture from it. The problem: a mesh must be defined by hand and drawn by rasterization (converting geometric shapes to pixels) — an operation that cannot be differentiated (you cannot take its mathematical derivative). When a pixel comes out wrong, there is no path backwards to say which part of the mesh to move. The optimizer is blind to the drawing step itself. The real bottleneck is this: the drawing step must be built into the math chain, or photos cannot teach the optimizer about 3D shape. NeRF reverses this: instead of making a shape first and drawing it, represent the whole scene as a single continuous function F_θ(x,d) → (c, σ) — for any spot in space and viewing direction, it answers 'what is the color and how solid is it?'. Rendering is defined as an integral (a sum over a continuous range) that works with calculus by default. Geometry is not forced in; it emerges naturally from making the pictures match.

The core ideas — and why they work

The scene as a continuous function

F_θ : (x,y,z,θ,φ) → (c, σ) where σ ≥ 0 is density and c ∈ [0,1]³ is view-dependent colour
A mesh has triangular faces; a 3D grid has small boxes — both are chopped into fixed pieces, and you must decide the size before you learn anything from the data. A neural network (a function learned from data via optimization) with learnable knobs θ takes a different approach: use a function instead of a box full of pieces. Ask the function about any spot in space and it says how solid it is there (σ) and what color light comes out toward you (c). The resolution is practically infinite because the network smoothly fills in between the spots you test. The direction angle input (θ,φ) lets the function learn view-dependent (changes based on viewing angle) effects — for example, a shiny highlight on a glass ball moves as you walk around it, and the network learns that movement. Nothing sits in 3D space; the whole scene lives in just a few million numbers — the knobs themselves.

Adding up color along a ray in a way you can backtrack through

C(r) = ∫₀^∞ T(t)·σ(t)·c(t) dt, T(t) = exp(−∫₀^t σ(s) ds)
Light travels in a straight line from the camera, and along the way it encounters solid stuff. At each spot, two things happen: some of the light bounces off or gets absorbed (controlled by how solid things are, σ), and the rest carries the local color c forward. How much light reaches a particular distance without being blocked is T(t) — it shrinks exponentially as you accumulate more stuff in front. The formula for the final picture adds up all the color contributions along the ray, front to back, each one reduced by how much light survived to reach it. In practice, you do not integrate forever — you sample at N finite spots spaced δ_i apart, and add: C ≈ Σᵢ Tᵢ·(1 − exp(−σᵢ·δᵢ))·cᵢ. Close things dominate, far things fade to black. The key property: every piece of this math is smooth and continuous. You can take derivatives (calculate how the output changes when you nudge the input slightly) — asking 'what if I changed the solid-ness or color by a tiny bit?'. So gradient descent (a method that nudges knobs to lower the error) can flow from a wrong pixel all the way back through the entire chain into the network knobs.

Fourier features wake up the network to fine detail

γ(x) = [sin(2⁰πx), cos(2⁰πx), sin(2¹πx), cos(2¹πx), …, sin(2^L πx), cos(2^L πx)]
A plain neural network with smooth bending naturally acts like a blurry filter. Smooth predictions come fast; sharp edges and fine textures take forever or never show up, because fitting tiny wiggles requires the knobs to be tuned in a precise way the optimizer does not naturally find. We tested this: the gap is real (23.25 versus 34.31 — roughly 14 times worse in pixel error). The fix: transform the input location using sine and cosine at many different scales. The same position x gets turned into many waves, from slow ripples 2⁰ to fast wiggles 2^L. Now the network only has to mix these pre-computed waves — a job it does easily. The spectral bias (network tendency to learn smooth shapes before sharp edges) is not defeated by a bigger network; it is defeated by showing the network different input.

Training just from pictures — no depth labels needed

L(θ) = Σ_rays ‖C_θ(r) − C_gt(r)‖², ∂L/∂θ = Σ_rays (C_θ − C_gt) · ∂C_θ/∂θ
Training is straightforward: pick a ray going through a pixel you know, draw what the current function predicts, compare it to the real photo, and push all the knobs in the direction that fixes the error. Repeat. No human marking up depth or what is what. No point clouds. The function automatically learns to put solid stuff exactly where edges in the picture say it must be, because changing it anywhere else breaks the picture. Different viewing angles compete, so wrong 3D geometry sticks out. Since shape and color are tuned toward the same goal, a function that matches the training photos almost always matches hidden 3D shape too. The downside: this requires hundreds of questions asked to the network per pixel per training round. It is slow.

The approaches, as variations on the math

Every speedup of NeRF answers the same two questions: what replaces the network, and how do you sample faster? The first version asked the network 64–128 times per pixel ray — taking hours per scene. Instant-NGP swapped most of the network for a multi-scale lookup table with numbers at each scale, blended by a tiny network — training dropped from hours to seconds. Dynamic NeRFs add time as a coordinate or learn how shapes deform over frames, enabling video. All keep the same core: scene as a function, pictures computed by an integral, photos teach the shape.

A worked numeric example

If a ray samples densities [0.2,0.5] and colors [1.0,0.4], each sample contributes color weighted by accumulated transmittance. Raising early density both adds its own color and blocks later color. NeRF learns geometry because opacity controls what light reaches the camera.

Hand-drawn meshes lock in the shape upfront so drawing is fast — you just paint the fixed triangles. But you must store millions of numbers. A network learns shape directly from pictures instead, paying a cost each time you ask it a question about one ray, but the entire world lives in just a few million network knobs. 3Where there are no blobs to splat

When you need to read hidden stuff — like X-ray scans, radio waves, or heat — the network learns different properties. Instead of color, it learns how much light gets absorbed or how bright it shines. The math is identical; the network just outputs different numbers, and the loss function measures the right thing (does the simulated X-ray match the real one?). The core idea — summing a quantity along a ray with exponential blocking — stays the same.
These papers apply ray-summing to non-optical data: X-rays, radio waves, and other physical phenomena. The core math is the same; only the physics changes.

The through-line. NeRF rests on one formula and one idea. The formula: add up color along a ray with how much light survives — smooth and takeable backward. The idea: put that formula inside the training loss, so pictures teach 3D structure. The hurdles were spectral bias (fixed by Fourier waves) and cost (you ask the network many times per pixel, still expensive). What matters is not the network itself — it is the decision to make the whole drawing process work with calculus, so you can backtrack from pixel error to the scene knobs. This move — differentiable drawing — repeats in learning hidden 3D from 2D images. The scene-as-one-function, the compression into knobs rather than boxes, and waking up the network via Fourier waves all show up over and over. The core lesson: once you can backtrack through how pictures form, the real world becomes the teacher.
