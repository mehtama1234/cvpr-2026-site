Plain-English big picture

What this is really about

Self-supervised learning creates its own teaching signal from raw data. It might hide part of an image, make two changed views of the same image match, or predict what comes next.

Where topology and shape enter

Topology helps define what should stay the same under changes. Crop, color, noise, or viewpoint may change the pixels, but the underlying object or surface can remain the same.

Where the same idea appears elsewhere

It appears in images, text, speech, biology, medical data, remote sensing, and robotics.

Why Self-supervised Learning is worth learning

It matters because labels are expensive and narrow. Raw data is abundant, and the model can learn useful structure before labels arrive.

The problem, as a quantity

Normally, you label every image by hand: 'cat' or 'car'. Self-supervised learning flips this around: the picture teaches itself. Take one photo and distort it two different ways (crop it, change its colors, rotate it). Ask the network: do these two messy versions show the same thing? If yes, push their squeezed numbers closer together; push other pictures' squeezed numbers away. This sounds easy. But there is a trap: the laziest answer is to output the same number all the time, no matter what image comes in. If you always send back the same number, then every pair of messy versions gets pulled toward that same target, every match looks identical, and the error measure stays flat at the worst possible value—done, no real learning happened. The actual challenge: force two messy versions of the same photo to stay similar to each other AND force all squeezed numbers to spread out and be different from each other. Without a guard against it, the error formula has an easy cheat: make all numbers collapse into one single point. The entire topic is about the mathematics that blocks that cheat.

The core ideas — and why they work

Contrastive learning (InfoNCE)

L_InfoNCE = −log[ exp(s(f(x_i), f(x_i'))/τ) / ( exp(s(f(x_i), f(x_i'))/τ) + Σ_k exp(s(f(x_i), f(x_k))/τ) ) ]

Take one photo, distort it twice: one anchor version and one true partner. Run both through the network to get squeezed numbers. Now ask: which of N squeezed numbers in the batch is the real match? Play a guessing game: the true partner is the right answer, the other N-1 are wrong answers. Use a softmax calculation—turn match scores into percentages that add to 100%: the right match gets a big percentage, wrong matches get tiny ones. Why does this stop the collapse into one number? The denominator (bottom part of the fraction) adds up all N options. If your network outputs the same squeezed number for every input, then all N matches are identical, the top matches the bottom, and the error stays flat at the worst value—not improving. To lower the error, the network must make the true match score higher than all the wrong ones. That forces the squeezed numbers to spread out and be different from each other. The knob called tau controls how picky the softmax is: small tau makes it strict (wrong answers must be very different), large tau makes it forgiving (wrong answers can be similar). The key point: the denominator forces the network to pick winners and losers, stopping uniform collapse.

Non-contrastive: stop-gradient + variance (BYOL, VICReg, DINO)

L = |f(x_i) − sg[f(x_i')]|² + λ_var(−Var_batch[z]) + λ_cov C_batch

Contrastive methods need huge batches (thousands of images) to work: more wrong answers make the network spread out more. But BYOL removes wrong answers entirely and does something different. It runs one distorted view normally through the network, and runs the other through a frozen copy (freeze it, stop learning). Match them using squared error: how far apart are the two squeezed numbers? Why does this not collapse immediately into one number? Because one side is frozen and does not learn. If the learning side shrinks to a tiny constant, gradients only flow back through the learning side and a matching head—the frozen side never changes. The matching head quickly learns to output that tiny constant, then stops improving. The model is stuck. To escape, BYOL adds a second rule: spread out the squeezed numbers across the batch. Make them take up more of the space rather than cluster together. VICReg makes this explicit: add a penalty that pushes the numbers to be more spread and more independent (each number direction is different from the others). DINO does something similar but updates the frozen copy slowly instead of stopping it. The core rule: without a softmax denominator forcing the network to be comprehensive, you must explicitly regulate spread and independence by hand. These replacements do the same job that the softmax denominator does. Collapse can happen in many places: router networks pick one path and ignore the rest, unused code-dictionary entries die off, reward formulas output any constant value, mode-seeking at test time (always picking the same answer). The fix is always the same: add an anti-collapse rule. It is not about redesigning the main formula, but adding a guard.

Masked reconstruction (MAE, masked language models)

L_recon = |x_hidden − decoder(encoder(x_visible))|², masking ratio m ∈ (0.5, 0.9)

Hide a large fraction of the input (75% of image squares, or 80% of words). The first network sees only what is left. A second network guesses what is missing, using only the squeezed numbers from the visible part. The imbalance is crucial: the first network cannot throw away information—if it does, the second network has nothing to work with. This forces a bottleneck on purpose. Why does it stop collapse? If the first network outputs the same squeezed number no matter what input it sees, the second network gets zero clues about what the hidden parts should be. The error shoots up. The task itself rewards squeezed numbers that carry a lot of different information. Reconstructing pixels or words naturally discourages shrinking—more numbers in the squeeze means more information available, which means lower error. Unlike contrastive learning (which asks 'do these show the same thing?'), masked reconstruction asks 'what was hidden?'—only squeezed numbers that understand the content can solve it. The hiding fraction controls difficulty: high fractions (80%, 90%) force the first network to extract the most important structure.

Joint-embedding predictive architecture (JEPA)

L = |predictor(proj_1(f(x_i))) − sg[proj_2(f(x_i'))]|² + λ_var(−Var[z]) + λ_cov||C − I||

JEPA combines all three ideas: predict one distorted view in the squeezed space of another, both run through networks. Use a frozen target (like BYOL—stop learning on one side) to block instant collapse into one number. But also add explicit spread and independence rules (like VICReg), so the predictor cannot output tiny or repetitive numbers. Three defenses: (1) stop learning on one side blocks the predictor from collapsing (output constant, freeze, done), (2) spread and independence rules prevent tiny or repetitive output, (3) two network branches learn together. The two projection heads map squeezed numbers to a new space; different structures on each side break symmetry and prevent collapse from either direction—neither side is the easy option. Multiple safeguards mean if one loosens, others catch the collapse. The predictor runs in squeezed space (not pixel space), so learning signals do not blur through pixel noise. Multiple defensive layers appear in other models too: energy-based models add score functions plus constraints, and Bayesian inference uses regularization plus distance penalties.

The approaches, as variations on the math

Contrastive alone: Push one distorted version close, push others far using a huge batch of wrong answers. Scale to thousands of wrong answers per step; tuning the sharpness setting is essential. Works well when the batch has varied images—each has distinct wrong answers. Cost: lots of computing power and memory, syncing across multiple computers.

Non-contrastive (BYOL recipe): Remove wrong answers, add stop learning. Simpler to code; no need for syncing across computing devices. Trade-off: must explicitly regulate spread; weaker without huge batches. Modern version: drop the second matching head, just match squeezed numbers directly with spread penalty.

Masked prediction plus fine-tuning: Pre-train by guessing hidden squares or words. Squeezed numbers learn fine detail because the second network must reconstruct. Fine-tune later: swap the second network for a task-specific head, freeze the first network or train it lightly. Advantage: the first network already understands structure.

Cross-modal (CLIP-style): Pictures and descriptions are two versions of the same content. Contrastive error aligns image and text squeezed numbers. Learning result: the model discovers that visual patterns map to word meanings, enabling zero-shot guessing on new categories (find the image closest in word space to a new description).

Robot learning from video: A robot's video stream is free self-supervised signal. Hide the next frame, predict it (time-based prediction). Or use two cameras: left and right see the same 3D world. Model learns what is real (robot position, world state) versus noise (lighting, camera quirks). Combine with world-change models to learn how the world evolves.

A worked numeric example

Two augmented views of the same image are pulled together while other images are pushed apart. If positive similarity is 3 and negatives are [1,0], the contrastive probability is about 0.844. If all embeddings collapse to the same vector, positives and negatives tie, and the objective loses its signal.

1Predict the hidden part
x_hat = decoder(encoder(x_visible)); minimize ||x_hidden - x_hat||² — unmasked regions encode enough to reconstruct masked regions without seeing them
Masked prediction works because pictures have patterns that repeat: nearby squares look similar. The first network must fit all scene information into visible squares, then the second network uses that nearby similarity to guess what is missing. Papers (RVM, MuM, SARMAE, NeighborMAE) use this same idea on video frames (different times look similar), multiple camera angles (different views show the same world), radar (different sensor types see the same place), and satellite images (neighboring areas resemble each other) by changing what you can see but keeping the rule: information you cannot see lives in information you can.
These papers hide parts of pictures or video and train networks to guess what is missing. They squeeze different types of information: time (next video frame), different viewing angles (3D shape), different sensors (laser versus camera), or geographic area (neighboring satellite images).

2Match two views
z₁ = encoder(view₁); z₂ = encoder(view₂); maximize similarity(z₁, z₂) via teacher-student distillation with EMA updates to target encoder
Two views of the same scene carry the same meaning but show different pixels. A teacher network extracts stable meaning from one view; a student catches up by learning on the other. Slowly updating the teacher stops collapse: the target drifts gradually, so the student always has something to chase. Papers (PointINS, TimeBridge, SPECTRE) use this same idea on 3D point sets (different angles), video start and end frames (different times), and 3D scans (different sensor passes)—the rule stays the same: turn different angles, times, or sensors into one squeezed space.
These papers train one network to teach another by viewing the same scene from different angles or at different times. The teacher is frozen or changes slowly, forcing the student to keep chasing a moving target.

3Predict in latent space, and fight collapse
z_t = encoder(x_t); z_pred = predictor(z_t); loss = ||z_pred - sg(z_target)||² + λ·covariance_regularization(z_pred) — stop-gradient + variance penalty
Guessing in squeezed space is faster than guessing pixels but invites collapse: the network can shrink predictions to a dot and get zero error. Spread and independence rules force predictions to scatter across the space; stop learning on target blocks the predictor from shrinking that too. Papers (PHANTOM, V-JEPA, degeneration studies) show this rule works for video (next frame prediction), physics models (world change), and diffusion (iterative refinement)—regularization is the collapse safety net.
These papers predict squeezed numbers, not raw pixels, then add safety rules to stop collapse. Spread, independence, and physics constraints keep predictions scattered and meaningful.

The through-line.

The core idea is simple: a good squeezed representation must compress what matters while throwing away what does not. Self-supervised learning asks a question only the data can answer: do two messy versions encode the same thing? But that question has an easy cheat—squash all numbers into one point, and all versions look identical. The entire topic is about mathematics that blocks that cheat. Contrastive methods block it via the softmax denominator (no single number beats all comparisons). Non-contrastive methods regulate spread and independence by writing the rules explicitly (like softmax but written out step-by-step). Masked methods hide input, so the first network must preserve information—the task itself prevents collapse. These are not separate tricks; they are different ways to pull the same lever: squeeze what matters while keeping things spread out. That tension, written as mathematics, pulls features out of data with no labels needed.
