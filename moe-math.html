Mixture of experts — why it works, mathematically

A model that has learned a great deal has to run its entire bulk of numbers on every single piece of input, even when almost none of that knowledge is relevant. This is how it learns to switch on only the few specialist parts a given piece actually needs — and the one trap that ruins it.

Plain-English big picture

What this is really about

A mixture of experts stores many specialist networks but uses only a few for each input. A router decides which experts should handle the current case.

Where topology and shape enter

Topology appears in the routing map. Inputs that are close in meaning should often go to similar experts, while different regions of the data surface can be served by different specialists.

Where the same idea appears elsewhere

MoE is used in language models, vision, recommendation, retrieval, and large multi-task systems.

Why Mixture of experts is worth learning

It matters because it gives a model more capacity without paying the full cost on every example.

The problem, as a quantity

A model that knows a lot — grammar, geography, chemistry, poetry — stores that knowledge as a huge pile of adjustable numbers, and normally it runs the whole pile for every incoming piece of input, say each word. That is wasteful: the numbers that are expert in rare chemistry still get run on an ordinary word about the weather. And it caps how much the model can know, because doubling the knowledge doubles the work done on every piece.

The obvious wish is to let the model switch on only the handful of its parts that matter for the piece in front of it, and leave the rest idle. The obstacle is learning. Picking 'these parts, not those' is a hard yes-or-no choice, and a model learns only by making tiny adjustments that lower its mistakes — a hard choice offers no gentle slope to adjust along. And the lazy escape — softly running all the parts a little and blending them — brings back exactly the full cost you were trying to avoid.

So the real problem is sharp: build a chooser that switches on a genuine small subset of the model's parts, cheaply, yet can still be improved by small nudges — and, as we will see, keep that chooser from quietly collapsing into always picking the same part.

The core ideas — and why they work

Switching on only a few specialists, in a way that can still be learned

y = Σᵢ∈topk gᵢ(x)·Eᵢ(x), g(x) = softmax(router(x)), k ≪ N
Picture the model's knowledge split into many separate specialist networks. Running all of them on every piece would cost as much as one giant network, so instead a small extra network — call it the chooser — looks at the incoming piece and gives each specialist a relevance score. Those scores are turned into shares: all positive, adding up to 1. Then only the few specialists with the largest shares — the top k out of all N — actually run; the rest stay switched off. The output is the shares-weighted blend of just those few.

The reason the scores are turned into shares, rather than used as a bare pick, is learning. Among the specialists that do run, a tiny change in a score makes only a tiny change in the blend, so the chooser can be improved by small nudges toward giving more weight to the specialists that helped and less to the ones that did not. The hard part — 'run only the top few' — rides on top of that smooth core, so the model gets the cheapness of a real subset while keeping a slope it can climb. Because k is far smaller than N, only a sliver of the model runs on any one piece.

The trap: the chooser learns to always pick the same specialist

Collapse: g(x) → [0, …, 0, 1, 0, …, 0] for all x (argmax, entropy → 0)
Left to itself, the chooser finds a lazy answer that is hard to escape. Suppose that early in training one specialist happens to be a little better than the rest. The chooser sends it a few more pieces; because it now trains on more, it gets better still; so the chooser sends it even more — a runaway loop that feeds the strong and starves the weak.

The end state is collapse: for every piece, the shares pile almost entirely onto that one specialist — the share list becomes all zeros except a single near-1 — and the spread of the shares, their entropy, falls to nothing. Now the damage is done. You paid to store many specialists, but only one is ever switched on, so they have effectively merged back into a single overworked generalist. The capacity you built is wasted, and the whole point of the design is lost. Everything else here exists to stop this one thing from happening.

A gentle penalty that forbids the pile-up

ℒ_load = λ·Σⱼ(Σᵢ gᵢ(x^(i))_j)² / (k·|batch|), target ≈ k/N per expert
The cure is to score the model on a second thing, alongside getting the answer right: a penalty that grows whenever the pieces are shared out unevenly. Over a batch, count how much total work each specialist received. If a few specialists hog most of it, the penalty is large; if the work is spread so that each specialist gets roughly its fair portion — about k out of N — the penalty is near zero.

This pushes back precisely against the runaway loop from the previous idea: the moment one specialist starts to hog, the penalty rises and nudges the chooser to send the next pieces elsewhere. So every specialist stays fed with work, stays distinct, and keeps deepening its own specialty. It is a light touch on purpose — it never dictates which specialist should take a given piece, only that the totals across the batch should stay balanced. The answer-getting is still what decides the routing; the penalty just forbids the one degenerate solution.

Why this buys more knowledge without buying more cost

Parameters ∝ N, FLOPs per token ∝ k, N ≫ k
Here is the payoff stated plainly. The number of adjustable numbers in the model grows with N, the count of specialists — add more specialists and the model can hold more knowledge. But the amount of computing spent on each incoming piece grows only with k, the few specialists actually switched on. Since N is far larger than k, you can keep piling in specialist after specialist — a vast store of knowledge — while the bill for each piece barely moves.

That split is the entire trick: many numbers stored, few of them active at any moment. It breaks the usual iron rule that a model which knows more must do more work on every piece. The only thing standing between you and free knowledge is keeping the chooser honest — which is what the balancing penalty is for.

One number that tells you if the chooser is healthy

Perp_router = exp(−Σᵢ gᵢ(x) log gᵢ(x)) = 2^entropy
You want a quick gauge of whether the chooser is spreading its work or quietly sliding toward collapse. Take the spread of the shares and read it as an effective count of how many specialists are genuinely in play. If the chooser uses all the specialists evenly, this count sits up near N; if it has collapsed onto one, the count sinks toward 1.

Watching this single number during training is an early-warning light. A steady, high value means the work is well spread and the specialists are staying distinct. A value that keeps sinking means the runaway pile-up is winning, and it will show up here long before the final answers visibly suffer — early enough to turn up the balancing penalty and pull the model back.

The approaches, as variations on the math

Every mixture-of-experts design is the same machine with a few dials.

How the chooser decides. It can look at each small piece separately, or at the whole input at once; it can learn its scores, or use a fixed rule that spreads pieces by a simple hash. How many run. Switching on just one specialist per piece is the cheapest but the most prone to collapse; two is the common safe floor; more trades cost for smoother blending. What counts as a specialist. It can be a whole sub-network, or merely one slice of a larger layer. How balance is enforced. Either the gentle penalty above, or a hard cap on how many pieces any one specialist is allowed to accept before the overflow is sent elsewhere. Underneath every version the thread is fixed: store many specialists, switch on only a few per piece, and keep the load balanced so none of them dies of neglect.

A worked numeric example

Suppose four experts have router logits [3,2,0,-1]. Softmax weights are about [0.696,0.256,0.035,0.013]; top-2 routing keeps the first two and skips half the network. The model has four experts of capacity, but this token pays for only two.

Soft share-based weighting keeps the path for learning open to every expert while pushing them toward specializing in one type of input. Unlike a hard yes-or-no assignment, this lets the router learn the best balance per token without penalty, and experts naturally group around their strongest input types as a learned side effect.

2The fragile heart
Stabilize router via eigenbasis reparameterization or dual-model guidance: expert_i = U_i · eigenvector_i (orthonormal basis per expert) OR gate_output = blend(student_affinity, teacher_guidance) + drift_penalty
Collapse happens when the router converges to picking one expert; orthonormal re-parameterization (using separate orthogonal coordinate systems for each expert) spreads the learned representation across clean, separate dimensions so diversity is built into the parameter space itself. Teacher guidance or drift-aware penalties add external pressure that stops early collapse by rewarding genuine disagreement about which expert fits best.
These four papers all address the same pathology: router collapse, where the learned selector stops exploring and always picks one expert. One uses orthonormal dimensions to force diversity, another copies guidance from a large teacher model, the third treats selection as a learned choice problem, and the fourth detects ambiguous tokens and expands capacity dynamically.

The through-line. The core difficulty is to let a model choose a small part of itself to run and still learn that choice from nothing but right-and-wrong feedback. Turning the chooser's scores into smooth shares makes the choice learnable; switching on only the top few keeps it cheap; and the balancing penalty stops the choice from collapsing into always-the-same. Two plain ideas do all the work: turn scores into shares so that a choice can be nudged toward better, and add a counter-pressure against the cheap shortcut of dumping everything onto one winner. Once both are in place, the prize — knowing far more without paying more per piece — falls out on its own.
