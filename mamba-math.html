State-space models / Mamba — why it works, mathematically

A compressed memory of the past, updated in linear time via learned choices about what to keep

Plain-English big picture

What this is really about

Mamba and state-space models keep a compact memory that changes over time. Instead of comparing every token to every other token, the model carries a running state and decides what to remember or forget.

Where topology and shape enter

For topology, this is useful when structure unfolds as a scan or sequence: tracing a boundary, following a vessel, walking along a mesh, or reading frames in a video. The memory must preserve the connected story without storing everything.

Where the same idea appears elsewhere

It appears in language, video, audio, sensors, robotics, and long document processing.

Why State-space models / Mamba is worth learning

It matters because long inputs are expensive. A good memory lets a model handle long streams without all-pairs comparison.

The problem, as a quantity

Transformers attend to every token with every other, costing time and memory that grows with sequence length squared. For long documents, videos, or streaming data, this becomes too expensive. The real tension: to stay selective about what matters, you must re-read everything each time a new token arrives, but reading everything costs a lot. Can you instead keep a small fixed-size memory and update it in one pass while still choosing what to remember?

The core ideas — and why they work

Linear recurrence as fixed-memory state

h_t = Ā·h_{t−1} + B̄·x_t, y_t = C·h_t, h_t ∈ ℝ^N, N ≪ L
A linear recurrence compresses all history into a single fixed-size list of numbers, h_t. Linearity unlocks a fast algorithm: you unroll this into one pass over all tokens or compute it in parallel using a tree. This trades the expensive cost of attention (re-reading everything each time) for one pass over the sequence. You compress history, so the memory holds only what it captures. But if the memory is sufficient—if the task doesn't need word-for-word recall—this lossy summary is honest. The memory is a running summary, not a complete record. Fixed-size memory-as-compression is how distillation and world models work too.

Fixed rules for all tokens are fast but rigid

If A, B, C are constants: h_t = A·h_{t−1} + B·x_t ⇒ closed-form convolution, but one memory strategy for all inputs
In a classical linear system, the rules don't change: the model learns one global strategy for what to remember and forget. All tokens are updated by the same rule. This is computationally beautiful but inflexible: the model can't decide what to keep for this token versus that one. Every token gets the same treatment. This is fast but not selective. Attention can change its focus per token. A state-space model gives you speed but hands away that selectivity.

Selectivity: learned choices about what to keep

Mamba: Δ_t, B̄_t, C_t = f(x_t); h_t = exp(Δ_t · A)·h_{t−1} + (B̄_t / Δ_t)·x_t, y_t = C_t·h_t
Mamba breaks the rigid rule: the memory update rules now depend on the input. The model asks: for this token, what matters? If the token is important, make the step size larger to strengthen the memory update; if it's noise, shrink it to let it fade. This is a learned choice—the model trains a function to predict what the memory needs. The memory update stays linear in its rules, so the parallel tree still works. You get attention-like selectivity without the expensive memory cost.

Constant-memory state scales to arbitrary length

State size N is fixed; KV cache size is L×D. For L → ∞ or streaming: state-space is O(1) memory, Transformer is O(L).
A Transformer stores full attention keys and values, growing with sequence length: L tokens, D numbers each. For a million-token document or a video with a million frames, the memory is enormous. A state-space model's memory is always the same size: N numbers, typically hundreds or thousands. You discard information at each step—that's what 'state' means, a lossy summary—but you choose what to discard via learned choices. When trained well, the few crucial bits you keep are more useful than the full record. One fixed-size state summarizes an arbitrarily large image; you never pay the pixel-count tax. For edge devices and robots, this enables inference without huge memory blocks.

Parallel trees: unrolling linearity for fast computation

Recurrence h_t = A·h_{t−1} + B·x_t can be reformulated as: h_L = (A^L, A^{L−1}·B·x_1 + A^{L−2}·B·x_2 + ... + B·x_L). Associative ops → O(log L) parallel depth.
A step-by-step loop can't be parallelized—step t must wait for step t−1. But if you rewrite the memory update as an associative sum, you expose a tree of log(L) depth. GPUs are built for trees: each layer runs all branches in parallel, and after log(L) layers all L steps are done. The trick works only because the math is linear: addition and multiplication are associative. Nonlinear models break this, so you're back to sequential step-by-step. Linearity unlocks hardware parallelism. You give up the power of squashing functions, but Mamba recovers expressiveness via learned selectivity choices, which inject nonlinearity in a hardware-friendly way.

The approaches, as variations on the math

Apply state-space models wherever sequences are long or memory must stay fixed: language models (competitive with Transformers, faster during generation), images and video (one state per image, no pixel-by-pixel cost, arbitrary resolution), audio streams (constant memory for arbitrarily long audio, perfect for real-time), and embedded control (policy memory persists without growing). Hybrids combine both: state-spaces for efficient long-context backbone, then cheap attention for sharp reasoning. For 2D images, scanning order matters—left-to-right top-to-bottom, column-by-column, or space-filling curves change what the state sees first. Small mobile devices benefit most: inference runs without growing memory, while Transformers must allocate the full key-value store upfront.

A worked numeric example

For a one-dimensional state update h_t=0.8h_{t-1}+x_t, an input from five steps ago is weighted by 0.8^5=0.328. If the learned decay becomes 0.95, the same input still has weight 0.774. The state-space lever is visible in the number: change the decay, and the model changes how long memory survives.

1Which order do I read a 2D image
h_t = A_t ⊙ h_{t-1} + B_t ⊙ x_t where A_t, B_t depend on position: adaptive scanning lets image structure choose the state update weights, not raster-scan order
Standard state-space models flatten 2D images into 1D sequences with fixed scanning order. Mamba makes this adaptive: each location learns whether to preserve prior memory (keep it all) or reset it (start fresh), and how much to absorb current input. Some systems learn scanning order by following edges and object boundaries rather than pixel grids, compressing redundant regions while preserving where things change.
These four papers all ask how to scan a 2D image as a sequence without losing information. One uses learned masks per timestep, one adapts the path based on image features, one prunes patches before processing, and one scales the entire backbone to foundation-model size. Each shows that scanning order matters—you can fix it or learn it.

3Every pixel, and unordered 3D
Geometry G guides serialization π(p) of 3D points: h_t = A h_{t-1} + B x_{π(t)} where π preserves local neighborhoods, not Cartesian order
Linear recurrence requires a 1D sequence, but 3D point clouds and volume data have no natural order. Left-to-right top-to-bottom (x, y, z) scrambles the geometry. Some systems bake anatomy or shape into the rules. Axial and lateral slice-scans interleave so information flows in all 3D directions. Others reorder points by local shape properties instead of coordinates, so the geometry is respected rather than imposed by grid coordinates.
These four papers deal with data that has no natural 1D order: medical images, electron microscopy, point clouds, and 3D shapes. Each learns a scanning order or memory update that respects data geometry instead of imposing a grid.

The through-line. Linearity gives you a fast algorithm: parallel trees in log(L) depth. Learned choices give you the power: input-dependent gating lets the model choose what to remember and forget per token. Together: one pass over all tokens, constant memory regardless of length, and a learned strategy for what matters. The trade-off from attention's flexibility is real, but for many tasks—especially long-context and streaming—the speed and memory win is worth it.
