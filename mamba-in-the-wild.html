State-space models · how the field actually goes linear

Read in order, remember a little — Mamba across CVPR & Robotics

The why page argued the idea from first principles: attention compares everything to everything (quadratic), while a state-space model reads the input once with a small running memory (linear time, constant memory) — and selectivity lets it choose what to keep. This page shows how far that reaches. In vision Mamba is the efficiency engine wherever inputs are long or high-res; in a robot, its constant-size memory is what can run forever onboard. Two things to hold onto. In vision, Mamba is chosen as a compute win — process long or high-res inputs at linear rather than quadratic cost — and the recurring puzzle is how to scan a 2D image or 3D cloud without destroying its structure. In robotics, the appeal is different: a robot runs continuously, and attention's cache grows every timestep, so a fixed-size running state fits a real-time, memory-bounded onboard loop.

The uses — from a cheaper backbone to a memory that runs forever

Nine threads. Uses 1-6 are the vision work (backbones+scanning, long video, high-res dense prediction, 3D, hybrid, deployment); 7-9 are the robotics inversion into onboard perception, persistent localization, and runnable policies (CVPR'26 vision · ROBOTICS'25 ICRA/IROS).

1 · Which order do I read a 2D image — backbones & scanning

To use Mamba as a general image encoder you must flatten a 2D grid into a 1D stream — but any single raster order breaks neighborhoods (pixels next to each other in 2D land far apart in 1D). The near-universal sub-problem: design a scan order (multi-directional, diagonal, Hilbert, snake, content-adaptive) so the linear-time backbone still sees 2D structure.

4 · An unordered 3D blob is not a sequence — point clouds & more

7 · Linear-time vision on a small onboard GPU — robot perception

Robotics inverts the appeal. A field robot, drone, or car must segment, detect, and enhance in real time on a small onboard GPU, where transformer cost grows quadratically with image size. Mamba does the same long-range reasoning at linear cost, so these swap attention for selective-scan blocks (often keeping a few attention layers) to hit real-time. The largest robotics bucket.

9 · Small enough to run the policy — control & forecasting

Robot policies increasingly run heavy backbones too big for a small onboard computer. Mamba's linear-time, constant-state design shrinks the policy while keeping the ability to fuse a stream of observations into an action — and serves as the temporal engine keeping predicted trajectories consistent. Honest note: in 2025 the selling point is efficiency, not yet long-horizon memory.

What changes when the robot never stops receiving input

Same mechanism — a linear-time scan with a constant-size state — opposite motivation.

axisCVPR 2026 (vision)Robotics 2025 (ICRA+IROS)
Why linear timeprocess a long or high-res fixed input cheaper — better accuracy per FLOPa stream that never ends — a fixed-size memory that runs forever onboard
The inputa known-length sequence you just want cheaperan unbounded, continuous stream of observations
The enemyattention's quadratic compute on long/high-res inputsattention's cache growing unbounded every timestep

The through-line. A state-space model reads the input in order and carries a small running memory — linear time, constant memory — where attention compares everyone to everyone at quadratic cost. Vision reaches for it to make a long or high-res input cheaper; a robot reaches for it because it acts continuously and needs a memory that does not grow every timestep. Same selective scan; one chases FLOPs, the other chases a loop that can run forever.
