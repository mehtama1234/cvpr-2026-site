1 · Beating the quadratic wall

At the heart of a Transformer, every token stops and compares itself to every other token, then blends them into a content-weighted average. That comparison is the source of all its power and all its pain: with n tokens you get n times n comparisons, so the cost grows with the square of the sequence length. For text that is annoying; for vision it is ruinous, because a high-resolution image or a few seconds of video shatters into tens of thousands of tokens, and squaring that number blows past any memory or time budget. There are really only two ways out. Either you feed attention fewer tokens by pruning, merging, or subsampling the ones that do not matter, or you make the math itself cheaper by replacing the all-pairs comparison with an approximation that scales linearly. Mamba and other state-space models take the second route to its logical end, streaming through the sequence one step at a time and carrying a running summary instead of re-comparing everything, which behaves like a low-rank, linear-time stand-in for the very same weighted average. The papers below attack the wall from both sides.
CVPR'26Trainable Log-linear Sparse Attention for Efficient Diffusion Transformers
Problem
Diffusion Transformers make gorgeous images, but their self-attention cost grows with the square of the token count, so pushing to high resolution quickly becomes unaffordable. The usual fix, keeping only the top-K most relevant tokens for each query, has a hidden catch: just finding those top-K still requires comparing everything to everything, and you have to keep raising K as sequences grow to avoid losing the big picture.
Approach
Their answer, Log-linear Sparse Attention, is a cheaper-math route that shrinks the cost from n-squared to n times log n. The trick is a pyramid: they repeatedly mean-pool the tokens into coarser and coarser summaries, only about log n levels deep. At the coarsest, tiny level they can afford a full all-pairs comparison, then walk back down the pyramid, using each level's winners to decide which fine-grained tokens are worth comparing at the next. Crucially they also keep a handful of coarse summary tokens from every level in the final blend, so each token still senses the global context without paying for every neighbor. A custom GPU kernel keeps this sparse selection fast in both the forward and backward pass by never building a dense attention mask.
Why it matters
Because both the selection and the attention now scale log-linearly instead of quadratically, they accelerate attention inference by over 28 times and match full-attention image quality while comparing far fewer token pairs than the square would demand.

CVPR'26Attention Surgery: An Efficient Recipe to Linearize Your Video Diffusion Transformer
Problem
In a state-of-the-art video diffusion model, more than three quarters of the compute is spent on self-attention, precisely because comparing every token to every other one scales with the square of a very long video-sized sequence. You could swap in a cheap linear attention that skips the all-pairs comparison, but doing so has historically meant retraining the whole model from scratch or accepting a brutal quality drop.
Approach
Attention Surgery is a cheaper-kernel route that converts an already-trained model instead of rebuilding it. First it teaches each block a hybrid attention that keeps only a uniformly subsampled sprinkle of true softmax tokens as anchors and handles the rest with a linear-time approximation, trained to mimic the original block's output. Then, because some blocks tolerate aggressive linearization better than others, it solves a knapsack-style budget problem to assign each block its own mix of exact-versus-linear attention. Finally a short finetune on a modest video set stitches the global coherence back together. The whole operation runs in under 0.4 thousand GPU hours.
Why it matters
By replacing most of the quadratic all-pairs comparison with a linear approximation, it makes attention roughly six times faster per block and eliminates the out-of-memory crashes that the squared cost caused on longer clips, all while matching the original model's quality score.

CVPR'26Saliency-Driven Token Merging for Vision Transformers
Problem
A Vision Transformer chops an image into a long grid of patch tokens, and since attention compares every patch to every other patch, the cost climbs with the square of how many patches there are. Simply throwing patches away loses spatial detail, and merging them all uniformly blurs away the parts that actually matter.
Approach
This is a fewer-tokens route that decides which tokens to collapse based on how important they are. A learned saliency map scores every patch by how much it contributes to the task, and low-saliency tokens, typically flat background, get merged together into single combined tokens while high-saliency regions are kept intact and untouched. The result is an adaptive reduction: cluttered, informative regions stay finely resolved while boring regions are compressed, so the sequence fed to attention is shorter but keeps its meaningful structure. Because it merges rather than deletes, no region vanishes entirely; it is just represented more coarsely.
Why it matters
Fewer tokens going into attention means fewer of those n-times-n comparisons, so the quadratic cost shrinks toward the informative parts of the image while accuracy holds steady.

CVPR'26HAWK: Head Importance-Aware Visual Token Pruning in Multimodal Models
Problem
When a multimodal language model looks at an image, it turns that image into hundreds of visual tokens, far more than the accompanying text, and since attention cost grows with the square of the total token count, those visual tokens dominate the bill and make the model too slow for real-time use. Prior pruning methods threw tokens away as if every attention head cared about the same things, which is not true.
Approach
HAWK is a fewer-tokens route that prunes visual tokens more intelligently by respecting the differing roles of attention heads. Offline, it runs ablations that switch off each head one at a time and measures the resulting accuracy drop, producing a static importance weight for every head. At run time, it also computes how much each visual token is attended to by the text query, deliberately stripping out positional bias so the score reflects genuine content relevance. It then combines the static head-importance weights with these dynamic text-guided scores, keeps only the top-scoring visual tokens, and discards the rest, all without any additional training.
Why it matters
By deleting up to 80 percent of the visual tokens before they ever reach attention, it directly deflates the squared token count that drives the quadratic cost, cutting end-to-end latency by about a quarter while retaining 96 percent of accuracy.

CVPR'26When Transformers Meet Mamba: A Hybrid Transformer-Mamba Network for Video Object Detection
Problem
Detecting objects across video frames rewards a model that can relate distant moments to each other, which is exactly what attention does well, but relating every frame's tokens to every other frame's tokens scales with the square of the sequence and becomes prohibitive over long clips. Mamba, a state-space model, runs in linear time but on its own is weaker at rich contextual reasoning than a Transformer.
Approach
TMambaDet is a Mamba-successor route that splits the job by strength. Within a single frame, where the token count is manageable, it uses a deformable Transformer that spends its attention only on adaptively chosen sample points to capture spatial structure. Across frames, where the sequence gets long, it hands off to a bidirectional Mamba encoder that streams through time in linear cost instead of comparing all frame pairs. A final decoder entangles the two, letting attention and Mamba cooperate on the multi-scale fusion. Mamba works here because a state-space model carries a running summary through the sequence, which behaves like a low-rank, linear-time approximation of the same content-weighted average that attention computes exhaustively.
Why it matters
By routing the long temporal axis through Mamba's linear scan rather than quadratic attention, it keeps the expensive squared cost confined to the small within-frame problem and reaches state-of-the-art detection at a fraction of the compute.

2 · Re-routing what attention looks at

Plain attention lets every token look at every other token, all at once. That sounds powerful, but it is quietly wasteful and quietly naive: the cost grows with the square of the number of tokens, and it treats a scene as a bag of patches with no built-in sense of where things sit in space, which view a pixel came from, or how a formula reads left to right. The papers here all make the same move from a different angle: instead of letting attention roam freely, they engineer who is allowed to look at whom. Some restrict the lookups along real geometry, so a pixel in one camera only compares itself to the sliver of the other camera where its match could physically be. Some factor a full 2D sweep into a horizontal pass and a vertical pass, or aim each query at just a handful of learned sample points, to cut the quadratic cost while keeping the structure that matters. And running underneath many of them is cross-attention as a universal glue — the primitive that lets one stream of tokens (an image) selectively pull in information from a different stream (a language model, a depth map, a set of register slots), which is how modality, geometry, and structure get fused in the first place.
CVPR'26Vision Transformers Need More Than Registers
Problem
Vision Transformers trained in almost any way develop ugly glitches: a few patch tokens blow up to huge values, and the dense features across the image stop lining up with what is actually there. Register tokens — a handful of extra blank slots added so the model has somewhere to dump global bookkeeping — were supposed to fix this, but they only patch the symptom and not the cause.
Approach
The authors trace the glitch to what they call lazy aggregation: the class token, which is supposed to summarize the whole image, learns a shortcut and leans on empty background patches to carry its global signal, because background is an easy place to stash information without disturbing the foreground. So the fix is not to add more storage slots but to change which patches the summary token is allowed to attend to. Their method, LazyStrike, measures how foreground-like each patch is and then selectively re-weights the aggregation so the class token pulls its global meaning from informative foreground regions instead of coasting on background. Two diagnostics — a Patch Score comparing each patch to the class token, and a Point-in-Box score checking whether attention lands inside objects — let them see and correct the misrouting directly. In effect they re-steer the all-to-one attention that builds the global feature.
Why it matters
It shows the artifacts were never a storage problem but a routing problem — the model was looking at the wrong patches — and steering attention back onto the foreground cleaned up dense features across twelve benchmarks at once.

CVPR'26Ov3R: Open-Vocabulary Semantic 3D Reconstruction from RGB Videos
Problem
Systems that rebuild 3D geometry from a plain RGB video are fast and accurate at shape, but they are semantically blind — they do not know that this surface is a chair and that one is a floor. Meanwhile the methods that do understand open-vocabulary meaning usually need a depth sensor or an offline pipeline, so nothing did both live from ordinary video.
Approach
Ov3R bolts language understanding onto a reconstruction network using cross-attention as the fusion primitive. It runs a segmenter to cut each frame into objects, passes each masked object through CLIP to get language-aligned features, and assembles those into a per-pixel semantic feature map. The reconstruction branch then treats its own image tokens as the queries and the CLIP feature map as the keys and values, so each geometry token reaches across and pulls in exactly the semantic evidence relevant to it — literally the softmax cross-attention of image features against object CLIP features. A second head learns to carry those CLIP semantics into 3D scene space so meaning and shape stay consistent as the map grows. Finally a fusion module blends three feature streams — the reconstruction's CLIP features, DINO features, and a 3D-CLIP point encoder — again through learned cross-attention with weighted merging, and aligns the result to text embeddings so any word can query the scene. All of this runs at fifteen frames per second on a single GPU.
Why it matters
It is a clean example of cross-attention as universal glue: two different token streams, one geometric and one linguistic, are stitched together by letting each geometry token selectively attend to the semantic tokens it needs.

CVPR'26IDESplat: Iterative Depth Probability Estimation for Generalizable 3D Gaussian Splatting
Problem
To turn a few photos into a 3D scene you need to know how far away each pixel is, and the usual trick is to compare a pixel in one image against the other images to guess its depth. Doing that comparison with a single sweep is unreliable — it produces a blurry, low-confidence depth guess that then poisons everything built on top of it.
Approach
IDESplat constrains the comparison with real two-view geometry: a pixel in one camera cannot match just anywhere in the other camera, it can only lie along a single line — the epipolar line — set by the cameras' relative pose. So rather than full all-to-all attention across the whole other image, the method uses epipolar attention, where each pixel only attends to the candidate points strung along its epipolar line, each candidate standing for a different depth. Its Depth Probability Boosting Unit then does this warp-and-attend step several times in a cascade, multiplying together the epipolar attention maps from successive passes so that depths agreed on repeatedly get reinforced and shaky ones fade. Each round narrows the depth search range and raises the feature resolution, progressively sharpening a coarse guess into a confident one. Restricting the lookups to the geometrically valid line is both cheaper and more accurate than searching everywhere.
Why it matters
It is attention re-routed by physics: because a correct match must lie on the epipolar line, forcing attention to look only there beats an unconstrained search — here matching DepthSplat's quality with a tenth of the parameters.

CVPR'26UniMERNet: A Universal Network for Real-World Mathematical Expression Recognition
Problem
Reading a photographed math formula into LaTeX means handling long strings of symbols in printed, screen-grabbed, and handwritten forms. Full self-attention over every pixel pair is both slow and clumsy for these long, highly structured sequences, making it impractical to deploy.
Approach
UniMERNet's key idea is to factorize the expensive 2D attention into two cheap 1D passes that follow how a formula is actually read. Its Raster-Scan Attention first lets every pixel attend along its own horizontal row, then along its own vertical column, instead of attending to all pixels at once. Because a full grid of interactions is replaced by a row pass plus a column pass, the cost drops from quadratic toward linear while still letting any pixel reach any other in two hops — and the reading-order structure of mathematical notation is baked into the routing. The encoder alternates these Raster-Scan layers with ordinary local Window Attention in a Swin-style hierarchy, so local detail and long-range layout both get captured. A standard decoder then uses cross-attention to turn the encoded image into the LaTeX token sequence.
Why it matters
It shows that where full attention is unaffordable, you can factor it along the axes the data already lives on — rows then columns — and get five times faster inference without losing accuracy.

CVPR'26Dr.Occ: Depth- and Region-Guided 3D Occupancy from Surround-View Cameras for Autonomous Driving
Problem
A self-driving car has to reconstruct a dense 3D grid of what is occupied and what each cell is, using only its surround-view cameras. Lifting flat 2D images into that 3D grid keeps going wrong because the depth estimates are coarse, so voxels get their image features from the wrong pixels.
Approach
Dr.Occ steers the 2D-to-3D lookup with deformable cross-attention rather than letting every 3D voxel query attend densely over the whole image. In deformable attention a query does not compare itself to all keys; it predicts a small set of offset positions and samples the image at just those few learned points, so each voxel gathers evidence only from the handful of pixels most likely to belong to it. Dr.Occ first uses an external depth model to build a geometry-aware mask of which voxels are plausibly non-empty, then runs the deformable cross-attention densification only on those geometrically sensible voxels, so attention is aimed by real depth instead of guesswork. A second stage routes computation the same frugal way in 3D: a router scores regions of space and repeatedly applies a single refinement expert to only the top-scoring regions, concentrating capacity where the semantics are hard and imbalanced. Both stages share one principle — spend attention only where geometry says it is worth spending.
Why it matters
It is deformable attention used exactly as intended: aiming each query at a few geometrically justified sample points instead of the full image lifts a strong baseline by over seven points of mIoU while keeping the model lean.

3 · Telling attention where things are

Attention treats a sequence as a set. When it compares one token to another, it only sees their contents, not their order; shuffle the tokens and the raw attention math gives the same answer. That is a problem, because in a sentence, a video, or an image, where something sits is half its meaning. So position is not something attention knows on its own; it has to be added in, injected as a signal riding alongside each token. The most popular way to do this today is RoPE (rotary positional encoding), which rotates each token's query and key vectors by an angle proportional to its position, so that when two tokens are compared, only the gap between them, their relative distance, shows through. The exact recipe you pick for injecting position quietly decides one of the most important properties of a model: whether something trained on short sequences (or small images, or brief clips) still works when you hand it something much longer or larger at test time, the train-short-test-long generalization that every paper below is really chasing.
CVPR'26Infinity-RoPE: Action-Controllable Infinite Video Generation Emerges From Autoregressive Self-Rollout
Problem
A video model that generates frame after frame has a hard ceiling baked into its positional encoding: its 3D-RoPE was trained to count out to about 1024 frames and no further, so it simply cannot address a position past that horizon. Once you ask for a longer clip, the model has no coordinate to place the new frames at, and quality collapses. Retraining a bigger positional scheme is expensive and defeats the goal of reusing a strong short-horizon model.
Approach
Infinity-RoPE keeps the pretrained model but changes how time is counted. Its Block-Relativistic RoPE treats the temporal coordinate as a moving reference frame: instead of numbering frames from an absolute zero that eventually runs off the end, each new block of frames is rotated relative to the base model's maximum horizon, so the model always operates inside the range of positions it was trained on. A second piece, KV Flush, throws away most of the running memory and keeps only a global anchor plus the last frame, which holds memory constant and keeps the model responsive to new action prompts during a long rollout. A third piece, RoPE Cut, deliberately inserts a jump in the time coordinate to produce a clean cinematic cut. Crucially all of this is training-free: it is a reinterpretation of the position signal, not new learned weights.
Why it matters
This is the clearest demonstration that how you inject position, not how big your model is, sets the length limit, and that rewriting position as a relative, moving coordinate is what turns a short-clip model into an effectively infinite one without retraining.

CVPR'26Cross-Scale Pansharpening via ScaleFormer and the PanScale Benchmark
Problem
Pansharpening fuses a sharp grayscale satellite image with a lower-resolution color image to make a sharp color one, but models are trained at one fixed resolution ratio (say 4x) and fall apart when a different satellite hands them a 2x or 8x ratio. Different sensors and missions shoot at wildly different resolutions, so a model locked to its training scale is nearly useless in practice. The catch is that no one had framed why this generalization fails.
Approach
ScaleFormer's key move is to reframe resolution generalization as sequence-length generalization: a lower-resolution image simply becomes a shorter sequence of patches and a higher-resolution one a longer sequence. Its Scale-Aware Patchify turns images at any scale into patch sequences of the matching length, and bucketed training exposes the model to a range of lengths so it learns to cope with variable-length inputs. Separate Spatial and Sequence Transformers process the two kinds of structure, and Cross Transformers fuse the grayscale and color streams. The linchpin is RoPE: because rotary encoding expresses position as a relative rotation, the model can extrapolate to sequence lengths, and therefore resolution ratios, it never saw in training. The paper also ships the PanScale benchmark spanning 0.5m to 15m resolutions.
Why it matters
It shows that a spatial problem (unseen resolutions) and a positional problem (unseen sequence lengths) are the same problem, and that RoPE's relative encoding is precisely what lets a model trained at one scale extrapolate to another it never saw.

CVPR'26Head-wise Adaptive Rotary Positional Encoding for Fine-Grained Image Generation
Problem
Standard multi-dimensional RoPE for images treats each axis independently and rotates every attention head the same way, so it cannot capture that horizontal and vertical structure carry different frequency content, and it blocks the cross-axis interactions needed for precise spatial relations. This dull, one-size-fits-all position signal shows up as generated images that miscount objects, misplace parts, and drift on color. Fine-grained image generation needs a position code that different heads can specialize.
Approach
HARoPE inserts a small learnable transformation before the rotary step, parameterized through an SVD (a clean decomposition of a matrix), so the rotation basis itself can adapt to the data rather than being fixed by hand. This lets rotary planes align with meaningful directions, mixes information across axes instead of keeping them independent, and, critically, gives each attention head its own transformation so heads can develop specialized positional receptive fields. The transformation is applied symmetrically to both queries and keys, which is what preserves RoPE's core guarantee that only the relative offset between two tokens matters. It is a lightweight change that drops into existing generators like Flux and SD3.
Why it matters
It shows that injecting position is not a solved, static step: making the relative-position signal learnable and per-head, while carefully preserving relativity, is what buys precise spatial control, correct counts, and faithful color.

CVPR'26SoPE: Spherical Coordinate-Based Positional Embedding for Enhancing Spatial Perception of 3D Large Vision Language Models
Problem
A 3D vision-language model has to reason about where things sit in a real scene, but the positional embeddings it inherits were built for flat grids or 1D text and do not naturally express 3D spatial relationships. As a result these models have a weak sense of direction and distance, which hurts exactly the tasks (embodied AI, robotics) that need good spatial grounding.
Approach
SoPE injects position using spherical coordinates, encoding a point by its direction and distance (angles and radius) rather than by flat x, y grid indices. This matches how spatial relations actually work in a 3D scene, where which way and how far are the natural quantities, so the position signal the attention layers receive is aligned with the geometry of the world rather than fighting it. Feeding this geometry-aware coordinate into the model's positional embedding gives its attention a more faithful sense of where each element lies. The result is stronger 3D spatial perception and reasoning in the vision-language model.
Why it matters
It makes the point that the shape of the position code should match the space you are working in: choosing spherical coordinates for a 3D world, instead of a flat grid, is what lets attention perceive direction and distance correctly.

4 · Reading attention, and choosing tokens

Attention is not just how a model computes — it is a record of where the model looked. For every word it produces, the model spreads a fixed budget of attention across the image, and that spread is legible: pile it onto one small region and the word is grounded in something really there; smear it thinly across the whole picture and the model is guessing from language habit rather than pixels — the fingerprint of a hallucination. Because that trace is readable, 2026 work uses it two ways: to explain which internal parts drive a decision, and to catch the model when it makes things up. But before any attention can run, there is an earlier and quieter design choice — how the picture becomes tokens in the first place. For years the default was to chop every image into a fixed grid of 16x16 pixel patches and call each square a token, regardless of what it contained. This year that default is being questioned: the token grid is itself a modeling decision, and choosing tokens that follow objects and meaning — rather than a blind grid — changes what attention even has to work with.
CVPR'26Beyond the Global Scores: Fine-Grained Token Grounding as a Robust Detector of LVLM Hallucinations
Problem
Vision-language models routinely describe objects and attributes that are not in the image — hallucinations that are dangerous in settings like healthcare or robotics. The usual way to catch this is a single global score of how well the whole caption matches the whole image, but that coarse average misses hallucinations whose evidence is weak and scattered rather than absent.
Approach
The authors stop looking at the image as a whole and instead inspect, patch by patch and layer by layer, how each generated word attends to the picture. They find two tell-tale signatures of a made-up word: its attention is diffuse and non-localized, spread thinly across many patches, and it has no real semantic match to any particular region. They turn these into two measurable numbers — an Attention Dispersion Score for how spread-out the attention is, and a Cross-modal Grounding Consistency score for whether the word actually aligns with visual content — combined with signals like attention entropy. A faithful word concentrates its attention compactly on the thing it names; a hallucinated word does not. The result is a lightweight, interpretable detector reaching up to 90% token-level accuracy.
Why it matters
This is attention used directly as a lie detector: because the attention map is a readable trace of where a word looked, concentrated equals grounded and dispersed equals hallucinating. It also locates the cause — the model leaning on language priors instead of the visual encoder — rather than just scoring the symptom.

CVPR'26CIGMA: Causal Information-Gain Mechanistic Attribution of Attention Heads in Vision Transformers
Problem
Vision Transformers often win by cheating — latching onto background texture that happens to correlate with the label instead of the object itself. Existing fixes prune parts of the network but cannot say which parts caused the shortcut or prove that removing them was the right call.
Approach
CIGMA treats each attention head as a suspect and asks, causally, how much it relies on the object versus the surrounding context. CVPR'26AToken: A Unified Tokenizer for Vision
Problem
Language models thrive because a single tokenizer turns any text into a shared stream of tokens, but vision has no such thing — separate tokenizers exist for images, for video, for 3D, and each is tuned either for faithful reconstruction or for semantic understanding, never both. This fragmentation means the token layer, the very foundation attention operates on, differs for every kind of visual data.
Approach
AToken proposes one tokenizer for all of them by placing images, video, and 3D into a shared 4D latent space with rotary position embeddings: an image is a flat 2D slice, video extends along the time axis, and 3D fills a spatial-depth axis. Crucially it trains without a GAN, replacing adversarial instability with a Gram-matrix loss that captures the second-order texture statistics reconstruction needs. A four-stage curriculum grows the tokenizer from images to video to 3D, each stage building on the last. The single tokenizer stays competitive across all three modalities at once.
Why it matters

5 · Fusing senses and reading other agents

A robot never sees the world through one clean picture. It sees through a camera that gives dense color, a LiDAR that gives sparse but exact geometry, a fingertip that feels contact, a microphone, a language instruction, a force sensor on its wrist. Each of these lives in its own frame of reference, its own units, its own kind of noise, and the whole trick is deciding which pixel corresponds to which laser point, which touch matches which glimpse. Cross-attention is the natural operator for this: it lets one stream of information reach across and ask which parts of that other stream are relevant to me right now, aligning and merging things that a naive stack of layers could never line up. And a robot's world is not just objects but other decision-makers — cars, pedestrians, other robots — whose futures are tangled together, so the machine has to reason over a whole set of agents and figure out who actually matters. Attention over that set is the second gift: because it treats the agents as an unordered collection and weighs them by content rather than position, it is permutation-invariant and scales to however many neighbors show up. A static image needs neither of these — one frame, no other minds. Robotics needs both, and both are the same lookup wearing a different hat.
ROBOTICS'25RoBiFusion: A Robust and Bidirectional Interaction Camera-LiDAR 3D Object Detection Framework
Problem
To detect objects in 3D, a self-driving car wants to combine its camera (rich color, no depth) with its LiDAR (exact geometry, but sparse). Most systems only merge the two very late, after each has been crushed into a shared bird's-eye map, throwing away the fine early details. Merging them early instead is tempting, but the camera and LiDAR are never perfectly calibrated, so a naive early merge just smears noise from one sensor onto the other.
Approach
RoBiFusion makes the fusion bidirectional and runs it at both shallow and deep levels. Its core is a cross-attention Camera-LiDAR Feature Matching module: instead of trusting the fixed calibration to say which pixel goes with which laser point, it lets features from one sensor query the other and dynamically match themselves to the most relevant partners. In the LiDAR-to-camera direction it adds a depth representation that mutes LiDAR noise; in the camera-to-LiDAR direction it uses deformable attention with differentiable grid sampling to pull the right image features onto the point cloud. Because the matching is learned by content rather than nailed to a calibration matrix, small calibration errors stop poisoning the merge. The result beats the strong BEVFusion baseline by 1.5% mAP on nuScenes.

ROBOTICS'25Curb Your Attention: Causal Attention Gating for Robust Trajectory Prediction in Autonomous Driving
Problem

Approach

6 · The transformer as the policy

At its core, controlling a robot is a sequence problem: given the history of what the robot has seen and done, decide the next action. If you chop that history into tokens — an image here, a joint reading there, the last action taken — then choosing the next action becomes exactly the same operation a language model performs when it predicts the next word. That single move imports the whole toolkit of long-horizon sequence modeling into robotics, including the trick of return-conditioning: paste a desired outcome onto the front of the sequence and let the model roll out actions that reach it. The Transformer, in other words, stops being a perception module and becomes the policy itself — the GPT recipe pointed at control. But a robot is not a chatbot; it runs on-board at a fixed control rate, and attention’s quadratic cost in sequence length bites hardest exactly where the compute budget is tightest. So this theme has two faces: the papers that reframe control as autoregression, and the papers that swap attention for linear-time state-space successors like Mamba to make it run in real time.
ROBOTICS'25ICRT: In-Context Imitation Learning via Next-Token Prediction
Problem
A robot policy trained on a fixed set of tasks usually has to be retrained to handle anything new. The goal here is generalization to novel tasks at test time using only a handful of demonstration examples as context — and crucially, with no extra training.
Approach
ICRT is a causal Transformer that treats the robot’s sensorimotor trajectory as a token stream — camera images, proprioception, and actions all interleaved — and does plain autoregressive next-token prediction over it. Because it is a single next-token model, you can hand it a few demonstration trajectories as a prompt and it simply continues the sequence, inferring the intended task from that context the way a language model continues text from an example. This is the GPT recipe applied literally to sensorimotor data: the same causal architecture, the same next-token objective, only the tokens are pixels and joint angles and gripper commands instead of words. Task specification collapses into prompting, so adapting to a new task means writing a new context, not running a new gradient step.
Why it matters
This is the clearest statement of the theme: when you tokenize a robot’s experience and predict the next token, in-context learning — the emergent superpower of large language models — comes along for free, and the paper reports it beats state-of-the-art robot foundation models on unseen tasks without any additional training.

Top to bottom, the themes circle one primitive: first the fight to make attention cheap enough to use (the quadratic wall), then steering what it looks at, telling it where things are, and reading it back out — and finally the cross-over where the same lookup fuses a robot's senses, reasons about other agents, and becomes the control policy itself.
