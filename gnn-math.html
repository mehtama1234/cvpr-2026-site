Graph neural networks — why it works, mathematically

A node's meaning lives in its neighbourhood, not in its own features — but the very operation that reads the neighbourhood destroys it if you repeat it too many times.

The problem, as a quantity

A flat vector of node features is the wrong object. In relational data — molecular bonds, scene graphs, citation networks — the signal is not what a node is but who it connects to: two nodes with identical features can belong to opposite classes if their neighbours differ. So the function you need must take a graph as input and be indifferent to how the nodes happen to be numbered. That second requirement is a hard constraint on the function class: only permutation-equivariant functions are admissible. And once you commit to a permutation-equivariant design — neighbour-averaging — you inherit a mathematical trap: averaging is a low-pass filter, and running it repeatedly drives every node's representation toward the same vector. The obstacle is therefore a tension between two quantities: depth (more rounds = wider receptive field) and distinguishability (more rounds = less contrast between nodes). There is no free lunch.

The core ideas — and why they work

Message passing as normalised-adjacency propagation

H' = σ(Â·H·W), Â = D^{-1/2}·(A+I)·D^{-1/2}, one step of graph diffusion
The operation Â·H replaces every node's feature vector with a weighted average of its own features and its neighbours' features, where the weights are set by the normalised adjacency Â. Adding the identity (self-loop) before normalising keeps each node's own signal in the mix. The weight matrix W then projects this blended vector into a new space, and the nonlinearity σ lets the model compose these steps nonlinearly across layers. Why this exact form? Because Â is symmetric and doubly stochastic: its eigenvalues all lie in [−1,+1], so the propagation is numerically stable, and the averaging it encodes is exactly the symmetric-normalised diffusion operator from spectral graph theory. The learnable part is only W — the graph structure enters purely through Â. Same primitive elsewhere: this is the Propagation-as-smoothing primitive — the identical move that attention applies when it softmax-weights over values, and that iterative slot assignment uses to aggregate scene patches. A little smoothing is helpful; too much collapses distinctions everywhere.

Over-smoothing — the diffusion limit kills distinguishability

Â^L → v₁·v₁ᵀ as L→∞, node-pair cosine-similarity → 1, classification accuracy → chance
Multiplying H by Â repeatedly is exactly running the heat equation on the graph — features diffuse from node to node just as temperature equalises across a conductor. The eigenvectors of Â are the graph's 'frequencies': the top eigenvector v₁ (eigenvalue +1) is a smooth, nearly-constant signal over the whole graph; high-frequency eigenvectors (eigenvalues near −1) encode sharp node-to-node contrasts. Each multiplication by Â preserves low-frequency components and damps high-frequency ones. After L rounds, Â^L·H → v₁·(v₁ᵀ·H): every node's representation collapses to the same projection onto the top eigenvector. Cosine similarity between any two nodes approaches 1 and the features that distinguish them have been erased. This is not a training failure — it is a structural consequence of repeated low-pass filtering. The graph Laplacian L̂ = I − Â makes it precise: its eigenspectrum tells you exactly how fast each 'frequency mode' decays per round. The enemy it defeats — and then becomes: over-smoothing is the degeneracy trap for GNNs, the same collapse that self-supervised learning fights with contrastive losses, VQ codebooks fight with commitment terms, and MoE routing fights with load-balancing penalties. Here the trivial minimiser is 'all nodes map to the same vector', and the only defence is limiting depth to 2–4 layers.

Permutation-equivariance — symmetry as the function-class constraint

f(P·H, P·A·Pᵀ) = P·f(H, A) for any permutation matrix P
A graph has no canonical ordering of its nodes — the same molecule is the same molecule regardless of which atom you call node 1. So any valid function on graphs must satisfy the equivariance condition above: permute the input nodes, and the output permutes the same way. Neighbour-averaging enforces this automatically: a sum or average over a set is the same regardless of the order you encounter the set's elements. This is why the aggregation in message passing must be a symmetric function (sum, mean, max) — not a concatenation, which would be order-dependent. The constraint is not cosmetic. It cuts the function class from 'all functions of node-index pairs' down to 'functions of multisets of neighbour features', which is a far tighter and more generalisable class. The theory of Weisfeiler-Leman graph isomorphism then gives a hard ceiling: two graphs that 1-WL cannot distinguish will produce the same GNN output no matter how deep the network — the symmetry requirement bounds what is computable, not just what is practical. Same primitive elsewhere: this is the Symmetry-as-a-constraint primitive shared with equivariant networks (SE(3)-equivariance in 3D point-cloud models) and with attention itself, which is permutation-equivariant over the sequence it attends to.

Structure beats features — signal lives in edges, not nodes

I(Y; A) ≫ I(Y; X_node) when community / class membership is encoded in connectivity
The empirical fact is sharp: on a graph where node features are pure noise and class membership is encoded entirely in the edge structure (4 communities, dense intra-community links, sparse inter-community), a plain MLP on node features scores 19% (chance is 25%) while a 2-layer GNN scores 96%. The mutual information between labels Y and the adjacency A far exceeds the mutual information between labels and node features X. Why does this happen in real data? Because graphs often model systems where an entity is defined by its role in a structure — a protein binding site by the atoms it bridges, a paper's field by who cites it, a robot object by what it is spatially next to. The features recorded at each node are proxies; the graph topology is the ground truth. A GNN that propagates along edges therefore accesses fundamentally different information than a model that treats nodes independently, even with identical node features. The catch is that this advantage is structural, not depth-unlimited: once 2–3 hops of neighbourhood are captured, adding more layers does not add new information — it only adds smoothing noise that destroys what was already extracted.

The approaches, as variations on the math

Every GNN design is a choice along three axes, each trading off against the others. Axis 1 — what to aggregate: GCN sums with Â-normalisation; GraphSAGE samples a fixed-size neighbourhood and concatenates; GAT replaces the fixed Â weights with learned attention coefficients αᵤᵥ = softmax(aᵀ[Wh_u ‖ Wh_v]), so each edge's weight is input-dependent. Attention lets the model suppress noisy neighbours, but it does not escape over-smoothing — it only changes which neighbours dominate the blur. Axis 2 — how deep to go: the over-smoothing analysis says 2–4 layers covers most useful receptive fields; residual connections (add the layer-0 features back at every layer) slow the decay of high-frequency signals and allow slightly deeper nets. Axis 3 — what the graph represents: for molecules, nodes are atoms and edges are bonds — the graph is given by physics. For scenes, nodes are detected objects and edges are inferred spatial relations — the graph is itself a learned or heuristic construction. For robots in multi-agent settings, nodes are agents and edges are communication links — the graph is a design decision. The choice of graph topology is as important as the GNN architecture sitting on top of it.

1Building the graph: scene graph generation
P(edges) = Π_f φ_f(x_nodes, x_edges) // factor graph constrains candidate functional relations via proximity + semantic factors, converting detection into structured joint inference.
Scene graphs must infer which edges exist before message-passing works. Factor graphs encode hard constraints (two objects must be close to support an edge) and soft priors (semantics favor certain relations), turning the graph construction itself into a learnable probabilistic model. Shallow reasoning over a well-built graph beats deep reasoning over noise.

2Reasoning over relations: relational graphs for recognition and pose
H'_part = Aggregate_{neighbors} σ(Θ · concat(h_self, h_neighbor, spatial_encoding)) // node features fused with part-level relational embeddings, leveraging spatial layout as inductive bias.
Objects and their parts form natural hierarchies; encoding spatial offsets directly in node embeddings (e.g., part position relative to parent) lets shallow GNNs reason about configuration without learning deep averaging. Attention over part relations replaces long-range diffusion with explicit geometry.

3Native graphs: GNNs for structured domains

Over-smoothing arises when every node receives equal weight from all neighbors. Content-adaptive neighborhood selection (choosing sparser neighbors for smooth regions, denser for complex ones) lets deep GNNs preserve boundary structure. The graph itself becomes a learned skip connection.

4Relational grounding: graphs across video, HOI, and open-vocabulary
H'_obj, H'_rel = MoE(h_obj, h_rel | routing_weight = softmax(Semantic_Score(object, relation))) // expert layers conditionally route object/relation features based on semantic relevance.
Object and relation features have conflicting gradients in multi-task settings (e.g., detecting a ball and the kick relation). Mixture-of-Experts routing decouples them, letting each expert specialize to one modality. Message-passing then operates on cleaner, task-focused embeddings without averaging noise.

5The robot scene graph: relational maps a robot builds and plans over
S'_t = Π_g φ_g(S_t, π_t) // graph encodes objects as nodes, spatial relations as edges, updated by interacting with the scene (physics feedback → edge weights change, new nodes appear).
Robots must maintain and update scene graphs as they move. Each interaction provides ground-truth feedback (grasp succeeded, object moved). Reweighting edges after action feedback turns the graph into a lived model of the world, not a static detector. Message-passing over this evolving structure predicts how actions propagate.

6Graphs as the robot's structure: morphology, multi-agent, and prediction
H'_joint = σ(W · Aggregate_{k ∈ kinematic_chain(i)} h_k + Position(i)) // encode limb/joint structure as graph edges matching the robot's morphology, bypassing learned feature averaging.
A robot's body is a physical graph (limbs are nodes, joints are directed edges). Encoding this hard constraint directly (joint i aggregates only from its parent and children) gives GNNs the right inductive bias for control. Message-passing through the morphology graph naturally learns locomotion without depth, since depth would mean aggregating across the entire body repeatedly.

Coordinated Multi-Robot Navigation with Formation Adaptation — Hierarchical GNN at group level decides formation shape; robots are nodes, formation edges encode desired distances.
The through-line. Graph neural networks are the answer to a single, clean question: how do you learn on data whose meaning lives in connections rather than things? The answer — let every node average its neighbours' features and repeat — turns out to be exactly one step of graph diffusion, and the normalised adjacency Â is the diffusion operator. That elegance comes with an equally clean limit: diffusion is a low-pass filter, and running it too many times drives all node features toward the graph's top eigenvector, erasing every distinction the task depends on. So the art of GNNs is not making them deeper — it is choosing a depth that captures the right neighbourhood radius before the smoothing swamps the signal. The three recurring primitives underneath are propagation as smoothing (the same move as attention, slot-assignment, and iterative message passing), the degeneracy trap (the same collapse as SSL and codebook training, just wearing different clothes), and symmetry as a constraint on the function class (the same idea that forces equivariant 3D networks and attention to respect their input's symmetry group). GNNs make all three vivid in a single operation.
