1 · Fixing CLIP's blind spots

CLIP is excellent at answering is there a dog in this picture? — but ask it whether the cube is on top of the sphere, how many birds there are, or which object is red, and it starts to guess. The reason is baked into how it learns. CLIP only ever pulls a whole image toward its whole caption in a shared space, so it soaks up the general gist of a scene while quietly ignoring which word goes with which thing. Worse, it learns from raw web data where a few common objects appear millions of times and rare or fine-grained ones barely show up, so the loss is happy the moment it spots the obvious. The four papers in this cluster all repair the training itself rather than bolting on a fix afterward: one rebalances the data so rare concepts actually get seen, one aligns groups of image regions to the grammar of the caption, one teaches the model to bind attributes to objects using noun phrases instead of brittle trick negatives, and one cures a lazy habit of only reading the first sentence. The shared payoff is a CLIP that can truly bind a red cube on a blue sphere, count, and notice fine detail — not just confidently announce that there is a dog.
CVPR'26Concept-Aware Batch Sampling Improves Language-Image Pretraining
Problem
The giant web datasets CLIP learns from are wildly lopsided: a handful of common objects flood almost every batch, while rare and specialized concepts barely appear, so the model never gets enough practice on the long tail. Existing fixes curate the data once, up front, throwing away examples and locking in a single choice that cannot adapt to what you actually want the model to do.
Approach
The authors first build DataConcept, a 128-million image-text set where every image is richly annotated — tagged with concepts, given bounding boxes around the objects, and rewritten with concept-aware captions. Then, instead of curating once, they curate on the fly during training: for each oversized draft batch, a scoring function picks which examples to keep. One mode, diversity maximization, deliberately favors images containing under-represented, long-tail concepts so rare things finally get airtime, which helps recognition. A second mode, frequency maximization, favors busy multi-object scenes, which helps retrieval. Crucially nothing is discarded — the same data can be sampled either way depending on the goal.
Why it matters
By actively feeding the model the concepts it would otherwise starve for, this lifts zero-shot recognition (+5% on ImageNet) and retrieval (+9%), directly widening CLIP's blind spot for rare and fine-grained categories.
CVPR'26PowerCLIP: Powerset Alignment for Contrastive Pre-Training
Problem
Standard alignment either matches the whole image to the whole caption or matches one region to one phrase, but real scenes are compositional — meaning lives in combinations of things, like a person and the bench they sit on. Single-region objectives can never capture that a group of regions together corresponds to a phrase built from several words.
Approach
PowerCLIP aligns subsets of image regions to the structure of the sentence. It draws on the caption's parse tree — the grammar that says which words group into phrases — and tries to match every possible combination of image regions against those phrase structures. The catch is that the number of region combinations explodes exponentially, so training on all of them naively is impossible. The authors introduce Non-Linear Aggregators, a clever summarizing trick that provably approximates the full all-combinations loss but costs only linear time in the number of regions. This lets the model learn how parts of an image compose into meaning the same way words compose into phrases.
Why it matters
Teaching CLIP to align region groups to phrase structure is exactly what compositional understanding needs, and it pays off broadly — state-of-the-art on 22 of 28 benchmarks spanning classification, retrieval, robustness, and compositionality.
CVPR'26No Hard Negatives Required: Concept Centric Learning Leads to Compositionality without Degrading Zero-shot Capabilities of Contrastive Models
Problem
CLIP struggles to bind attributes to the right object — it can tell a red thing and a blue thing are present without knowing which is which. The popular fix, training on tricky wrong captions (hard negatives), does improve this binding but quietly wrecks the model's general zero-shot and retrieval skills, so it is not a free lunch.
Approach
The authors trace the failure to two root causes: long captions let the model succeed without ever reasoning about composition, and CLIP's final pooling step blurs everything together, erasing which word belongs to which object. Their fix skips hard negatives entirely. They use basic language tools to pull out short noun phrases — small chunks like red cube — and align each one to the image. A parameter-free cross-modal attention-pooling step then builds concept-centric image features that keep binding information intact, supervised by extra contrastive losses. In effect the model is taught to attach each descriptive phrase to the right visual thing, directly.
Why it matters
This delivers state-of-the-art compositionality — proper attribute binding and relation understanding — while preserving zero-shot and retrieval quality and adding no inference cost, breaking the usual trade-off.
CVPR'26CLIP Is Shortsighted: Paying Attention Beyond the First Sentence
Problem
When CLIP is fine-tuned on long, detailed captions, it develops a lazy shortcut: it leans almost entirely on the opening summary sentence and early words, ignoring the rich detail buried later in the text. Move that information deeper into the caption and retrieval accuracy collapses, showing the model never really learned to read past the start.
Approach
The cause is structural. Long-caption datasets tend to follow the same shape — a summary sentence, then detailed description — so the model minimizes its loss by only reading the summary, without ever growing a real long-context attention span. DeBias-CLIP attacks the habit with three simple caption tweaks and no new parameters: delete the opening summary sentence, randomly shuffle and subsample the remaining sentences so no fixed order can be memorized, and pad the front with filler so important content is pushed to later positions the model normally neglects. Training on both the full and the shuffled-padded captions forces attention across the entire text.
Why it matters
Curing the first-sentence bias yields state-of-the-art long-text retrieval and robustness to sentence reordering, so CLIP finally uses fine-grained detail wherever it appears rather than skimming the headline.

2 · Naming every pixel

CLIP was trained to give one score for a whole image against a whole caption — is this picture a dog, or a cat? But detection and segmentation need something finer: a score for every box and a score for every pixel. This gap is the biggest and most crowded pattern in the 2026 CLIP literature, because everyone wants CLIP's magic power — naming things it was never trained to name — but delivered at the level of regions and pixels instead of whole images. The dominant moves are three. First, re-wire CLIP's own attention so its internal features stop describing the whole image and start describing local patches, then add region- or pixel-alignment heads on top. Second, fuse CLIP's semantics with the spatial precision of models like DINO or SAM, letting one supply the names and the other supply the crisp boundaries. Third — and this is what makes the theme striking — much of this is training-free: you re-arrange what a frozen CLIP already computes and get open-vocabulary masks and boxes for categories the model has never seen, with no extra training at all.

CVPR'26Reconstructing CLIP for Open-Vocabulary Dense Perception
Problem

CLIP learned to classify a whole image at once, so when you try to reuse it for segmentation or detection its features come out coarse and blurry — the spatial detail has been squeezed out. The result is low-resolution, mushy predictions that cannot tell you cleanly which pixel belongs to which thing.

Approach

Rather than bolt a small fix onto CLIP, this work rebuilds its feature pathway for dense output. It extracts features at multiple scales and pools them across a spatial pyramid so both large regions and fine detail survive. A feature-pyramid network keeps high-resolution maps alive all the way through instead of letting them collapse to a single global vector. Crucially, the text embeddings are projected to match the spatial resolution of the image features, so a class name can be compared against every location on the map — giving a real per-pixel alignment instead of one image-level score.

Why it matters

It turns CLIP's whole-image naming power into dense, per-pixel open-vocabulary labeling, so you can segment and detect categories the model was never explicitly trained on while keeping crisp spatial detail.

CVPR'26WeDetect: Fast Open-Vocabulary Object Detection as Retrieval
Problem

Many open-vocabulary detectors are accurate but slow, because they re-mix the text query with the image inside the network on every single inference — you pay that cost again for each new prompt. Faster retrieval-style alternatives that keep the two apart have historically given up accuracy to get the speed.

Approach

WeDetect treats detection as retrieval with two separate towers: a ConvNeXt image backbone with a multi-scale neck on one side, and an XLM-RoBERTa text encoder on the other, with no cross-attention between them. Region proposals are matched to text embeddings by a simple dot-product similarity, so text can be encoded once and reused. To keep accuracy without fusion, it adds a learnable objectness prompt that models category-agnostic box quality, trained on a massive 15M-image, 330M-box set with multi-granularity label sampling so it does not overfit to coarse or fine labels. For referring queries it attaches a lightweight Qwen3-VL binary head that simply accepts or rejects a box for a given phrase — grounding without dragging heavy fusion back into the detector.

Why it matters

It delivers real-time open-vocabulary box labeling — naming and localizing arbitrary categories at up to 62.5 FPS — making name-anything detection cheap enough for deployment.

CVPR'26PEARL: Geometry Aligns Semantics for Training-Free Open-Vocabulary Semantic Segmentation
Problem

Because CLIP was trained for global image-text agreement, its patch features are geometrically misaligned for dense work: a few background-dominated directions near the top of the encoder hijack how patches attend to each other, so per-pixel similarities come out spatially inconsistent. Existing training-free segmenters either lean on heavy post-processing or treat text and vision separately, leaving this geometry problem unfixed.

Approach

PEARL fixes the geometry at its source, with no training. In the last self-attention block it inserts an orthogonal Procrustes alignment that rotates the keys toward the query subspace, correcting the background-biased drift so patches interact cleanly. It then runs a text-aware Laplacian propagation: per-pixel logits are refined by a graph solve in which the text itself gates which neighbors talk to each other based on semantic relatedness, while image gradients keep object boundaries sharp. In effect, text stops being a mere labeler and becomes a structural prior that steers how evidence spreads across the image. The whole thing is compact — no auxiliary backbones, no extra data.

Why it matters

By treating correct token geometry as a prior, it produces training-free open-vocabulary pixel masks that suppress background spill and preserve thin structures for categories never seen at training time.

CVPR'26SRA-Det: Learning Omni-Grained Open-Vocabulary Detection Beyond Category Names
Problem

Open-vocabulary detectors mostly work at the level of category names, so they stumble on fine-grained queries where objects differ by just an attribute or two — a dog with gray and white fur, or a metal knife with a black plastic handle. The strong category signal drowns out the attribute cues, and collapsing the whole phrase into one text vector loses the individual details.

Approach

SRA-Det stops treating the query as one blob and decomposes it into multiple semantic facets. A Semantic Retrieval Augmentation module uses learnable queries to attend over the token-level text features and pull out several distinct facets — roughly one per attribute. Then a Multi-Semantic Matching step scores each candidate object against every facet and combines the scores with a soft-min operator that acts like a differentiable logical AND: a box only wins if it satisfies all the required attributes, not just the loudest one. To train it, an automatic pipeline has an LLM generate category-specific attributes and a dual CLIP-based check verifies those attributes at the instance level, yielding attribute-rich supervision at scale.

Why it matters

It pushes open-vocabulary box labeling beyond names to attribute-precise descriptions, so you can detect exactly the object a compound phrase asks for — +13.8 mAP over OWL-ViT on the fine-grained FG-OVD benchmark.

3 · Freeze it and adapt

CLIP has already soaked up a huge amount of the visual and language world during pre-training, so retraining it from scratch for a new job would be wasteful and expensive. The cheap play is to leave the whole model frozen and bolt on something small: a tiny adapter that reshapes its text features, or a handful of learned prompt tokens that steer it toward a task. This kind of prompt learning and adapter tuning specializes a frozen CLIP for one dataset or a few-shot setting while touching almost none of its weights. Other methods go even further and use the model with no target-side training at all, either engineering the text prompts by hand or adapting the prompt on the fly for each incoming image at test time. A recurring aim across all of these is squeezing more reliable zero-shot behavior out of a frozen model, so its confidence is well-calibrated and not just high. That same reliability goal extends to catching out-of-distribution inputs the model was never meant to classify, so it can say I do not know this instead of guessing.
CVPR'26ReBaPL: Repulsive Bayesian Prompt Learning
Problem
Learning prompt tokens for a frozen CLIP tends to overfit and generalize poorly to new distributions. The usual training finds a single best set of prompt tokens, but that one point estimate ignores the fact that many different prompts work well. Committing to just one throws away that diversity and hurts out-of-distribution accuracy.
Approach
ReBaPL treats prompt learning as sampling a whole distribution of good prompts rather than hunting for one winner. It keeps K particles, each a different prompt configuration, and runs cyclical rounds that alternate between exploring aggressively and then carefully sampling with injected noise. The key ingredient is a repulsive force that pushes the particles apart so they land on genuinely different solutions instead of collapsing onto the same one. Crucially, the repulsion is measured not in raw weight space but on the distributions of the features the prompts produce, compared with metrics like Maximum Mean Discrepancy or Wasserstein distance, which sidesteps the fact that identical prompts can look different numerically. It bolts onto existing prompt-learning methods like MaPLe and MMRL as a plug-and-play upgrade, and at inference it simply averages the predictions of all the saved samples.
Why it matters
By keeping a diverse ensemble of prompts instead of one overfit guess, it retains CLIP's broad open-vocabulary knowledge while still specializing cheaply, improving base-to-novel, cross-dataset, and domain-generalization results (for example MMRL+ReBaPL reaches a best-in-class 67.62% cross-dataset average). It is a lightweight way to make a frozen model both more accurate and more honest about its own uncertainty.
CVPR'26Beyond Graph Model: Reliable VLM Fine-Tuning via Random Graph Adapter
Problem
The cheapest way to adapt CLIP is a small text-side adapter, but the usual adapters are deterministic: they pin each class to a single fixed text feature. That single feature cannot capture how many different ways a category can be described, and it ignores how classes relate to one another.
Approach
VRGAdapter replaces the fixed per-class feature with a probability distribution over descriptions, so each class is a Gaussian blob seeded from many diverse text descriptions written by a language model. It then arranges the classes as nodes in a random knowledge graph and lets them pass messages to each other, so a class's representation is shaped by its neighbors and the relationships between categories are baked in. Learnable sampling from these distributions produces the final adapted text features, and an old-style deterministic adapter is just the special case where diversity collapses to one. An uncertainty-guided fusion scheme then combines predictions from several backbones for a more robust ensemble. All of this trains only the small adapter while CLIP stays frozen.
Why it matters
Modeling both the spread of descriptions within a class and the ties between classes lets a tiny adapter specialize CLIP more faithfully without disturbing its pre-trained knowledge. The result is more reliable few-shot adaptation that beats both deterministic and earlier graph-based adapters.
CVPR'26SoC: Semantic Orthogonal Calibration for Test-Time Prompt Tuning
Problem
Test-time prompt tuning adapts a frozen CLIP to each individual test image by nudging its prompt tokens, with no training data at all. A prior method, O-TPT, forces the class embeddings to be strictly perpendicular to spread them out, but that hard constraint over-inflates the model's confidence and wrecks its calibration, so its probabilities can no longer be trusted.
Approach
SoC adds a gentler soft-orthogonality regularizer on top of the standard test-time objective. Instead of demanding exact perpendicularity, it measures the cosine similarity between every pair of class prompt embeddings and uses a Huber loss to pull each pair toward a mild negative target, penalizing both being too aligned and being too orthogonal. The paper proves mathematically (Proposition 1 and Corollary 1) that the hard-orthogonality constraint raises the per-class confidence floor more aggressively than this Huber version, which is exactly why the older method miscalibrates. Because it only reshapes how classes sit relative to each other, it slots into existing test-time tuning with no extra data. It is evaluated on 11 classification datasets and 4 ImageNet shift variants with a ViT-L/14 backbone.
Why it matters
It squeezes more reliable zero-shot behavior out of a frozen model, improving both accuracy and calibration at once (mean ECE 5.4 vs 7.7 for O-TPT, accuracy 72.3 vs 71.4). Trustworthy confidence, not just correct labels, is what makes a frozen backbone usable in the wild.
CVPR'26Activation Matters: Test-time Activated Negative Labels for OOD Detection with Vision-Language Models
Problem
To flag inputs that do not belong to any known class, a popular trick gives CLIP a set of negative labels that are far from the in-distribution classes and checks whether an image matches those instead. The trouble is that many of these distant labels barely respond to actual out-of-distribution images, so they carry little signal and can even mislead the detector.
Approach
TANL introduces an activation metric that measures how strongly each candidate label lights up across the data, using the average classification probability it receives. At test time it watches confidently-positive and confidently-negative images and dynamically keeps the negative labels that actually activate on the incoming distribution, discarding the dead ones. It offers a distribution-adaptive variant that adjusts to the whole test set and a batch-adaptive variant that adjusts per batch, so the label set stays aligned with what the model is currently seeing. A new activation-aware scoring function then leans on the strongly-activated negatives when deciding if an image is out-of-distribution. The whole thing requires no training and runs efficiently, with theoretical backing.
Why it matters
It squeezes far more reliable out-of-distribution detection from a completely frozen, training-free CLIP by picking negative labels that truly respond rather than ones that merely sit far away (FPR95 drops from 25.4% to 9.8% on ImageNet using fewer labels). Reliably knowing what it does not know is a core part of trusting a zero-shot model.

4 · Fixing the geometry, reaching new worlds

Even for categories CLIP already knows, its geometry is subtly off: the picture of a dog and the words a dog do not land on top of each other. Instead the images pile into one cluster and the words pile into another, with an empty gap between them — the so-called modality gap — and this same off-ness means that using CLIP to find one photo from another photo works worse than you would hope. One line of work stares hard at this geometry and tries to repair it, asking whether the two clusters can be nudged into honest agreement. A second line takes CLIP's real superpower — naming things it was never explicitly trained on — and carries it out of the world of web photos into places CLIP stumbles: raw point clouds of a room, grainy ultrasound scans, satellite tiles. It does this by distilling CLIP's knowledge into those domains or retraining a fresh domain-specific CLIP from scratch. Both efforts are really the same wish: to make the alignment trustworthy in exactly the places where, right now, it is not.
CVPR'26Reevaluating the Intra-Modal Misalignment Hypothesis in CLIP
Problem
CLIP places pictures in one region of its space and text in another, leaving the modality gap, and a popular story blames a second, separate defect: that images are also badly arranged among themselves. Many methods then try to fix image-to-image structure directly, hoping to close the gap and improve retrieval. This paper asks whether that separate defect even exists, or whether people are chasing a phantom.
Approach
The authors give a clean mathematical proof: in CLIP's shared space, how similar two images look to each other is completely fixed once you know how images relate to text — there is no free wiggle room left for an independent image-to-image problem to fix. In other words, the much-discussed intra-modal misalignment is not a separate knob you can turn. They confirm this empirically by showing that a method built to rearrange image-to-image structure (Optimal Transport) buys no real gain over the baseline. They then offer a simple, training-free repair called PCA arrow: take a small pile of text embeddings, find their main directions, and project the image embeddings onto that same text subspace so the two modalities finally share a frame. As a clincher they show SigLIP, which glues image and text together more tightly, beats the vision-only DINOv2 even on pure image tasks — so it is the image-to-text alignment, not any private image structure, that drives performance.
Why it matters
This reframes the modality gap as a single problem — honest image-to-text alignment — rather than two, so effort stops going into repairing a geometry that was never broken. The takeaway is that trustworthy alignment comes from tightening the bridge between modalities, not from polishing each side alone.
CVPR'26IsoCLIP: Decomposing CLIP Projectors for Efficient Intra-modal Alignment
Problem
CLIP is trained only to pull matching image-text pairs together, so it never learns to arrange images sensibly against other images or text against other text. Yet people constantly reuse it for exactly those image-to-image and text-to-text searches, where it underperforms. Existing fixes exist but are slow and expensive to run.
Approach
The authors open up CLIP's final projection layers — the last little transforms applied before comparison — and show they secretly split into two jobs: one part actually aligns image with text, and the other part does nothing but normalize each modality on its own. Using a standard matrix decomposition (SVD) on those layer weights, they find that the space breaks into an isotropic slice where image and text are already well aligned, plus leftover lopsided directions that belong to just one modality and only add noise. IsoCLIP simply keeps the well-aligned isotropic slice and drops the lopsided directions. Because this is only a spectral decomposition of weights that already exist, it needs no training and adds zero runtime cost. The result is markedly better image-to-image and text-to-text retrieval across several CLIP variants, beating the slow inversion-based methods.
Why it matters
It shows the geometry needed for honest same-modality search was already hiding inside CLIP — you just have to isolate the aligned subspace and discard the rest. That makes CLIP usable for the retrieval jobs people already do with it, for free.
CVPR'26Ov3R: Open-Vocabulary Semantic 3D Reconstruction from RGB Videos
Problem
Fast 3D reconstruction systems can rebuild the shape of a room from an ordinary video, but they hand back bare geometry with no idea what anything is. Methods that do add open-vocabulary meaning usually need a depth sensor or run slowly offline. Nothing rebuilt geometry and named its parts, from RGB video alone, in real time.
Approach
Ov3R pushes CLIP's naming ability directly into the reconstruction process instead of bolting it on afterward. It first uses SAM to cut each frame into objects, runs CLIP on each object cutout, and stitches the results into a per-pixel map of object-level CLIP features — a cleaner signal than running CLIP on the whole cluttered frame. Those features are then cross-attended into the image-to-points branch of a SLAM3R-style reconstructor, and a second head is trained to carry the same CLIP meaning into the 3D scene coordinates themselves, so geometry and semantics are built together. At query time a fusion module blends the 3D-CLIP features with DINO features and compares them against the text embeddings of whatever class names you type, letting you segment the scene by open vocabulary. It runs at 15 FPS on a single RTX 3090 and sets the state of the art on both reconstruction and open-vocabulary 3D segmentation benchmarks.
Why it matters
This carries CLIP's open-vocabulary superpower off the flat web photo and into live 3D space, where raw point clouds have no built-in notion of language. Distilling object-level CLIP features into the geometry itself is what makes a rebuilt room queryable by plain words.
CVPR'26Ultrasound-CLIP: Semantic-Aware Contrastive Pre-training for Ultrasound Image-Text Understanding
Problem
Ultrasound is one of the most common scans in the clinic yet makes up under 5% of medical image-text data, so off-the-shelf CLIP has barely seen it. It also breaks CLIP's assumptions: the same tissue looks different across regions, the view depends on how the operator held the probe, and diagnosis hinges on ultrasound-specific attributes CLIP has no words for. Reading it well takes clinicians years.
Approach
Rather than patch a web-trained model, the authors retrain a domain CLIP from scratch on US-365K, the first fully-ultrasound vision-language dataset — 365,000 image-text pairs spanning 52 anatomical categories. They first lay down an Ultrasonographic Diagnostic Taxonomy that organizes anatomy hierarchically and captures diagnostic attributes across nine dimensions. A heterogeneous graph encoder then models how diagnostic labels and their attributes relate, so the model reasons about lesion-and-attribute structure rather than treating each caption as a flat string. Crucially, instead of the usual hard right/wrong pairing, they use semantic soft labels that grant partial credit for near-matches — fitting a field where two findings can be genuinely similar. Trained this way with dual-branch contrastive learning, Ultrasound-CLIP reaches state-of-the-art on ultrasound classification and retrieval and generalizes across zero-shot, linear-probe, and fine-tuning settings.
Why it matters
It shows that when a domain is far enough from web photos, the honest move is to rebuild CLIP inside that domain with its own vocabulary and its own soft notion of similarity. That is how the open-vocabulary idea becomes trustworthy in a specialty where the generic model was effectively blind.

5 · Commanded in open language

An old-fashioned robot only knows what it was trained to name, so if you tell it to bring the mug and mug was never in its fixed list of labels, it is simply blind to the thing you want. CLIP-style alignment breaks that ceiling by putting pictures and words into one shared space, so a robot can be told in plain language to find or grasp an object nobody labeled in advance. For navigation, it paints the map itself with vision-language features and then heads to whichever spot is most similar to the words you said. For grasping, it grounds those words down to actual pixels and hands that region to a grasp planner, sometimes retraining CLIP so the alignment also understands actions and which part of an object affords the task. The payoff is a robot you can simply talk to, instructing it in open language rather than from a menu. But the failure mode moves off the screen and into the physical world: instead of a mislabeled caption, the robot grasps the wrong object or fetches the wrong thing. Naming and doing become the same act, which means a naming mistake is now a mistake your hands can feel.
ROBOTICS'25One Map to Find Them All: Real-time Open-Vocabulary Mapping for Zero-shot Multi-Object Navigation
Problem
When a robot is told to find several different objects one after another, most zero-shot navigation systems throw away everything they saw during the last search. So each new command starts the exploration from scratch, wastefully re-walking rooms it already understood.
Approach
As the robot moves, it paints a persistent map of the space with vision-language features, so every location carries an embedding that can be compared against any words you type in later. Because the map lives in the same shared space as text, a new query never needs new training. A probabilistic-semantic update smooths out the noise in those per-place features so the map does not chase spurious matches. And a measure of semantic uncertainty steers the robot toward the places most worth exploring, letting one built-up map answer many object queries in a row.
Why it matters
This is acting on words directly: the map is searched by meaning, so a plain-language command lands the robot at the most text-similar spot. If the alignment misjudges which place matches, the robot physically walks to the wrong room.
ROBOTICS'25Helpful DoggyBot: Open-World Object Fetching using Legged Robots and Vision-Language Models
Problem
A quadruped robot dog has no hand, no built-in sense of what objects mean, and cannot easily cross indoor obstacles, so it cannot do a genuinely helpful chore like fetching a specific object you name. The gap is both physical and semantic at once.
Approach
The robot dog gets a simple front-mounted gripper and a low-level controller trained in simulation on egocentric depth, which gives it agile locomotion like climbing and tilting its whole body to reach. On top of that, pre-trained vision-language models read fisheye and egocentric RGB cameras to recognize the object you asked for and turn that into commands, with no real-world training data collected in advance. Because the vision-language model already aligns pictures with open language, the dog can be told to fetch an object it was never specifically trained on and still zero-shot generalize to a new home. It reaches sixty percent success on fetch tasks that even require climbing over obstacles.
Why it matters
Here the language becomes a whole-body action: you say a word and the dog crosses the room and picks up the thing. When the vision-language grounding names the wrong object, the robot physically fetches the wrong item back to you.
ROBOTICS'25AffordGrasp: In-Context Affordance Reasoning for Open-Vocabulary Task-Oriented Grasping in Clutter
Problem
Grasping the right object is not enough; a robot also has to grasp the right part of it, and doing that for unfamiliar objects in a messy cluttered pile is hard without special training data for each task. Existing systems struggle when the instruction is implicit rather than a precise labeled command.
Approach
AffordGrasp uses a vision-language model to reason, in context, about what task you actually intend from an implicit instruction, rather than needing you to spell it out. It then grounds that reasoning down to specific parts of the object through a visual grounding module, marking which region affords the task. Because this grounding lives in the open-language space, it works on novel objects the robot never saw before. The chosen affordance region is finally handed to a grasp planner, which computes a grasp pose that lands inside that correct part.
Why it matters
This is where naming turns into precise handling: the words are grounded all the way to the pixels of the right part before the fingers close. Get the part wrong and the physical failure is concrete, the robot grabs a knife by the blade instead of the handle.
ROBOTICS'25Robotic-CLIP: Fine-Tuning CLIP on Action Data for Robotic Applications
Problem
CLIP learned its picture-and-word alignment from frozen, static images, so it has no real sense of dynamic actions. That makes it a shaky backbone for robots, whose whole job is to do things over time rather than recognize a single snapshot.
Approach
Robotic-CLIP retrains CLIP on frames drawn from action videos instead of still photos, using more than three hundred thousand videos and roughly seven million frames each labeled with an action description. The same contrastive learning that once aligned images with object names now aligns action frames with action words. This extends the shared space so that phrases about doing, not just naming, line up with what the camera sees. The result outperforms every CLIP-based baseline on language-driven robot tasks, including real-world grasping.
Why it matters
By teaching the alignment to understand actions, a spoken instruction can drive what the robot does, not just what it labels. If the retrained alignment misreads the action, that error shows up as the gripper doing the wrong motion in the real world.

6 · A map you query by text

Instead of steering a robot toward one named target, you can build a whole 3D map where every object carries a CLIP language embedding, so the finished map is queryable by text like a database and you can ask it where is the mug next to the sink and get back a location. Storing relations between objects, not just the objects, lets the robot do spatial reasoning about which mug and which sink. Modern versions attach these language features to voxels, to point clouds, or to Gaussian splats, and they build the map online while the sensors are still noisy and the scene is only half-seen. The same alignment that makes a map searchable is also a safety layer. A robot trained on a fixed list of labels silently ignores anything outside that list, which on a road is a dangerous failure, because the one object it has never seen is exactly the one it drives into. Vision-language alignment plus a measure of uncertainty lets the system say this is something, and it is not one of my known classes rather than confidently mislabeling it or dropping it entirely. The goal here is not a benchmark number; it is not driving into the thing the robot has never seen before.
ROBOTICS'25Beyond Bare Queries: Open-Vocabulary Object Grounding with 3D Scene Graph
Problem
You want to tell a robot bring me the mug on the left, but a scene has many mugs, and a system that only matches words to objects one at a time cannot tell them apart. The hard part is the relations: which mug, relative to which other thing. Open-vocabulary methods that score each object in isolation fail exactly when the query depends on how objects sit next to each other.
Approach
The pipeline, called BBQ, first turns raw sensor views into a 3D scene graph, where each node is an object and edges record how objects relate in space. It builds this graph by associating the same object across frames using DINO visual features and raycasting, then asks a 2D vision-language model to describe each node in words. When a query arrives, an LLM runs a step-by-step deductive reasoning algorithm over the graph, eliminating candidates until only the object the sentence actually refers to remains. Because the object descriptions come from a foundation model rather than a fixed label list, the map answers open-vocabulary text queries without any task-specific training. It reaches state-of-the-art grounding on the Sr3D+, Nr3D, and ScanRefer benchmarks zero-shot.
Why it matters
This is the map-as-database idea in its clearest form: build a queryable 3D graph once, then resolve arbitrary text queries by reasoning over relations rather than matching a single word to a single blob.
ROBOTICS'25OpenGS-Fusion: Open-Vocabulary Dense Mapping with Hybrid 3D Gaussian Splatting for Refined Object-Level Understanding
Problem
Earlier open-vocabulary 3D maps are built offline in a rigid batch pipeline and then decide what belongs to an object using one fixed similarity cutoff. A single hard threshold is wrong in different parts of a scene, so object boundaries come out blurry and the map is not accurate enough at the object level. It also cannot keep up in real time as the robot moves.
Approach
OpenGS-Fusion builds the map as 3D Gaussian splats and fuses each splat with a language feature online, so every piece of the reconstructed scene carries a CLIP-style embedding you can query by text. It combines the splats with a Truncated Signed Distance Field so the geometry stays consistent while the semantic features are fused frame by frame. Instead of one global cutoff, a multimodal LLM sets the similarity threshold adaptively (the MLLM-AAT strategy), tightening or loosening the boundary per object so segmentation snaps to the real object edges. This runs as an online dense-mapping system rather than an offline batch job. The adaptive thresholding lifts 3D mIoU by 17% over fixed-threshold baselines.
Why it matters
It shows the language embedding does not have to live in a separate index: you can attach it directly to the geometry primitives, so the reconstructed surface is the searchable database, built live under sensor noise.
ROBOTICS'25Leveraging Text-Driven Semantic Variation for Robust OOD Segmentation
Problem
A driving perception model trained only on the visual appearance of known classes has no way to represent an object it has never seen, so genuine road anomalies slip through. The failure is worst for truly unseen hazards, the cases where safety matters most.
Approach
The method attacks the problem through language instead of only pixels. It generates text prompts at deliberately varying semantic distances from the in-distribution classes, from things that are almost-but-not-quite a known class to things far outside it, so the model learns a spread of what not-a-known-class can look like. This Distance-Based OOD prompting is paired with OOD Semantic Augmentation, and a transformer decoder aligns the visual features with these text embeddings so anomalies stand out as regions that match the far-away prompts rather than any known class. Because the supervision comes from language variation, the model generalizes to anomalies never present in the training images. It sets state-of-the-art on the Fishyscapes, Segment-Me-If-You-Can, and Road Anomaly benchmarks.
Why it matters
This is vision-language alignment used purely as a safety net: by describing the space around the known classes in words, the car can flag something is there and it is not one of my classes before it drives into it.
ROBOTICS'25Open-Set LiDAR Panoptic Segmentation Guided by Uncertainty-Aware Learning
Problem
LiDAR segmentation models for self-driving are trained under a closed-set assumption: every point must be one of the known classes. In the open world they meet object types that were never in the training set, and a closed-set model quietly forces each of those unknown things into a known label, so it never reports that something new is present.
Approach
ULOPS makes the network report how uncertain it is rather than always committing to a known class. It uses Dirichlet-based evidential learning to estimate predictive uncertainty inside a panoptic architecture that has separate decoders for semantics, for point embeddings, and for instance centers. Three purpose-built losses (Uniform Evidence, Adaptive Uncertainty Separation, and Contrastive Uncertainty) train the model so that known objects get confident predictions while genuinely unknown instances light up as high-uncertainty regions and are segmented out as their own separate objects rather than absorbed into a known class. This lets the system carve out unknown instances at the object level instead of just per-point noise. The authors add open-set evaluation settings for KITTI-360 and nuScenes to measure exactly this unknown-detection ability.
Why it matters
Uncertainty is the safety signal here: instead of mislabeling the unfamiliar object, the robot marks it as an object I do not recognize and can treat it as an obstacle rather than driving through it.
Reading it whole. Top to bottom, the themes walk the same alignment outward: first fix what CLIP’s whole-image training misses, then lift its alignment down to every pixel, then adapt it cheaply or use it with no training, then repair its geometry and carry it into new domains — and finally hand the same words-to-pixels trick to a robot so it can be commanded, mapped, and kept safe by name. The tasks differ wildly; the primitive — put pictures and words in one space and pull each toward its match — never changes.
