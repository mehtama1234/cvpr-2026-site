Symmetry as a prior — equivariance across CVPR & Robotics

The why page argued it from first principles: build a known symmetry into the network so rotating the input rotates the answer — free generalization instead of memorized orientations. This page shows an honest split: in mainstream 2D vision, big data and augmentation often substitute for it, so it clusters in 3D/point-cloud/remote-sensing corners; in robotics, where poses live on SE(3), it is the native language.

What changes between vision and a robot

axisCVPR 2026 (vision)Robotics 2025
Is symmetry optionaloften — enough data + augmentation fakes itno — a robot cannot brute-force every pose with real trials
Where it entersthe network (equivariant layers) or a canonicalization stepthe action space, the estimator, the controller
Typical objectpoint clouds, oriented boxes, shapesgripper poses, trajectories, multi-agent control
The payoffdata efficiency in the geometric cornerssample-efficient policies that generalize across placements
The through-line. Equivariance builds a symmetry into the model so it need not learn it from data. In vision it is a data-efficiency prior for the geometric corners; in robotics, where every pose is an element of SE(3), it is the native structure of action and estimation — the same primitive, a helpful prior versus the geometry of the world.
