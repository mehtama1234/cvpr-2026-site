Optimization landscapes and grokking — why it works, mathematically

Training can find a memorizing valley first and the real rule later. Grokking is the moment the simpler circuit finally wins.

Plain-English big picture

What this is really about

Grokking is the pattern where a model first memorizes the training examples and only later finds the simple rule that works on new examples. The training score looks good before the model truly understands.

Where topology and shape enter

Topology helps explain why the simple rule may be a cleaner shape in the solution space. Many parameter settings can fit the training data, but only some form a stable, simple region that extends to unseen cases.

Where the same idea appears elsewhere

The idea matters in math tasks, code, reasoning, games, and any setting where examples are few but the hidden rule is simple.

Why Optimization landscapes and grokking is worth learning

It matters because early success can be fake. We need to know whether a model learned the rule or merely stored the cases.

The problem, as a quantity

A loss landscape contains many ways to fit the training set. Some are lookup tables: perfect on seen examples, useless off them. Others are compact rules: also perfect on seen examples, but correct on unseen combinations. The puzzle of grokking is temporal: why does optimization sometimes reach zero training error early, sit there for a long time, and only much later jump to high test accuracy?

The core ideas — and why they work

Train loss does not identify the rule

many θ satisfy L_train(θ)=0, but L_test(θ) differs
The training set is a finite list of examples and their answers. Many different functions can match all those answers exactly. One function might just memorize each answer by storing it; another might learn the actual operation that produces those answers. After the model learns to match every training example, both functions look the same when you measure the training error. The real difference only shows up on new examples the model has never seen. The additional information needed to pick the right function is not hidden in the training error number alone. It comes from other choices: whether the learning method prefers smaller parameters over larger ones, the design of the model, how much variety is in the training set, and whether you penalize complex parameter configurations. One key fact: a finite dataset cannot uniquely pin down one function; it only narrows down which functions are ruled out.

Weight decay changes which zero-loss solution survives

min θ L_train(θ) + λ||θ||²
Once the model can match every training example perfectly, the training error stops changing—it is already zero. At that point, the training error cannot tell the difference between memorization and real learning. But there is another signal: a penalty that grows with the size of the parameters. This penalty keeps pushing toward smaller, simpler parameter values. A compact circuit that implements the actual operation can become cheaper under this penalty than a memorizing network that stores lookups. The delay in grokking happens because: first, the model finds any way to match all the training examples, then the penalty gradually nudges it toward a simpler way to do the same job. Both approaches give zero error on training; the penalty decides which one the optimizer chooses to keep.

A circuit forms when features align with the task symmetry

f(a,b)=a+b mod p requires equivariance to cyclic shifts
For operations like modular arithmetic, the actual rule is not just a table of answers; it is a pattern that stays the same under certain shifts. For example, if you shift all the numbers in a circular way, the operation still works the same. A network can find simple repeating patterns (like waves in Fourier analysis) that capture this rotation pattern compactly. In contrast, a lookup table needs a separate memory location for each pair of inputs. The repeating-pattern approach uses far fewer parameters. The reason grokking happens at all: the task has hidden structure—a symmetry—that can be compressed into a few features. If the task were just random answers with no pattern, no amount of training would find a compact rule.

The jump is a threshold crossing, not magic

test accuracy ≈ 1[circuit strength > memorizer strength]
Inside the network, the compact rule can be getting stronger step by step, steadily improving. But on the outside, the test accuracy number might look flat for a while, because the final answer is discrete: right or wrong. Until the rule becomes strong enough to beat the memorizer on enough test examples, the accuracy score barely changes. Once the rule crosses the point where it beats the memorizer on most examples, many answers flip at once and the accuracy jumps suddenly. This explains grokking: the internal optimization is smooth and gradual, but the measured score has a threshold. Below the threshold, the memorizer wins; above it, the rule wins. The visible jump is where that threshold is crossed.

The approaches, as variations on the math

Grokking studies vary the data fraction (how many training examples the model sees), weight decay (how much to penalize large parameters), model size (how many parameters to allow), optimizer (which learning algorithm to use), and task algebra (what operation to learn) to see when the solution changes from table lookup to rule. Landscape views track movement along zero-training-loss valleys (the paths where training error is already zero). Circuit views inspect whether interpretable features, often simple repeating patterns for modular tasks, have formed. Scaling views ask why more data sometimes removes the delay by making the rule easier to identify earlier.

A worked numeric example

The run at analysis/grok/toy_grok.json trained modular addition over p=97 (addition where you wrap around after 97). Training accuracy reached 1.0 by step 100, while test accuracy stayed around 0.40 for many checkpoints. Around step 2600, test accuracy crossed 0.968 and then reached 1.0. That gap is the point: fitting the observed table happened quickly; discovering the compact rule took longer.

The through-line. Grokking is a microscope on generalization. It shows that zero training error is not the destination; it is a plateau containing many possible explanations of the data. The choice of learning rate, regularization, architecture, and scale decide which explanation survives. That makes grokking the bridge between scaling laws, information bottlenecks, hidden structure and symmetry in tasks, and the trap that models face: abandon the cheap memorizing solution and settle into the compact rule that actually transfers to new examples.
