Normalization (batch / layer norm) — why it works, mathematically

A network's layers pass numbers between them, but if one layer feeds numbers of wildly different sizes to the next, learning gets confused and slow. This is the trick that makes sure every layer receives signals in a standard, predictable range — freeing it to learn faster.

The key turn — the principle at work

The stuck point. Deep layers can send numbers whose scale drifts during training. The next layer then has to learn from inputs that keep changing size and center.

The mathematical move. The principle is scale control. Normalization subtracts a mean and divides by a spread, then lets the model learn a new scale and shift if useful.

What changes. Each layer receives numbers in a stable range. This keeps forward signals and backward gradients from becoming too large or too small, while still allowing the network to choose its own final scale.

The problem, as a quantity

A neural network is a tall stack of operations, each one taking numbers from the layer below and producing new numbers to pass up. The problem is that the outputs of one layer can drift — sometimes all tiny, sometimes all huge. The next layer, which was trained assuming numbers in a certain size range, now gets garbage and can't use what it learned.

Imagine tuning a radio. You learned that turning the knob by 1 degree changes the volume by a small, predictable amount. But then someone starts feeding you a pre-amplified signal that is 100 times louder. Now the same 1-degree turn screams. The knob-to-volume relationship you learned is useless. That is what happens when a layer's input sizes drift unpredictably — the layer's learned rules no longer match reality.

The core ideas — and why they work

Re-center and re-scale each layer's signals to a standard shape

x̂ = (x − μ) / √(σ² + ε)
The core idea is to grab the numbers coming out of a layer, measure how spread out they are (the average value and the spread around it), and then shrink them back to a predictable shape. The equation subtracts the center point (called μ, the middle value) from each number, then divides by the spread (called σ, a measure of how far numbers scatter), plus a tiny safety number ε so we never divide by zero. The result is a bundle of numbers that cluster around zero with a standard, predictable scatter. Every layer receives the same kind of signal shape, so it can rely on what it learned.

Hand the freedom back with a learned scale and shift

y = γ·x̂ + β (γ, β learned)
Here's the catch: if every layer is forced to the same shape, they all start to look the same. No variety, no specialization. So after standardizing, the network is allowed to unstandardize — it learns two new numbers (γ and β) that scale and shift the standardized result. Think of it as handing the freedom back. The network learns whether this particular layer wants its signal taller, shorter, or shifted sideways. This pair of learned numbers is tiny compared to the cost of getting the signal into a usable range first.

It stops each layer from chasing a moving target

keeps the signal's scale steady across layers → allows bigger steps
Without normalization, a layer can push its output numbers bigger and bigger, because that makes it feel more confident in what it learned. But when you push one layer's output huge, the next layer receives huge inputs, and that breaks the next layer's learned rules. It is like feedback: size begets size. Normalization cuts that feedback loop. It forces each layer to stay in a predictable range, so the next layer does not need to re-learn everything. Because signals stay steady, the learning algorithm can take bigger steps without overshooting — it knows the signal range is stable, so the knob-to-output relationship it learned is still true.

Averaged over what: across examples, or across features

batch-norm: μ,σ over examples; layer-norm: μ,σ over features
The two types of normalization answer one question differently: what do we average over. Batch normalization measures the center and spread by looking at the same number's value across all the examples in a training batch — it pools information across a group of inputs. Layer normalization measures the center and spread by looking across all the numbers in one example — it pools information within a single sample. Batch norm works better in large batches because averaging over many examples gives a stable estimate. Layer norm works better when examples arrive one at a time (like in inference or when batch size is tiny), because it does not depend on the batch. Most modern networks use layer norm because it does not change behavior between training and deployment.

The approaches, as variations on the math

Normalization is really a single machine with a few adjustable dials. The core step is always the same: measure the center and spread, then standardize. The choices are what to average over (batch norm across examples, layer norm across features, instance norm across space, group norm across subsets), when to standardize (before the next operation, after, or with a delay), and whether to include learned scale and shift (almost always yes, because the network needs freedom to specialize). The thread never changes: predictable signal shapes let each layer trust what it learned, so the whole stack can train faster and more stably.

Every approach, and the lever it pulls

1Normalization axis: averaging over samples vs features
Batch norm averages μ over examples; Layer norm averages over features
Batch norm computes the mean and spread of each feature across all examples in the batch, so it ties what happens in one training example to others. Layer norm instead computes mean and spread of all features within a single example, so each example normalizes itself independently. Batch norm works well when you want to stabilize training across many examples; layer norm works well when batch size varies or when you want each example to stand alone.
2Train vs test split: moving statistics
Batch norm uses batch μ, σ at train; exponential moving average at test. Layer norm uses same at both.
Batch norm faces a problem: during training, the mean and spread of each feature change every batch as new examples arrive. To make this stable at test time when you have only a few examples, batch norm remembers an exponential moving average of the statistics from all training batches. Layer norm has no moving parts—it computes fresh mean and spread on the fly for each forward pass, whether training or testing. Batch norm requires this extra bookkeeping; layer norm does not.
3Scope of averaging: full features vs grouped
Layer norm groups all features; Group norm groups F features into G subsets; Instance norm: each feature alone
Layer norm pools all your feature channels together when computing mean and spread, which can wash out rare or specialized signals. Group norm divides your channels into G groups (for example, 64 channels into 32 groups of 2) and normalizes each group separately, keeping some independence. Instance norm normalizes each channel on its own, with no pooling across features. As you shrink the group, you add more separation but lose the smoothing power of larger pools; as you expand, you smooth more but risk drowning out finer details.
4Affine transform: learned scale and shift restore flexibility
After norm: z_norm = (x - μ) / σ; apply y = γ * z_norm + β with learned γ and β
Normalization forces all signals into a standard shape (mean zero, spread one), which is powerful but rigid—it strips away information about the original range. The learned scale γ and shift β let the model recover: γ scales the normalized signal back up or down, and β slides the whole thing up or down. This means the model gets to keep its flexibility—it can learn whether a feature should be large or small, centered high or low—while still gaining the stability that normalization provides.

What breaks without this

What goes wrong. Without normalization, each layer keeps receiving numbers whose scale can drift while training. One layer may send values that are tiny today and huge tomorrow. The next layer has to learn while its input keeps changing under its feet.

Why it goes wrong. Deep networks pass numbers through many stages. If the scale grows, later steps can become wild. If it shrinks, later steps can become too weak to matter.

What this idea gives you. Normalization resets the scale before the next layer works. It does not solve learning by itself; it keeps the numbers in a range where learning can keep going.

The through-line. The core problem is that when signals drift in scale between layers, learning gets confused — each layer expects a certain size range but receives something wildly different, breaking the relationship it learned. Without a steady signal shape, the learning algorithm has to be cautious, taking tiny steps because it cannot trust its own rules. Two plain ideas carry it: measure the center and spread of each layer's output, then squeeze it back to a predictable shape (so the next layer sees a reliable range), and hand the freedom back by letting the network learn a custom scale and shift (so it can specialize for its own job without losing the stability gain).
