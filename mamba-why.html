State-space models — linear-time sequence modeling, and why Mamba needed selectivity

Attention made transformers powerful by letting every token look at every other — but that same move is a wall: its cost grows with the square of the input, so long videos, huge images, and dense point clouds become unaffordable. State-space models (the Mamba family) offer a different bargain: read the input in order, carrying a small running memory, at linear cost. This page is the plain story of that trade, built on a real run — including the one ingredient, selectivity, without which the cheap model is useless.

1 · The problem — attention compares everyone to everyone

The engine inside a transformer is attention: to process a sequence, every token is compared against every other token, so the model can pull in whatever context it needs from anywhere. It is wonderfully flexible — and its bill grows with the square of the length. Double the resolution or the video length and the cost roughly quadruples. For a small photo that is fine; for a 40-minute video, a gigapixel slide, or a dense point cloud, it is the wall you hit.

The problem, stated once: model long sequences and big inputs with a global view, but without attention's quadratic blow-up in time and memory as the input grows.

2 · The reframe — read in order, carry a small memory

The idea: don't compare everything to everything — read the input once, left to right, keeping a small running summary. Like reading a sentence, a state-space model steps through the sequence one token at a time, updating a fixed-size state that carries what it has seen so far. One step per token means the cost grows in proportion to the length, not its square — and because the memory is a fixed-size state, it never grows. Linear time, constant memory.
state_t = update(state_(t-1), token_t) output_t = read(state_t)     # one step per token, a fixed-size running memory — a selective scan

But a plain running memory has a fatal weakness: if the update rule is fixed, it cannot decide what to keep — it blurs everything it reads into one summary. Mamba's breakthrough was to make the update depend on the input (selectivity), so the scan can hold onto the tokens that matter and let the rest wash past. The run shows both the selectivity and the cost.

3 · Seen on a real run — selectivity, and the cost gap

1 · Selectivity is what makes the linear model work

We set a selective-copy task: a few content tokens are scattered among blanks, and the model must reproduce just the content, in order — it has to choose what to remember and skip the rest. Three models, same size:

selective SSM (Mamba)
90%
attention
76%
plain (non-selective) SSM
41%

The selective SSM nails it (90%), and so does attention (76%) — both can pick out content by what it is. But a plain, non-selective SSM — one whose memory update is fixed and cannot depend on the input — is stuck at 41%. It reads in order at linear cost, but with no way to decide what matters, it drowns in the blanks.

That is Mamba's key idea: make the running memory's update input-dependent, so a linear-time scan can still selectively remember the important tokens and forget the rest. Without selectivity, cheap is useless; with it, you get attention-like ability at a fraction of the cost.

2 · And the cost is the whole point — linear, not quadratic

Here is why anyone bothers. Attention builds a full table comparing every token to every other, so both its work and its memory grow with the square of the length. The SSM just takes one step per token with a fixed-size state. The counts, as the sequence grows:

At length 4,096, attention makes 16,777,216 comparisons and must hold a table that big in memory; the SSM takes just 32,768 steps and its memory never grows — a constant 512. Double the length and attention's cost quadruples while the SSM's merely doubles. That gap is the wall Mamba was built to get around.

4 · Why it matters — the drop-in for anything long or big

Linear time and constant memory make state-space models the natural choice wherever attention chokes: hour- long video, high-resolution medical scans and satellite tiles, dense point clouds, and streaming sensor data. They show up less as a headline and more as a quiet efficiency engine swapped in wherever the input is long. The one recurring puzzle: an image is 2D and a point cloud is an unordered blob, but a scan needs a 1D order — so much of the craft is designing a scan path (diagonal, Hilbert-curve, snake, content-aware) that flattens the input without tearing apart what was neighboring.

5 · The surprise — a memory that can run forever

In vision, Mamba is picked to make a big fixed input cheaper. A robot wants something subtler. It runs continuously — it never stops receiving observations — and attention's memory grows with every new timestep, an unbounded cache for an unbounded stream. That is exactly wrong for a device that must run for hours on a small onboard computer.

A fixed-size state fits a loop that never ends. Mamba's constant running memory is the right shape for real-time, memory-bounded, onboard control: remember a long history at a flat, small, predictable cost. Vision reaches for the linear-time compute win; a robot reaches for the constant-size memory that lets the loop run forever. The in-the-wild page lays out both sides.
