CLIP — why it works, mathematically

Text is a free label set. Teach an image encoder and a text encoder to measure distance the same way, and every word becomes a class without extra training.

Plain-English big picture

What this is really about

CLIP-style learning puts images and text into the same room. A picture of a dog should land near the phrase 'a dog running', and far from 'a red car'. The model learns by comparing many correct and incorrect pairs.

Where topology and shape enter

For topology and shape work, this means words can point to structure: loop, boundary, connected part, hole, handle, inside, outside. The model can begin to connect human descriptions with the shape features that make those descriptions true.

Where the same idea appears elsewhere

The same image-text matching supports search, captioning, robot instructions, medical report lookup, design tools, and open-vocabulary detection. It lets a system use language as an interface to visual data.

Why CLIP is worth learning

It matters because fixed label lists are too small for the real world. Language gives vision a flexible way to ask for new things without retraining from scratch.

The problem, as a quantity

An image and its caption describe the same moment, yet live in entirely different math spaces: one is a grid of brightness numbers, the other a list of integer codes for words. To make a model that can sort images by any noun in English — not a fixed list of 1,000, but literally any word — you need one shared measure where 'a photo of a dog' and an actual dog-image are close together, and a photo of a cat is far away. The real problem has two sharp parts. First, you cannot name all possible labels at training time: English has hundreds of thousands of nouns and the world has infinitely more things. Second, you cannot compare an image to a word using any obvious rule — picture numbers and word numbers are not in the same kind of space at all. So the problem is: build a space that does not yet exist, and teach two different encoders to fill it the same way, using only the weak clue that some (image, caption) pairs were about the same thing.

The core ideas — and why they work

InfoNCE: softmax over a matrix of similarities

L_i = -log[ exp(sim(vᵢ, tᵢ)/τ) / Σⱼ exp(sim(vᵢ, tⱼ)/τ) ], sim(v,t) = vᵀt / (‖v‖‖t‖)
The loss function does one thing: for each image i, it runs softmax — turn numbers into shares that add up to 1 — over all text code-lists in the batch and tells the model 'your own caption must win the highest share.' The sum in the denominator Σⱼ exp(sim(vᵢ,tⱼ)/τ) adds up every other caption in the batch. All of them are negatives, for free, not because anyone labelled them but because they are simply other images' captions. The whole batch makes an N-by-N table of match scores — N pairs on the diagonal that are true matches (the model should learn these), and N times N minus N pairs off the diagonal that are wrong matches (the model should learn these too). Why does this teach the model anything useful? Because real captions are specific: 'a golden retriever chasing a frisbee' is nearly one of a kind in a batch of 32,768 images. A model that cannot tell it apart from 'a woman in a red coat' gets heavily punished by the sum in the denominator. So the loss pushes the encoders to save exactly the meaning that separates one caption from another — not to copy pixel values back, but to capture what the words mean.

Temperature τ: sharpness of the boundary between similar and different

grad_τ L ∝ (sᵢᵢ - 𝔼ⱼ[sᵢⱼ]) / τ² — hotter τ smooths, colder τ amplifies angle gaps
τ is not something you guess by intuition — it controls the shape of the learned space directly. A small τ makes the softmax nearly a hard pick-the-best: the loss acts as if only one thing matters — whether the right pair scores higher than every other pair — and it punishes anything close to a tie harshly. This spreads the image and text code-lists across a sphere and uses up the full range of angles. A large τ softens the shares: many pairs get similar probability, the push to improve is weak, and code-lists cluster in a tiny region. The loss barely forces them to learn. CLIP learns log τ as a dial (so τ stays positive) and it settles around 0.07, making the space much sharper than most people would guess. The real danger is collapse: if all images land near the same code-list, every angle score is about 1 and the softmax becomes flat — the model gets no push to change. Scaling both outputs to unit length (dividing by their size) and learning τ are the two fixes that stop this.

Shared embedding space: angle distance as a common language

ŷ = argmaxₖ sim(v_image, t_k), t_k = TextEncoder('a photo of a {class_k}')
After training ends, sorting new images by text is not a new trick added on — it is just the space doing its job. Take a new class name k and run it through the same text encoder that was trained together with images: you get a unit code-list t_k living in the same space as every image code-list. Pick the class whose code-list has the most angle agreement with the image. No retraining, no new weights for prediction, no labelled examples needed. This works because the loss during training set one hard rule on the space: an image code-list must be closer in angle to the text describing it than to any other text in the batch. That rule, applied over 400 million (image, caption) pairs, fills the space densely enough that new class names land near images they describe. The space is also built from parts: 'orange cat' lands between 'orange' and 'cat' because text naturally combines pieces of meaning.

Batch size as contrastive power: N negatives for free

signal-to-noise ∝ log N, memory ∝ N·d (d = embedding dim) — trade GPU memory for discriminative force
In a batch of N pairs, each image sees N minus 1 wrong captions and the sum in the loss has N terms. Doubling N does not double the learning signal — it adds the log of N more discrimination per step (because the sum grows and the model must push much harder to win). In practice this means this kind of loss loves large batches: CLIP used N equals 32,768. A batch of 32 gives 31 wrong examples; a batch of 32,768 gives 32,767, and many of them are 'hard' — meaning they are close in content to the true caption. Hard wrong examples are what teach fine details — the model cannot get away with rough code-lists when the sum includes 'a golden retriever running' right next to 'a golden retriever sitting.' New tricks (momentum lists that remember old examples, gathering code-lists across many GPUs without backprop) are workarounds to fake a large N without needing huge memory. Honest truth: CLIP scales well with N and with more data, but the large-batch need makes it expensive to copy without many GPUs.

The approaches, as variations on the math

Every change to CLIP tweaks one of two things: where the matching happens and what is being matched. Image-level matching (original CLIP) gives zero-shot sorting but no location info — it cannot tell you where a 'dog' is, only that the image has one. Per-region or per-patch matching (detection or segment by open vocabulary: add more matching locally at each spatial spot) applies the loss to local code-lists, so each region gets its own angle score against the text. Freeze-and-tweak methods (CoOp, CLIP-Adapter, LoRA on the encoders) keep the shared space fixed and add a small trainable turn to fit a new domain — keeping broad zero-shot use while gaining narrow depth. Robotics variants embed language goals as text, then use angle similarity to the observation code-list as a reward or a policy input — turning the metric space into real live control. The common thread: once you have a space where angle measures meaning alignment, any new task is just a new search into that space.

A worked numeric example

With image-text similarities [4,1,0], softmax gives the correct caption probability about 0.936. If the correct pair similarity falls to 2, probability drops to about 0.665. CLIP learns by widening this margin against every wrong caption in the batch.

The through-line. CLIP's core move is building a space that does not exist yet — one where pictures and words can be measured the same way — by forcing matched pairs to be close under the gradual push of softmax. Two ideas do all the work: InfoNCE turns a batch of N pairs into N-squared supervision signals with no labels beyond 'these go together'; and the shared angle metric makes that space immediately useful for any new text search, old or new. The temperature τ and unit scaling stop collapse — the same trap that threatens every strong loss of this kind. Deep down, CLIP is a matching problem solved by softmax, the same two recurring moves that run attention and routing. What makes it singular is the data: 400 million noisy (image, caption) pairs from the web are weak clues, but weak times huge equals a space dense enough that any English word finds its neighborhood.
