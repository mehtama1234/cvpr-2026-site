Equivariance — teaching a network the symmetries of the world

A cat upside-down is still a cat. A wrench rotated forty degrees is the same wrench. The world is full of these symmetries, and a plain network is blind to them — shown a thing it learned upright, then rotated, it can be hopelessly lost, because it had to memorize every orientation separately. Equivariance is the idea of building the symmetry into the network, so that rotating the input simply rotates the answer — guaranteed, not learned. This page is the plain story of that idea, and a real run where symmetry does the work of data you never had to collect.

Mathematical core

Hidden quantity. The page is really about estimating which transformations should move the answer predictably.

Evidence. The model sees rotations, shifts, permutations, views, coordinate frames, and consistency losses.

Rule. The fundamental rule is to tie the model's output to the symmetry of the task, so transformed input gives transformed output.

Failure test. Without the symmetry, the model has to relearn the same fact in every pose and fails outside the seen geometry.

1 · The problem — the same thing, in a new pose

Almost everything a vision system sees could appear at any position, any orientation, any scale, and it would mean the same thing. A plain network does not know this. Unless you show it a wrench at every angle, it may recognize the upright one and miss the tilted one — so you pour in more data, more augmentation, more parameters, all to teach it something you already knew for certain: that rotating a thing does not change what it is.

The problem, stated once: the world has known symmetries (rotate, translate, reflect and the meaning is unchanged) — how do you stop a network from wastefully re-learning each one from data?

2 · The reframe — bake the symmetry in

The idea: make the symmetry a property of the architecture, not a lesson from data. A network is equivariant to rotation if rotating the input rotates the output in exactly the same way — the network and the rotation commute. Build that in and you get every orientation for the price of one. There are three ways up this mountain: augment (show rotated copies and hope it learns the symmetry — approximate), canonicalize (rotate every input into one standard pose first, so the model only sees one version), or build it in (design the layers so equivariance holds exactly, by construction).
f( rotate(x) ) = rotate( f(x) ) # equivariance: the network commutes with the symmetry     # learn one orientation, get all of them for free — no extra data

The payoff is data efficiency and guaranteed generalization. The run shows it in the starkest possible way.

3 · Seen on a real run — symmetry as free data

1 · The star — train on a slice, and only symmetry generalizes

We taught a small network to read the orientation of an arrow. Then we handicapped it: it only ever saw arrows pointing in a 90° wedge during training (angles 0–90°). At test time we asked about every orientation. Two versions — an ordinary network, and one with rotation symmetry built in by construction:

plain network
seen angles (0–90°)
0.03° error
unseen angles (90–360°)
121.85° error
built-in-equivariant network
seen angles (0–90°)
0.1° error
unseen angles (90–360°)
0.11° error
Inside the wedge both are near-perfect. Outside it, the plain network utterly collapses — 121.85° average error, essentially guessing — while the built-in-equivariant network is still spot-on at 0.11°. It generalizes to orientations it never saw, because symmetry fills them in for free: once it knows an arrow at 30°, equivariance tells it exactly what one at 210° must look like. That is an inductive bias doing the work of data you never collected.

2 · The honest nuance — with enough data, a plain net fakes it

Does that mean a plain network can never be symmetric? No — and here is the honest catch. We measured equivariance error: rotate the input, and the output should rotate the same amount. Trained on all angles, even the plain network is roughly equivariant (well under a degree), because it simply saw every rotation:

The built-in-equivariant model is exact by construction (near-zero at the rotations it is built around); the plain and augmented models are only approximately equivariant, and only where they had data. So the real prize is not symmetry-when-you-have-everything — it is generalizing from far less, exactly the wedge result above.

4 · Why it matters — the prior you don't pay for

Every symmetry you build in is training data you never have to collect and generalization you get for free — which is why equivariance is decisive exactly where data is scarce or exactness matters. In mainstream 2D vision, huge datasets and heavy augmentation often let a plain network fake the symmetry, so built-in equivariance is a smaller (though real) win. But move to 3D shapes, point clouds, molecules, physical fields — where orientation is genuinely arbitrary and data is precious — and building the symmetry in stops being optional.

5 · The surprise — a robot lives in SE(3)

For a robot, symmetry is not a nice-to-have — it is the native language. A gripper pose, an object's placement, a trajectory: these are rotations and translations in 3D space (mathematicians call the group of them SE(3)). A policy that grasps a mug on the left should grasp the same mug rotated on the right without relearning — that is exactly equivariance, and building it in makes robot policies dramatically more sample-efficient.

Same idea, but now the symmetry is the task. Where 2D vision can often brute-force past symmetry with data, a robot cannot afford to — real trials are too costly — so SE(3)-equivariant grasping, Lie-group action spaces, and equivariant state estimators are a serious thread in robotics. Vision treats symmetry as a helpful prior; a robot treats it as the geometry of its world. The in-the-wild page lays out both sides.
